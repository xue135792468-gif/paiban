# 票据 06: 完整草稿的冲突校验与空白学期边界

Status: needs-triage
**Spec:** ../spec.md
**来源:** 2026-10-31 code-review Spec 残余项

## What

warm start 的「完整草稿」目前只检查：行非空、每个课节有作息时段、每个 assignment 的周课时数备齐。它不检查草稿内部是否有重复时段：如果一份旧草稿把同一班的两节课排在同一时段，或同一老师在同一时段有两节课，它仍会被选为 warm start，求解器从一个带硬冲突的解起步。

另一方面，既没有已发布基线、也没有完整草稿的学期没有 warm start，只能从零搜索；60/300 秒都可能停在少量冲突上。当前 ADR-0033 已写明这个边界，但 spec 的验收标准仍写成无条件。

## Why

用户要求「自动排课必须能直接发布」。有基线/导入草稿的路径已满足；空白学期是唯一不能承诺的场景。需要把边界写清楚，并避免选到带冲突的「完整」草稿。

## Acceptance

- [ ] `isComplete` 增加冲突校验：同一 `(班级, 时段)` 与同一 `(教师, 时段)` 各只能出现一次；有重复则跳过该草稿，继续找下一份。
- [ ] 增加一份带重复时段的草稿测试，证明它不会被选中。
- [ ] 增加空白学期（无基线、无完整草稿）的集成测试，记录从零搜索的实际结果；若仍不能到 0，明确 UI 提示与建议（加长求解时间/先导入草稿）。
- [ ] `spec.md` 把「必须直接发布」的保证边界写清楚：有基线或完整导入草稿的学期必须 0 硬冲突；空白学期为 best effort，并有可见提示。
