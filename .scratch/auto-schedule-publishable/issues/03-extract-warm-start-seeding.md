# 票据 03: 把 warm start 选择从 TimetableProblemBuilder 抽出去

Status: done
Category: enhancement
Priority: P4
**Spec:** ../spec.md
**来源:** 2026-10-31 code-review Standards 判断项（Divergent Change）

## What

`TimetableProblemBuilder` 现在同时负责：建求解问题、解析固定教室、选择 warm start（`timetable_entry` 或最早完整草稿）、校验草稿覆盖度。构造函数已有 8 个依赖。把 warm start 的「来源选择 + 覆盖校验 + 时段灌入」抽成一个独立的 service（例如 `WarmStartSeedService`），builder 只接收「每个 assignment 的时段队列」。

## Why

建题和选初始解是两件会独立变化的事：新增一种初始解来源、改变草稿完整性判断，都不应该再改 builder 的构造签名。当前一次 review 修复就让 builder 多背了两个仓储依赖，后续还会继续膨胀。

## Acceptance

- [x] 新增 `WarmStartSeedService`（scheduling.service），builder 只依赖它和建题所需的仓储。
- [x] warm start 来源优先级仍是：已发布基线 > 最早完整草稿 > 无。
- [x] `TimetableProblemBuilderTest` 拆成两组：builder 建题/固定教室；warm start 选择与覆盖校验。
- [x] 修复草稿遍历的 N+1（一次取草稿列表，按需批量取行或只取候选草稿）。
- [x] 不改变 ADR-0033 的外部行为。

### Agent Brief

**Category:** enhancement
**Summary:** Extract warm-start source selection and completeness validation into a dedicated service, leaving the problem builder to build the solver problem.

**Current behavior:**
`TimetableProblemBuilder` selects the warm-start source (published baseline, then the oldest complete draft), validates draft coverage, loads draft rows one draft at a time, and seeds lesson periods. Its constructor carries eight dependencies because of this.

**Desired behavior:**
A dedicated service owns warm-start selection and seeding. It returns a per-assignment queue of periods; the builder consumes that queue when it constructs lessons. Source priority stays: published baseline first, then the oldest complete draft, then none. Incomplete drafts (missing weekly lessons, unknown periods, or class/teacher period clashes once ticket 06 lands) are skipped. No external behavior changes: the same draft is selected and the same periods are seeded.

**Key interfaces:**
- `SemesterBaselineQuery.publishedLessons()` remains the only route to the published baseline; the new service depends on it, not on timetable repositories.
- The new service returns an assignment key → period queue map. The key is the same `(class, course, teacher)` identity the builder already uses.
- The builder constructor no longer takes draft repositories.

**Acceptance criteria:**
- [x] Warm-start source priority is unchanged and covered by unit tests.
- [x] A draft missing any assignment's weekly lessons is skipped; the next complete draft is considered.
- [x] The builder test suite is split: problem construction/fixed rooms, and warm-start selection/coverage.
- [x] Draft traversal no longer issues one query per candidate draft.
- [x] `scheduling` still imports no timetable repository; `scripts/check-module-boundaries.sh` stays green.

**Out of scope:**
- Changing the warm-start policy or the "complete draft" definition (ticket 06).
- Fixed-room resolution or solver scoring.
- Any UI change.
