# 票据 04: 统一求解得分与草稿校验的口径

Status: done
Category: bug
Priority: P1
**Spec:** ../spec.md
**来源:** 2026-10-31 code-review Standards 新发现

## What

同一份草稿存在两套数字：

- 求解器得分：未排课 10 hard、「班级固定教室」1 hard（`PaibanConstraintProvider`）。
- 草稿校验：`DraftValidator`/`ConstraintChecker` 只数班级/教师/教室等冲突；未排课和固定教室违规走单独的 publish blocker，不进入 `hardConflicts`。
- `SchedulingService.moveLesson` 在手工移动后把 `scoreHard` 覆写成 `-hardConflicts`，于是同一份草稿的「得分」和「校验硬冲突数」不是同一把尺子。

用户看到「得分 -10 hard」但校验说「0 硬冲突」，会以为哪里算错了。

用户已确认教室不作为约束：固定教室只约束求解器，不进入 `ConstraintChecker`。本票不再讨论它是否进入校验，范围收敛为求解得分与校验 `hardConflicts`/publish blocker 的显示口径统一，以及 `moveLesson` 的覆写问题。

## Why

展示口径不一致会掩盖真实违规，也让回归测试无法用一个分数判断草稿质量。

## Acceptance

- [x] 明确一个「草稿硬违规」的统一口径：求解得分、校验 `hardConflicts`、publish blocker 三者可解释地对应。
- [x] 移除或解释 `moveLesson` 里 `scoreHard = -hardConflicts` 的覆写，避免两套刻度。
- [x] 更新草稿页/草稿列表/比较框的文案，明确哪个数字是「发布校验」、哪个是「求解得分」。
- [x] 测试：未排课、班级冲突、缺教室三种情况的显示口径与 blocker 数量一一对应。

### Agent Brief

**Category:** bug
**Summary:** Make the publish check the primary verdict and demote the solver score to a labelled technical reference.

**Current behavior:**
The draft page shows a solver score next to a validation conflict count, and both look like the same kind of number. `SchedulingService.moveLesson` overwrites `scoreHard` with `-hardConflicts` after a manual move, so the stored score changes meaning. A draft can display “-10 hard” while validation says “0 hard conflicts”.

**Desired behavior:**
The publish check is the primary verdict: blockers and hard conflicts come from the current draft validation. The solver score is shown as a secondary technical reference, labelled so a person knows it may be stale after manual edits. A manual move no longer rewrites the solver score; the next validation/refresh shows the current publish status.

**Key interfaces:**
- The draft stats component and the draft list/comparison labels: “发布校验” stays primary, “求解得分（参考，手工调整后可能过期）” replaces the bare score label.
- `SchedulingService.moveLesson`: stop writing `scoreHard = -hardConflicts`; leave the last solver score untouched.
- The draft page already loads validation separately; keep that as the current source of truth for blockers.

**Acceptance criteria:**
- [ ] After a manual move, the stored solver score is unchanged; validation still reports the current hard conflicts and blockers.
- [ ] The draft page labels the score as a reference that may be stale after manual edits, and keeps the publish blockers as the primary verdict.
- [ ] The draft list and comparison dialog use the same “求解得分” wording; the comparison hint says publishing depends on the whole-draft validation, not the score.
- [ ] Existing backend tests that asserted the old overwrite are updated to assert the score is preserved and validation is current.
- [ ] No change to solver constraints, fixed-room handling, or validation rules.

**Out of scope:**
- Adding the fixed-room rule to the validator (user decided rooms are not a constraint).
- Changing solver scoring or the 10-hard unassigned penalty.
- Adding a persisted “score stale” flag or a database migration.
