# 01: 草稿编辑器首屏减负、溢出菜单与运行态优化浮出

**What to build:** 让教务管理员在 1440×900 桌面视口打开草稿编辑器时，首屏不再被大量辅助卡片和说明文字挤占，至少能直接看到 5–6 行课表网格；顶栏合并为单行（「返回排课」+ 草稿名与状态 + 操作说明 `ⓘ`，右侧为「撤销（N）」「更多 ▾」和唯一高亮主按钮「发布课表」/「撤回为草稿」）；「更多 ▾」按序收纳继续优化、比较草稿、重命名、刷新及分割线后的删除草稿；原本的四张统计大卡压成一条单行冲突摘要条，把求解器 `hard/soft` 得分退进「排课详情 ⓘ」，主显「N 处排课冲突」或「无冲突 · 可发布」并保留逐条定位入口；原四行锁定保护说明收进多选旁的 `ⓘ`；当 URL 携带 `?job=` 刷新恢复或正在运行继续优化时，优化进度与结果面板自动浮出在摘要条下方。

**Blocked by:** None (can start immediately)

**Status:** in-progress

- [ ] 1440×900 视口下草稿编辑器首屏可见课节行数达到 5–6 行以上，顶栏与控制条均无意外折行
- [ ] 右上角仅保留唯一高亮主按钮（未发布态为「发布课表」，已发布态为「撤回为草稿」），「撤销（N）」与「更多 ▾」并列其左侧
- [ ] 「更多 ▾」菜单按序包含：继续优化（附继承锁定节数，保留原有优化触发测试锚点；全锁定时置灰并提示原因）→ 比较草稿 → 重命名 → 刷新 → 分割线 → 删除草稿（沿用含锁二次确认）
- [ ] 统计大卡收拢为单行状态摘要条：有冲突显示「N 处排课冲突」与「逐条定位」，0 冲突显示「无冲突 · 可发布」；原始 `hard/soft` 分值仅在「排课详情 ⓘ」气泡内可见
- [ ] 原两行拖拽/撤销说明与四行锁定保护说明分别收进对应 `ⓘ` 触发提示，不再平铺占高
- [ ] 静止态不渲染「继续优化」大卡片；当刚发起继续优化或通过 `?job=` 恢复优化任务时，优化进度与结果面板自动在摘要条下方展开
- [ ] 遵守单文件组件 600 行体积限制（超出则抽离状态摘要或溢出菜单子组件）
- [ ] 补齐草稿编辑器视口收口、溢出菜单与 `?job=` 恢复行为单测，并更新草稿优化与生命周期相关 Playwright E2E 用例至通过
