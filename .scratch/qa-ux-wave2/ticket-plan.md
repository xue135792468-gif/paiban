# 第二波 UX 改造拆票路线（qa-ux-wave2）

对应规格：[spec.md](spec.md)

## 分批节奏与依赖拓扑

共拆分为 **7 张**垂直切片票据（全部 `Status: ready-for-agent`），按 Batch 1（`O2 + O3`）→ Batch 2（`O1 + O4`）→ 收口验收推进：

```
[Batch 1]
  01 草稿编辑器首屏减负与溢出菜单 ──┐
  02 工作台与课表页层级及术语 ──────┼──▶ [04 壳层去重、三段页签与空态] ──┐
  03 统一数据导入与上传校验 ────────┘                                     ├──▶ [07 集成验收与门禁收口]
[Batch 2（可随时并行或随 Batch 2 合入）]                                  │
  05 设置页按卡显式保存与分层 ────────────────────────────────────────────┤
  06 教师弹窗折叠与规则 AI 条件显隐 ──────────────────────────────────────┘
```

## 初始 Frontier 与并行写集边界

- **立即开工（Batch 1 Frontier）**：`01`、`02`、`03` 三票彼此写集隔离（草稿编辑器视图、工作台/课表视图、数据导入视图），可独立按序或开 worktree 并行推进；`05`、`06` 亦无前置阻塞，待 Batch 1 合入或按排期切入 Batch 2 时认领。
- **`04` 为何阻塞于 `01` 与 `03`**：`04` 需要同时修改工作台壳层（含草稿编辑器免顶层页签）与数据管理页签收敛（依赖 `03` 将两个导入页签合为「数据导入」），串行合并可彻底避免路由与壳层冲突。
- **共享工作区规则**：多会话并行时按项目规定使用独立 worktree，避免误提交他票未完成改动；每票完成后先跑定向 Vitest 与相关 Playwright E2E，收口票 `07` 执行全量门禁。
