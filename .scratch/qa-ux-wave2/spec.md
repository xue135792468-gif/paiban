# 第二波 UX 改造：界面层级治理、首屏视口预算与导入主次反转

Date: 2026-11-26
来源：基于 `.scratch/qa-ux-audit/triage-and-wave-plan.md`、`.scratch/qa-ux-audit/qa-ux-report.md`、两轮 Grill（Q1–Q14 全部采纳推荐方案）及已确认的低保真交互原型（`.scratch/qa-ux-audit/wave2-prototype.html`）。

## Problem Statement

首次上手排课系统的教务人员虽然能够走通核心业务链路，但在 1440×900 常规桌面视口下会被界面信息过载、层级混乱与入口错位严重干扰：

1. **多套壳层标题重复与无效工具栏常驻**：数据管理、调代课、课表工作台、设置四个功能域都在外层壳层与子页面各渲染一遍主标题和副标题（设置页一屏甚至出现四次「设置」）；数据管理顶部平铺 9 个等权页签，新手无法分辨建校顺序；没有当前学期时，年级、行政班、授课任务上方仍铺着一整排灰色禁用按钮，且授课任务页的概念公式横条在有数据后依旧常驻占用首屏。
2. **排课主链路首屏视口被辅助信息挤占，且直接暴露工程术语**：草稿编辑器上方叠加了外层工作台页签、两行副标题、6–7 个平铺操作按钮（删除掉行）、4 张统计大白卡、继续优化大卡片以及 4 行锁定长说明，导致 1440×900 下核心课表网格首屏只露出 2 行；课表工作台的「开始排课」主按钮被挤换行，右上挂着跨模块「导入课表」，「排课历史」整卡与草稿表高度重复；课表页「导出」按钮掉行悬空；界面直接向教务人员展示 `-22 hard / 0 soft`、`求解得分`、`表头行`、`复合键` 等内部工程词。
3. **数据导入主次反转与静默防错缺失**：系统把依赖外部 AI 供应商的配置型入口设为默认首页，未配置 AI 时 6 张目标卡中有 4 张不可用（含 3 张「即将支持」占位卡），首屏甚至看不到上传控件；而真正零依赖可用的手动选列与配方导入却藏在次级页签并使用浏览器原生灰色按钮；选入 `.txt` 等不支持格式时页面只静默置灰提交按钮而不给出任何错误原因。
4. **设置保存作用域冲突与低频字段干扰日常填写**：设置页顶部挂着「保存设置」总按钮，页面内部又有各卡独立的保存按钮，用户改完字段不知道该点哪一个——更隐蔽的是钉钉集成卡内的「事件令牌」实际跟随页头总保存提交，点卡片自身的「保存钉钉配置」并不会保存它；学校信息中的部署级「外部访问地址」、教师弹窗中的「电子邮箱 / 钉钉 UserID」、规则页在未启用 AI 时仍常驻的「AI 帮填」以及设置页已冻结的「代课人选推荐 · 即将推出」占位行都在持续分散注意力。

## Solution

以「核心任务为中心」重排首屏视觉权重，通过渐进式披露、渐进增强与通用领域语言翻译治理上述四组体验问题，**全程不改动后端求解算法、数据库 Schema 与权限路由契约**，分 Batch 1（`O2 + O3`）与 Batch 2（`O1 + O4` + 2 项同页小减法）两批落地：

1. **草稿编辑器与排课主链路首屏减负（O2）**：在 1440×900 基线下把草稿页顶部控制壳压缩为「单行顶栏 + 单行冲突摘要条 + 精简控制条」，移除外层工作台页签，将低频操作收进「更多 ▾」溢出菜单（运行中或 `?job=` 刷新恢复的优化任务仍自动浮出主区），将 `hard/soft` 得分退入「排课详情 ⓘ」，主显「N 处排课冲突 / 无冲突 · 可发布」，首屏可见课节从 2 行提升至 ≥5–6 行；同步整理工作台两行发起表单、单行收起无冲突已完成任务卡、折叠排课历史、以及课表页右上角导出布局，并将手动导入里的解析器术语译成大白话。
2. **数据导入主次反转（O3）**：以零 AI 依赖的「手动选列 / 配方导入」作为默认主路径，统一使用拖拽上传与即时后缀格式红字校验；将「AI 智能解析」作为顶部可切换的渐进增强模式，兼容既有会话与目标深链；未配置 AI 时展示干净引导页，已配置时彻底隐藏 3 张「即将支持」卡片。
3. **全站四套壳层去重与空态收敛（O1）**：统一剥离四个域壳层的重复 `H2` 与副标题，将「数据管理」顶部局部导航按建校先后重排为三段语义分组（共 8 项）；无学期空态下隐藏依赖学期的全灰工具栏按钮；仅在空态保留概念提示条；单学期隐藏「复制结构」。
4. **设置保存作用域澄清与低频字段分层（O4）**：删除设置页头歧义的总保存按钮，改为按配置卡片显式独立保存，并确保保存钉钉配置时连带持久化事件令牌；将外部访问地址、教师邮箱与钉钉绑定折叠进按需展开区（编辑已有数据时自动展开），隐藏未启用的规则页「AI 帮填」与冻结的「代课人选推荐」占位行。

## User Stories

1. 作为教务管理员，我想在数据管理、调代课、课表工作台和设置模块只看到一次页面主标题和针对当前页面的业务说明，以便不再被多层重复标题挤占视野。
2. 作为教务管理员，我想在进入草稿编辑器时隐藏顶层的「课表工作台」页签，仅保留「返回排课」出口，以便把宝贵的首屏高度留给课表网格。
3. 作为首次建校的教务管理员，我想在「数据管理」顶部看到按建校先后分好组（基础档案、排课输入、批量导入）的局部导航，以便一眼分辨先建什么、再填什么、最后从哪里批量导入。
4. 作为教务管理员，我想在系统尚未创建任何学期时，在年级、行政班、授课任务页面只看到简洁的「去创建学期」引导卡片，而不被上方一整排灰色禁用按钮误导。
5. 作为教务管理员，我想在已经录入授课任务后不再反复看到「授课任务 = 行政班 + 课程 + 每周节数 + 任课教师」的定义横条，仅在空态引导时看到它，以便表格首屏多展示几行数据。
6. 作为单学期学校的教务管理员，我想在只有 1 个学期时看不到「复制结构」按钮，仅在存在 2 个及以上学期时才看到它，以便操作列更清爽。
7. 作为教务管理员，我想在 1440×900 分辨率下打开草稿编辑器时首屏就能看到至少 5–6 行课节，而不必每次都先向下滚动才能开始调课。
8. 作为教务管理员，我想在草稿编辑器右上角只看到一个最醒目的主按钮（发布课表 / 撤回为草稿）以及「撤销（N）」「更多 ▾」，把继续优化、比较、重命名、刷新和危险的删除收进「更多 ▾」菜单，以便减少误触且顶栏不再折行。
9. 作为教务管理员，我想在草稿全部课节已被锁定时，「更多 ▾」里的「继续优化」呈禁用态并直接写明原因「全部课节已锁定」，以便立即明白为什么不能继续优化。
10. 作为教务管理员，我想在发起「继续优化」后或携带 `?job=` 刷新页面回来时，优化进度与结果面板自动浮出在摘要条下方，以便随时跟踪进展或取消任务，而不用点开「更多 ▾」去翻找。
11. 作为教务管理员，我想在草稿编辑器顶部看到一行紧凑的状态摘要（冲突数/可发布状态、已排/未排节数、已锁定节数与「逐条定位」按钮），而不是占满半屏的四张大统计卡和四行锁定说明文字，以便快速判断能否发布。
12. 作为非技术背景的教务老师，我想在草稿和工作台上直接看到「22 处排课冲突」「无冲突 · 可发布」以及「冲突情况」列，把 `-22 hard / 0 soft` 收进「排课详情 ⓘ」，以便不学求解器术语也能看懂排课结果，同时在需要排障时仍能查到分值。
13. 作为教务管理员，我想继续保留并看懂「跨班换人」「课节锁定」这些核心业务概念，并通过按钮旁简洁的提示气泡一秒理解它们的含义，以便区分草稿换课与发布后调代。
14. 作为教务管理员，我想在课表工作台的「发起排课任务」卡片里看到整齐两行排列的表单和右对齐的唯一主按钮「开始排课」，且不再出现跳往其他模块的「导入课表」按钮，以便流畅发起排课。
15. 作为教务管理员，我想在排课任务无冲突完成后，看到一条干净的单行绿色摘要（带「展开详情」和「打开草稿」），而在运行中、有冲突或失败时保持完整展开，以便平时不占地方、出问题时不漏报错。
16. 作为教务管理员，我想让「排课历史」默认折叠在「课表草稿」列表下方，只在当前还没有任何草稿且最近一次任务失败或被取消时自动展开，以便避免重复列表占屏又不错过失败排查入口。
17. 作为教师或教务管理员，我想在课表查看页把「导出」固定在标题行右上角、去掉副标题里重复的调/代长句，以便 1440px 下筛选控制条保持单行不折行。
18. 作为尚未配置任何 AI 供应商的新学校管理员，我想点击「数据导入」时直接看到零依赖可用的拖拽上传区（支持手动选列和配方自动匹配），而不是先被四段警告和四张灰卡片拦住。
19. 作为教务管理员，我想在手动选列界面看到「标题所在行」「合并在一列（如 班级|星期|节次）」「拆成三列（班级、星期、节次分开）」等大白话选项，以便不用懂什么是「表头行」或「复合键」就能完成列映射。
20. 作为教务管理员，我想在上传 `.txt` 等不支持的文件格式时，立刻在上传区下方看到明确指出允许格式与当前文件名的红色提示，而不是看到按钮静默变灰。
21. 作为已配置 AI 供应商的教务管理员，我想从同一导入页顶部切换到「AI 智能解析」模式（或在携带 `?session=` / `?target=` / `?mode=ai` 链接打开、以及存在未完成 AI 会话时一键恢复），并且只看到当前真正可用的 3 个导入目标（整本工作簿、教师、课表），隐藏 3 张「即将支持」占位卡。
22. 作为正在使用旧书签或配方测试链接的管理员，我想访问原手动导入入口路径时依然能正常打开手动导入流程，以便现有使用习惯与书签不失效。
23. 作为系统管理员，我想在设置页去掉容易混淆的页头「保存设置」总按钮，让学校信息、调代策略、收件人、钉钉集成、AI 特性各自拥有清晰的保存按钮，且保存钉钉配置时能一并保存「事件令牌」，以便所见即所存、绝不漏存字段。
24. 作为教务管理员，我想在学校信息里把「外部访问地址」折叠进「高级设置」、在钉钉未启用时隐藏其凭据框、在 AI 特性里隐藏灰态的「代课人选推荐 · 即将推出」，以便设置页只聚焦当前会用到的配置。
25. 作为教务管理员，我想在新建或编辑教师弹窗里先只填写「姓名、工号、任教学科、联系电话、状态」5 项常用信息，把「电子邮箱」和「钉钉 UserID」折叠进「更多信息」，并在编辑已有邮箱或钉钉绑定的教师时自动展开，以便既减少日常干扰又不误以为原有数据丢失。
26. 作为教务管理员，我想在未配置 AI 供应商或关闭「自然语言生成约束」开关时，在排课规则页工具栏看不到无用的「AI 帮填」按钮，仅当服务端确认可用时才显示它，以便不点到无效入口。

## Implementation Decisions

1. **分批交付边界与无后端改动原则**
   - 第二波完全在前端表示层与页面状态编排内实现，不修改后端求解器、数据库表结构与 REST API 契约（复用现有的设置局部合并更新接口与自然语言约束可用性查询接口）。
   - 实施分为两批独立推进：Batch 1 交付草稿编辑器、工作台、课表页及统一数据导入入口（O2 + O3）；Batch 2 交付四套壳层去重、数据管理三段页签与空态收敛、设置与表单高频/高级分层及同页小减法（O1 + O4）。

2. **四套壳层页头所有权与数据管理局部导航结构**
   - 数据管理、调代课、课表工作台、设置四个域级壳层组件全部移除外层大标题与副标题，仅保留顶部局部导航条；所有具体业务标题、副标题与操作区由子页面自身承担。
   - 课表工作台壳层在命中草稿编辑器路由时隐藏顶层导航条，改由编辑器顶栏的返回动作回退。
   - 数据管理局部导航采用三段语义分组，按「基础档案（学期与作息、年级、行政班、课程、教师）| 排课输入（授课任务）| 批量导入（数据导入、导入配方）」共 8 项呈现；侧边栏一级菜单、权限落地重定向规则以及新手教程引导锚点保持不变。
   - 上下文空态下隐藏依赖前置条件（当前学期）的禁用工具栏，说明性公式横条仅在空态下渲染；单学期不展示「复制结构」操作；作息表时间组筛选继续保持仅在存在时间组时展示。

3. **排课主链路视口预算、溢出菜单与状态驱动显隐**
   - 1440×900 桌面视口作为草稿编辑器与课表页的布局验收基准：草稿页通过单行顶栏、单行状态摘要条与精简控制条确保首屏网格露出至少 5–6 行课节。
   - 每页维持唯一主操作 CTA（工作台为「开始排课」、草稿页为「发布课表」或「撤回为草稿」、课表页为标题行右上「导出」）。草稿低频操作按「继续优化 → 比较草稿 → 重命名 → 刷新 → 分割线 → 删除草稿」收敛进「更多 ▾」菜单，并保留原有 `optimization-continue` 与删除确认语义。
   - 过程面板采取「异常或活跃自动显形、正常完成即收起」策略：
     - 草稿页的继续优化面板平时隐藏在「更多 ▾」中，一旦 URL 存在 `?job=` 或存在运行中/刚结束的优化任务，立即在摘要条下方自动浮出。
     - 工作台的当前任务卡片在无冲突完成态折叠成单行绿色摘要（提供「展开详情」与「打开草稿」），而在运行中、存在硬冲突或失败时保持完整展开。
     - 工作台的排课历史区默认折叠为摘要栏，仅当当前学期尚无草稿且最近一次任务为失败或取消时自动展开。

4. **领域语言统一与工程术语退场映射（源自交互原型定稿）**

| 界面位置 | 原展现形态 | 第二波定稿形态 | 处理策略 |
|---|---|---|---|
| 草稿摘要 / 工作台任务卡 | `硬冲突 N` / `求解得分 -22 hard / 0 soft` | `N 处排课冲突`（0 冲突显示 `无冲突 · 可发布`） | 原始 `hard/soft` 退入「排课详情 ⓘ」浮层 |
| 工作台草稿表列头 | `求解得分` | `冲突情况`（单元格显示 `无冲突` / `N 处冲突`，悬停提示得分） | 主显教务准入语义 |
| 手动选列映射器 | `表头行` | `标题所在行` | 解析器术语白话化 |
| 手动选列映射器 | `复合键（班级\|星期\|节次）` / `复合键列` | `合并在一列（如 班级\|星期\|节次）` / `合并信息列` | 解析器术语白话化 |
| 手动选列映射器 | `班级/星期/节次分列` | `拆成三列（班级、星期、节次分开）` | 选项同步平实化 |
| 草稿控制条 | `跨班换人` / `课节锁定` / `继承锁定` | 保留原词，附简短 tooltip 与 `ⓘ` 解释 | 遵循词汇表正式领域词 |

5. **统一数据导入状态机与渐进增强契约（源自交互原型定稿）**
   - 统一入口默认落入零 AI 依赖的「手动选列 / 配方」模式，使用统一拖拽上传组件并前置拦截非 `.xlsx` / `.xls` / `.csv` 文件，在上传区下方就地展示包含当前文件名的明确错误提示。
   - 顶部提供「手动选列 / 配方」与「AI 智能解析」双模式切换；当 URL 携带 `?session=`、`?target=` 或 `?mode=ai` 时自动切入 AI 模式；存在未放弃的 AI 导入会话时，在页顶展示轻量恢复横条。
   - 切入 AI 模式后：若尚未配置 AI 供应商，仅显示干净的引导卡片（「去 AI 助手配置」与「返回手动导入」）；若已配置，仅渲染已可用的「整本工作簿」「教师」「课表」3 张目标卡片，永久隐藏 3 张尚未实现的「即将支持」卡片。旧的手动导入路径继续保持直达手动模式的向后兼容。

6. **设置保存作用域划分与条件显隐**
   - 设置页取消页头总保存，使每张业务卡片成为独立的显式保存单元，分别调用现有局部更新接口或钉钉配置接口；提交钉钉配置时由前端把同卡片内的「事件令牌」一并写入设置键值，消除跨接口漏存。
   - 低频与未启用字段采用渐进式披露：外部访问地址折叠入学校信息「高级设置」；钉钉凭据与事件令牌在集成开关关闭时折叠；冻结的「代课人选推荐 · 即将推出」占位行隐藏。
   - 教师弹窗把邮箱与钉钉绑定收进「更多信息」，新建时默认折叠，编辑时只要二者任一已有非空值即自动展开。
   - 排课规则工具栏通过可用性探测接口控制「AI 帮填」渲染，仅在 `available === true` 时显示。

7. **单文件组件体积纪律**
   - 所有新增的弹窗、模式面板、汇总条与折叠块必须按职责拆出子组件或组合函数，严格遵守仓库既有的 600 行单文件组件体积限制与超限基线文件「只减不增」规则。

## Testing Decisions

1. **测试设计原则**
   - 测试只校验用户可观察的外部行为、文案呈现、显隐切换、持久化结果与视口可见性，不耦合组件内部变量名、CSS 类细节或私有辅助方法。

2. **测试接缝选择**
   - **主接缝（最高层端到端）：Playwright E2E（真实隔离后端 + 前端实例）**
     - 覆盖关键用户流：草稿优化与溢出菜单交互、`?job=` 刷新恢复、工作台表单提交与历史折叠、课表页导出布局、统一数据导入的手动/配方/AI 会话深链恢复与非法文件拦截、空学期与多学期显隐、设置页按卡独立保存（含钉钉配置与事件令牌持久化）、规则页 AI 开关可用性显隐以及新建/编辑教师弹窗折叠展开。
     - 直接沿用并升级现有对应 E2E 用例套件，不另造独立测试替身。
   - **次接缝（快速回归）：Vitest 组件与页面行为测试**
     - 集中覆盖分支密集的交互状态矩阵（如全锁定禁用「继续优化」、无冲突任务卡单行收起、无草稿且最近失败自动展开排课历史、上传非法后缀即时内联报错、钉钉保存双接口协同、教师弹窗编辑已有数据自动展开等）。
   - **仓库静态门禁**：以仓库既有门禁脚本校验 SFC 行数限制、ESLint、TypeScript 构建、本地日期规范、E2E helper 去重与票据状态一致性。
