# 钉钉免登与多用户管理 规格

来源：2026-11-10 三轮 grill 定稿（17 条，产品所有者全部按推荐确认），加写规格前的 3 条确认（恢复调代审批、老师只自助代课、验收方式），产品所有者 2026-11-10 确认按推荐。

## Problem Statement

现在系统实际上只有一个人在用：教务管理员用 `admin` 账号登录电脑端，排课、发布、调代都由他来做。老师想看课表、想请人代课，要么找教务，要么由教务给他单独建一个密码账号。

- 钉钉免登虽然有入口，但只认「管理员事先建好、并且已绑定教师」的账号。任何一环缺失都会悄悄退回密码登录页，老师不知道原因。
- 账号只能由管理员一个个建；建号、改角色、重置密码都不留记录。
- 管理员只有一种，全权。学校没法把「管排课」和「管账号」分给不同的人。
- 第 15 张票删掉了调代审批：老师自助提交代课，提交即生效，教务只能事后发现问题。
- 通知是按旧的「当事人 + 班主任 + 收件人名单」发的，和学校想要的「少打扰」不一致。

## Solution

把系统变成「全校老师在钉钉里直接用、管理员在电脑上管」的多用户系统。

- 老师第一次在钉钉里打开应用，系统按教师档案自动给他开一个「老师」账号并登录，不用审批，也不用密码。进不去时，页面会写清楚原因和该找谁。
- 老师以自己的课表为主，也能只读查看全校各班、各老师的课表。老师可以申请代课：选好代课人，系统当场检查有没有撞课；提交后由管理员审批，批准后才生效。
- 管理员分两级。**超级管理员**管账号、权限和钉钉配置。**教务管理员**管排课与审批，碰不到账号。保留 `admin` 密码账号作为总钥匙。
- 钉钉只发两类通知：给申请人的审批结果，给接课老师的代课通知。
- 所有账号操作留审计，超级管理员可以在页面上查看。
- 老师离职的处理：在钉钉同步预演里列为「将停用 N 人」，管理员确认后才停用。

## User Stories

### 进入与开号

1. 作为老师，我想在钉钉工作台点开排课应用就直接进入，不用记账号密码。
2. 作为第一次打开应用的老师，我想系统自动给我开好账号，这样不用等教务手动建号。
3. 作为已经通过通讯录同步绑定钉钉的老师，我想系统直接认出我，不再按姓名去找。
4. 作为还没绑定钉钉的老师，如果教师档案里只有一位老师和我的钉钉姓名同名，我想系统当场把我和这份档案配对并开号，这样我第一次打开就能用。
5. 作为和别的老师重名的老师，我想看到一页说明，写明「系统无法确认你是哪位老师，请联系教务处」。这样我知道该找谁，系统也不会把我认成别人。
6. 作为不在教师档案里的钉钉用户（比如行政人员），我想看到「你还没有开通，请联系教务处」，而不是一个让我输密码的页面。
7. 作为账号已被停用的老师，我想看到「账号已停用」，这样我知道这不是系统坏了。
8. 作为老师，我希望自己的账号没有密码，只能在钉钉里登录，这样不会因为密码泄露被冒用。
9. 作为超级管理员，我想用 `admin` 账号和密码随时登录电脑端，这样钉钉出问题时我还能进系统。
10. 作为超级管理员，我想从老师里挑人提升为管理员，被提升的人仍然从钉钉免登进入，不需要另设密码。
11. 作为超级管理员，我想在钉钉同步预演里看到「将停用 N 人」（钉钉里已经不在的老师），确认后才停用，这样不会因为一次同步失误把一批人锁在门外。
12. 作为超级管理员，我想把误停用的账号重新启用，启用后老师又能免登进入。
13. 作为被停用的老师，我想在下一次操作时就立刻被挡住，不用等登录过期。

### 身份与权限

14. 作为超级管理员，我想系统里只有「超级管理员 / 教务管理员 / 老师」三种身份可选，这样分配时不用理解一堆角色。
15. 作为超级管理员，我想管理账号：提升、降级、停用、启用、重置 `admin` 密码。
16. 作为超级管理员，我想独自负责钉钉参数和通讯录同步，这样教务管理员不会误改集成配置。
17. 作为教务管理员，我想做排课、发布、调代、审批等全部教务工作。
18. 作为教务管理员，我希望看不到也打不开账号管理页、钉钉配置和账号审计，这样职责边界是清楚的。
19. 作为老师，我想默认看到自己的课表。
20. 作为老师，我想只读查看全校任一班级、任一老师的课表，方便找人代课、了解别班安排。
21. 作为老师，我希望看不到草稿、排课规则、设置这些管理功能入口。
22. 作为原来被设成「班主任」的账号，我希望升级后自动变成「老师」，原来能看的东西一样都不少。

### 调代课（代课申请与审批）

23. 作为老师，我想为自己某个日期的一节课申请代课，并自己选好代课人。
24. 作为老师，我想在选代课人时就知道对方那节有没有空。系统当场检查空档和撞课，不合格的人不让提交。
25. 作为老师，我想在申请里写明原因。如果我其实想调课（换到别的时间），也可以写在申请里，由管理员在调课工作台处理。
26. 作为老师，我想在「我的调代」里看到申请的状态：待审批、已生效、已驳回、已撤回、已作废。
27. 作为老师，我想在管理员审批之前撤回自己的申请。
28. 作为管理员（超级或教务），我想有一个「待审批」列表，集中处理老师的申请。
29. 作为管理员，我想批准申请。批准时系统要按当前课表重新检查一遍，冲突了就不让批准，并提示原因。
30. 作为管理员，我想驳回申请，并写一句理由给老师看。
31. 作为管理员，我想在审批时把代课人换成别人，换的人同样要通过当场检查，然后再批准。
32. 作为管理员，两个管理员同时审批同一张申请时，我想以先处理的人为准，后来的人看到「已被处理」。
33. 作为管理员，如果一张申请到上课时间还没人处理，我希望它自动作废，不会在课后突然生效。
34. 作为管理员，我想仍然可以在调代工作台直接替老师发起调课或代课，确认后立即生效，不必走审批队列。
35. 作为老师，我希望同一节课在同一天只能有一张待审批申请，避免重复提交。

### 钉钉通知

36. 作为申请人，我想在申请被批准或驳回时收到钉钉工作通知，驳回时能看到理由。
37. 作为接课老师，我想在代课生效时收到钉钉通知，写清楚哪天、第几节、哪个班、什么课。
38. 作为在调课工作台里被挪动课节的老师，我想收到一条只讲「我的课被换到哪里」的钉钉通知。
39. 作为老师，我希望不再收到其他类型的钉钉推送，比如课表发布、抄送给班主任或教务的通知。
40. 作为管理员，我想在通知记录里查到某条通知是不是发成功了。

### 记录（审计）

41. 作为超级管理员，我想每一次账号操作都有记录：手工建号、自动开号、配对、改身份、重置密码、停用、启用、同步停用、批量导入。
42. 作为超级管理员，我想在一个页面上按时间倒序查看这些记录，能按操作类型和账号筛选。
43. 作为超级管理员，我想每条记录写明谁做的、对谁、做了什么、改之前和改之后各是什么。自动开号的「谁」写作「系统（钉钉免登）」。
44. 作为教务管理员，我希望看不到账号审计页。

### 配置与上线

45. 作为超级管理员，我想在「设置」页填写钉钉的 AppKey、AppSecret、AgentId、CorpId，并按「测试连接」立刻知道填得对不对。
46. 作为超级管理员，「测试连接」失败时，我想看到能看懂的原因，比如「AppKey 或 AppSecret 不正确」「网络连不上钉钉」。
47. 作为已经装了一键安装包的学校，我想升级后数据都在，原来的 `admin` 自动变成超级管理员。
48. 作为首次启用钉钉的学校，我想有一份图文说明书，一步步教我在钉钉开放平台建应用、配权限、填参数、做验收。

## Implementation Decisions

### 角色与权限

- 预置三个角色：超级管理员、教务管理员、老师。现有角色编码 `admin` 名称为「教务管理员」，具体用哪个编码给哪个角色，由实现时决定，但必须满足两点：升级后原 `admin` 账号成为超级管理员；不改任何权限判断点（ADR-0006，权限点不变，只改角色和权限的对应关系）。
- 超级管理员拥有全部权限。
- 教务管理员拥有超级管理员的全部权限，但去掉三项：用户与角色管理、集成配置（钉钉参数、通讯录同步）、账号审计查看（新增权限点，见下文）。
- 老师在现有权限（个人课表、本人授课任务、提交调代、本人调代记录）之外，加上「查看全部课表」的只读权限。实现时必须核对：凡是把「查看全部课表」和其他权限组合起来当成管理员判断的地方，老师都不能因此获得管理能力。调代代发要求的组合里含「审批调代」，老师没有，所以那里不受影响。逐处核对是验收项。
- 「班主任」角色不再出现在任何可选列表里。升级迁移把持有该角色的账号改为「老师」，再删除这个角色。按本班查看的两个权限点（本班课表、本班调代记录）保留在权限目录里，但不分配给任何预置角色。按 `head_teacher_id` 查本班调代的接口分支保留，不删，属于后续清理。
- 新增权限点「账号审计查看」，只给超级管理员。
- 账号页上「改身份」只提供三个选项。至少保留一个启用状态的超级管理员：最后一个不能被降级或停用。

### 账号与登录

- 账号分两类：一类是 `admin` 这种有密码的总钥匙账号；另一类是钉钉免登账号，不设密码，绑定教师档案。
- 钉钉免登账号用密码登录一律拒绝，提示「请在钉钉中打开」。账号页不提供「设置密码」。
- 免登流程（取代现在「任一环缺失就返回空」的行为）：
  1. 用 authCode 换到钉钉 userId，并取到钉钉姓名。
  2. 如果某教师档案的钉钉 userId 等于它，就是这位老师。
  3. 如果没有，在「尚未绑定钉钉」的教师档案里按钉钉姓名找。恰好一位时，把钉钉 userId 写入这份档案（配对）。零位或多位时，结果为「未开通」或「无法确认身份」。
  4. 这位老师有启用的账号，就登录。只有停用的账号，结果为「已停用」。没有账号，就自动建一个老师账号再登录。
- 配对和自动开号在同一个事务里完成，各写一条审计。
- 登录接口失败时返回结构化的原因码，至少包括：未开通、无法确认身份、已停用、钉钉未启用、钉钉调用失败。前端按原因码显示说明页，不再静默退回密码页。说明页上有一个「我是管理员，用密码登录」的小入口。
- 现有「停用即时生效」（每次请求查库）和 JWT 有效期保持不变。

### 通讯录同步

- 同步预演增加一类「将停用」：已绑定钉钉、并且有启用账号的老师，但本次扫描里不在钉钉可见范围内。预演仍然严格只读（ADR-0024）。
- 管理员确认时可以逐个排除。确认后停用对应账号，不删除教师档案，不改课表，每个账号写一条「同步停用」审计。
- 扫描不完整（钉钉接口部分失败）时，不给出「将停用」，并提示原因，避免误停用。

### 调代审批（恢复）

- 老师自助路径只申请代课。调课仍然只在管理员的调课工作台发起（产品所有者 2026-11-10 确认收窄定稿第 11 条）。
- 申请状态：已提交（待审批）、已生效、已驳回、已撤回、已作废。老师提交后停在「已提交」，不再当场生效。
- 提交时做和现在一样的当场检查：日期与学期、星期一致、开课截止、代课人空档与撞课、同一授课实例只能有一张待审批。不合格直接拒绝提交。
- 批准：以「已提交」状态为条件更新，先处理的人生效，后到的人收到「该申请已被处理」。批准时在学期锁下按当前课表重新检查并按开课截止检查，通过后沿用现有代课生效路径（包括再次调整时旧生效行退出），并写入状态历史。
- 改人后批准：管理员指定新的代课人，检查通过后按新代课人生效。最终代课人和期望代课人分别记录。
- 驳回：必须填写理由，状态变为「已驳回」。
- 撤回：只有申请人本人能撤回，而且只在「已提交」状态下可以。
- 作废：授课实例开课后仍在「已提交」的申请，自动变为「已作废」。实现时可以选择「查询或审批时惰性判定」或「定时清扫」，但审批接口必须拒绝已过开课时刻的申请。
- 第 15 张票（V55）删掉的审批人、审批时间、审批意见这几列，用新迁移加回来（不改旧迁移）。迁移版本号在实施时核对所有分支已占用的最高版本后续号；目前分支 `feature/rule-groups` 已占 V56–V58，并计划用 V59。
- 管理员工作台的「直接确认生效」保持不变，不进审批队列。

### 通知

- 钉钉发送的通知只保留以下几类：
  - 申请人的审批结果（批准、驳回，驳回附理由）。
  - 接课老师的代课生效通知，审批通过和工作台直接生效都发。
  - 工作台调课时，被挪动老师各自收到的调课通知。这属于「换课」的接课方，按定稿第 14 条保留。
- 停发以下通知：原任课教师的「已生效」抄送、班主任抄送、教务和收件人名单抄送、课表发布通知、方案校验告警。这些通知的模板和设置项保留不删，只是不再触发，设置页隐藏「通知范围」和「调代通知收件人」。
- 发送记录、3 次重试、失败标记，沿用现有通知记录。

### 审计

- 复用现有审计日志表和写入方式，新增动作类型：手工建号、自动开号、钉钉配对、改身份、重置密码、停用、启用、同步停用、批量导入账号。每条记录包含操作者（自动开号写「系统（钉钉免登）」）、目标账号、变更前和变更后。
- 新增审计查看页，只有持「账号审计查看」权限的人能打开，支持按时间倒序、按动作类型和目标账号筛选、分页。

### 配置与上线

- 设置页的钉钉区块（AppKey、AppSecret、AgentId、CorpId、事件令牌）只对持「集成配置」权限的人可见、可改。
- 新增「测试连接」：用当前填写的参数（可以还没保存）换一次 access token，并读取一次部门根节点，返回成功或可读的失败原因。不写库，不发通知。
- 升级迁移需要保证：原 `admin` 账号变为超级管理员，班主任账号变为老师，其余数据不动。一键安装包按现有流程升级，不加任何人工步骤。
- 在帮助中心或 `docs/` 下写一份图文说明书：钉钉开放平台建 H5 微应用、开通通讯录和工作通知权限、配置可见范围、填参数、测试连接、预演同步、请一位老师实机验收。不做启用向导。

### 第 3 条定稿与旧决定的关系

- 推翻 `DingTalkAuthProvider` 注释里写的「账号由管理员创建，绝不自动开号（用户故事 51）」。

- 部分推翻 ADR-0014 的通知范围配置。

## Testing Decisions

- 好的测试只验证外部行为：从 HTTP 接口进去，断言返回、数据库最终状态、审计记录、通知记录。不断言内部方法调用。
- **主要测试边界（一个）**：后端集成测试。用现有假钉钉客户端（`paiban.integration.dingtalk.fake`）从免登接口进入，把下面这条链走一遍：
  - 自动开号（已绑定、唯一同名配对、重名、不在档案、已停用）
  - 老师提交代课（撞课被拒）
  - 撤回
  - 教务管理员改人后批准，另一管理员晚到被拒
  - 驳回
  - 开课后作废
  - 通知只发给申请人和接课老师
  - 每一步都能在审计和状态历史里查到
- **权限矩阵测试**：三种身份 × 关键接口（账号管理、集成配置、审计查看、全校课表只读、审批、草稿编辑），断言允许或 403。
- **迁移测试**：参照 `TrimMigrationDataPreservationTest`，准备带 `admin` 账号和班主任账号的旧库，跑新迁移，断言角色转换正确、其他数据不变。
- **同步停用**：参照 `DingTalkIntegrationTest` 的预演与确认用例，加上「将停用」「排除」「扫描不完整不停用」三个场景。
- **前端**：一条 Playwright 端到端测试（手机视口）：老师免登进入，提交代课；切到教务管理员（电脑视口）在待审批里批准；老师在「我的调代」里看到「已生效」。说明页的原因码展示用组件单测覆盖。
- 真钉钉接入不能自动化：在说明书里写一份人工验收清单，由学校在配好钉钉后手动走一遍。

## Out of Scope

- 电脑端扫码登录
- 班主任身份，以及按本班查看
- 自定义角色界面
- 钉钉启用向导
- 老师自助发起调课（换到别的时间、置换环）
- 审批超时提醒或催办（只做开课自动作废）
- 家长端、学生端
- 多校

## Further Notes

- 依赖顺序：先做角色重整（01），审计（02）和其他票都依赖它；审批恢复（05）是通知收敛（06）的前提；整链验收（08）放在最后。
- 风险点有两个：
  - 老师拿到「查看全部课表」以后，必须逐处核对现有的权限组合判断，防止越权。票 01 的验收要列出核对清单。
  - 停发「课表发布」通知，可能有学校当作提醒在用。定稿只保留两类通知，这里照定稿执行；如果有学校反馈需要，再单独开票。
- 第 17 张票（按教师视角拖动换课）、`feature/rule-groups` 和本特性互不依赖。迁移版本号按上文规则续号即可。
