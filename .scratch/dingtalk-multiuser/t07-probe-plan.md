# 07 测试连接的工程方案（施工前准备）

2026-11-11，基于 396bd8b 检查实际源码。07 尚未施工，本文件只固定实现边界，不能当作测试结果。

## 当前事实与方案

- `IntegrationController.update` 逐键调用 `settings.put`，在后面才校验 syncStrategy；当前没有统一事务，非法策略可导致前面部分配置已保存。07 触及此入口时先校验所有参数，再用现有 `SettingsService.putAll` 原子保存。用公开 HTTP 无效策略回归验证所有旧值保持，不能仅查抛出异常。
- `HttpDingTalkClient.accessToken` 已用 appKey+appSecret 缓存键，凭据改变会自然失效；不存在“永远复用旧凭据 token”的既有缺陷。测试连接不能调用这个全局缓存，必须是临时独立 exchange。
- 当前设置页加载后 appSecret 清空，后端只返回 hasSecret。不能把空白输入当成真实空密钥，也不能为了测试先保存。
- 建议 DTO 明确区分本次输入 secret 与 useSavedSecret：本次有输入优先；仅在显式选择复用、请求 appKey 与已保存 appKey 一致、确有已保存 secret 时复用。改了 AppKey 又留空，应要求输入匹配的新 Secret，不能悄悄拿旧 Secret 去试。UI 说明“留空使用已保存密钥”只在上述条件成立时出现。保存继续沿用原有空白不覆盖语义。
- 测试不要求集成已启用；学校应能在启用/保存前探测。权限仍只给 integration:manage，教务/老师直接调用 403。
- 单独 probe service 接收本次凭据快照，调用 token 接口后读取根部门详情（dept_id=1）。网络在事务外、有连接/读取上限，不写设置、审计、教师、账号或通知。成功只能说明本次凭据可获取 token 并读根部门；不能声称 AgentId/CorpId、免登、全量可见范围、工作通知均已通过。
- 不把 vendor 正文/异常原文直接拼到响应；返回固定中文原因和稳定结果码。未知 token 错误不能一律断言密码错误，未知部门错误不能一律断言权限不足；提示检查凭据/权限并保留不含秘密的安全原因码。真实错误码如需精确分型，必须补官方来源，不能猜数字。
- 测试连接的新 API 与已保存运行客户端分别有离线适配测试；断言未保存表单值进入 HTTP、本次返回 token 用于根部门调用、旧缓存/配置值不改变。假客户端绿不能代替真实 HTTP 请求契约测试。

## 根部门协议来源

阿里巴巴官方开放平台 [获取部门详情](https://developer.alibaba.com/docs/api.htm?apiId=52330) 给出 `https://oapi.dingtalk.com/topapi/v2/department/get`，必填 dept_id、根部门为 1，响应 errcode/errmsg/result（含 dept_id/name/parent_id）。2026-11-11 通过网页搜索读取到官方页面内容与调用示例，未进行真实租户请求。

不要将 [获取部门列表](https://developer.alibaba.com/docs/api.htm?apiId=52326) 的 listsub 当成读取根节点详情；该接口只返回指定父部门的下一级子部门。原同步继续使用它，不顺便重写。
