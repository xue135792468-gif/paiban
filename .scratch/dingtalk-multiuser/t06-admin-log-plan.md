# 06 管理员发送记录入口（准备，尚未施工）

2026-11-12，主控统筹决定。05 尚在评审整改，本文件不代表 06 开工或通过。

## 需求和当前缺口

- `spec.md` 用户故事 40：管理员想在通知记录里查某条是否发送成功。通知行为段要求沿用发送记录、三次重试与失败标记；ADR-0014 后果还要求教务界面可见。
- 当前 AGENTS 明确旧站内通知页已下线、表保留；Controller 调用面盘点没有发送记录查询入口。只把 `notification_log` 写入数据库不能算用户已能查看。
- 因此在原 06 中补最小只读入口，复用现有表和权限。原个人通知中心的收件箱、未读、标记、删除、重发均不属于此入口。

## 最小落点与权限

- 在现有 `SettingsView` 通知区域用一个“通知发送记录”只读卡片替代退役的额外收件人卡，按需展开查询分页结果。保留独立调代策略卡的其它配置，仅隐藏通知范围控件；旧设置值保留。
- 不新增路由或侧边导航；从现有设置页进入。发送记录不依赖当前学期，避免设置排障也被空学期挡住。
- 查询与卡片使用现有 `Permissions.SUBSTITUTION_VIEW`。主控已实读 `IdentityDataInitializer.java:99-123`：超级、教务具备该权限；Teacher 只有 `SUBSTITUTION_VIEW_OWN`，没有全量查看权。两管理员能进设置，老师不能读取记录。
- 不增加权限目录项或迁移，不借用只有超级管理员才有的 `INTEGRATION_MANAGE` 或 `USER_MANAGE`，也不让浏览器为显示收件人去请求 `/users`。

## 只读查询约定

- 候选 `GET /api/notification-delivery-logs`，受上述权限保护；只读、分页、时间/ID 倒序，页大小有上限。复用现有项目分页习惯，不发通知、不更新记录、不附带自动重试。
- DTO 使用明确 allowlist：记录 ID、时间、渠道、模板、收件标识/安全的人类标签、内容、成功标记，以及固定安全的结果说明。只取必要字段，不暴露账号实体、凭据、原始第三方响应/错误正文/异常链。
- 旧行的 `error_message` 也不能原样透出；其内容未经过新安全约束。未知失败显示固定说明。收件人能按现有教师 UID/账号 ID 安全解析时显示姓名，否则诚实显示原有收件标识，不猜身份。
- 钉钉布尔成功在本特性中只证明平台业务码表示受理；UI 宜显示“钉钉已受理”，不声称老师已读或手机实际送达。本地降级记录显示“系统已保存”，不能把零个本地收件人标成成功。
- 不新增公开“发送/测试通知”端点。

## 验收边界

- 真 HTTP：Teacher 403、教务/超级 200；分页排序；读取不写表、不触发外发；种一条带敏感 vendor 错误文本的旧记录，响应及前端均不包含该原文。
- 前端：两管理员可见，老师不可见且不请求接口；按需打开及分页/错误提示，使用真实服务和 Fake 记录补浏览器截图。
- 审批结果/最终接课通知写成的记录应能在此看到；准确收件人、三次尝试、失败与本地降级仍以 `t06-delivery-boundary.md` 的业务集成回归为准。
- 并入 06 票时加一项用户故事 40 的明确验收复选框并链接本决定；这属于已确认规格内的缺口补齐。所有实现仍须在 05 放行后进行。
