# 06 通知交付事务边界（准备，尚未施工）

2026-11-11，统筹实读现有 NotificationService、DingTalkNotificationChannel、SubstitutionEffects；与后续机械调用图配套，未跑06测试。

## 核实的既有风险

现有 substitutionEffective/swapEffective 在事务内同步调用 channel.send，真实钉钉网络调用发生在业务事务内。新审批后若继续直接沿用，会持有学期/申请锁等待网络，也可能先发出通知再回滚本地状态。这是06收口时必须解决的交付边界，不能因假客户端很快而忽略。

## 最小可行方案（不要求通用框架）

- 在业务事务内生成最小不可变通知消息，注册“仅成功提交后发送”的交付；已回滚的申请/批准不发通知、不写成功通知记录。
- 可使用具体 Spring 事务事件监听器，AFTER_COMMIT；执行发送时必须真正脱离业务事务和已提交事务残留资源。若采用监听器，NOT_SUPPORTED 挂在经代理调用的监听入口以暂停外层资源，让读取和日志保存各走短事务。不要简单把同步网络放进 REQUIRES_NEW 整段事务，仍然违反网络在事务外的标准。
- 必须用独立查询验证通知记录确实提交。AFTER_COMMIT 仍能访问旧事务资源，不等于此时 repository 的 REQUIRED 写入一定再提交；这是 Spring 事务监听常见陷阱。
- 无事务的合法通知调用也需有明确行为（如 fallbackExecution），不能悄悄丢消息。不要为此次收敛引入持久队列/定时重试平台；若现有三次仅是即时发送重试，则保留此语义并如实说明，不声称有持久重放。
- 发送前重新检查收件账号可用与有效UID，不能因为04刚停用仍给该账号推送。对同一事件按最终外部收件身份去重；多个本地账号若绑定同一教师/UID，不应收重复钉钉工作通知。
- 审批结果认真实 operatorUserId，代课效果认最终代课人；调课按每位移动老师自己的明细。原任课人/班主任/教务/名单/发布/方案失败告警的触发全部收口，旧模板与设置值保留。
- 保留既有3次发送尝试、失败标记和记录；真实 HTTP 200 不必然意味着钉钉接受消息，施工时核实当前通知接口响应契约并测试业务错误响应，不能只把 toBodilessEntity 成功当送达。

## 公开行为证据

- 成功批准/驳回、直接代课、工作台调课：准确的收件人、模板、内容（驳回理由/日期节次/班课程），无额外类型；多账号/同UID去重。
- 事务回滚后无通知发送/成功日志；成功提交后的日志通过另一个请求/数据库查询可读。不得只断言内部事件或调用次数。
- 持续失败依然有最终失败记录，临时失败可在既有尝试范围恢复；停用账号不发。
- 发布、方案校验失败、旧范围/名单配置均不能触发退役推送。
- 真实钉钉通知仍由学校实机清单验证，离线HTTP stub或Fake不是实际送达证据。

## 05施工期间的统筹补查（仅06准备）

实读CompositeNotificationChannel后确认它是按顺序首个成功即停止：钉钉在前、local在后，**不是两个渠道始终都写一份**。06应保留既有失败降级语义，不能为了通知收敛删掉local记录表/擅称钉钉成功也必有Notification行。业务收件人先按新规则缩小；各渠道同一事件同一模板按实际外部UID去重，审批结果与接课通知是不同业务内容，不跨模板错误合并。停用账号过滤须在交付时重读，不只在业务事务内做一次。

可用具体不可变Message事件保存render后的title/content/link和必要收件账号ID，成功提交后由独立交付bean的NOT_SUPPORTED入口调用既有Composite；不传JPA managed实体或任意可变变量Map。无事务合法调用需有明确fallbackExecution行为。数据库记录用短事务（如本地渠道纯DB写入可整体@Transactional、外发渠道发送后单独保存log）；不得把整个网络发送包进REQUIRES_NEW。

HttpDingTalkClient.sendWorkNotification当前仅retrieve().toBodilessEntity()后返回true；因此06要在本地HTTP stub证明200且业务errcode非0被判失败，而不能只加服务层Fake回归。主源成功形状及task_id含义仍待有界官方调研，不猜错误码，不把异步任务受理当手机实际送达。所有未知失败保持固定安全错误，不能把原始vendor errmsg/响应体/异常链放进日志或审计。

交付故障不得让已经提交的批准/驳回对外伪装成业务失败：AFTER_COMMIT发送端应把预期外发失败落实到失败记录并安全返回，审批HTTP仍反映已提交状态。至少一条公开HTTP用例证明通知持续失败后三次尝试耗尽，申请仍EFFECTIVE且数据库独立查询可见失败记录。异常诊断只固定安全内容；若日志数据库本身不可用，也不能用外发异常链反向污染业务状态或泄漏凭据。保留当前立即重试与local降级，明确进程崩溃重放/持久outbox不在本票范围。

主线程现已找到并实读可读官方asyncsend_v2文档，见t06-notification-primary-research.md。新增重点：现工程actionCard/text/singleTitle/singleURL与官方action_card/markdown/single_title/single_url形状不一致，06按主源请求形状修正并加HTTP stub断言，不能只改返回码却继续Fake假绿。子代理无凭据空网关请求不是成功body的证明，也不推广为所有错误固定200。

## 响应时限与从未登录的接课老师（统筹决定，仍未施工）

- 实读frontend/src/api/http.ts的timeout为30000；HttpDingTalkClient连接5秒/读取15秒，每位收件人最多3次，且可能有多位收件人。因此仅把同步调用移到AFTER_COMMIT，仍可能让已生效的批准在前端超时。06采用**成功提交后进入专用有界内存执行器**，不占求解/import执行器；外发与重试不阻塞审批HTTP，也不把网络包进新事务。持久outbox/进程崩溃重放不在范围。
- 队列满或交付失败不能回落到HTTP线程同步发网络，也不能把已提交审批返回500；保留安全失败记录。事件/队列只携带最小不可变业务快照，不携带JPA实体或SecurityContext。发送时再读账号/教师映射与停用状态，不只在入队时判断。
- 增加可控外部阻塞的公开行为测试：通知适配器尚未返回时，批准HTTP已返回200、效果已提交；释放后独立查询发送记录。异步测试须等待本案交付结束再重置数据库，不能靠固定sleep碰运气。
- 新自动开号模式下，接课老师可能已有可信Teacher UID但从未打开应用，因而没有AppUser。**接课通知以最终Teacher身份为准，不能因为尚无账号而漏发，更不能为发通知偷偷开账号**；有可用UID且从未有账号，可直接发钉钉通知，链接打开后仍按正常免登流程开号。仅有停用账号则不发；有启用账号时按最终UID去重。申请人的审批结果则始终按真实operatorUserId，不借原教师账号代替。
- 收件目标应在内部保留“账号目标/教师目标”的语义，交付时再解析。既有Message/渠道可最小兼容扩展，保留旧构造和local降级；不能为了适配仅账号ID的旧接口创建影子账号或伪造UserId。Teacher无账号时没有本地收件账号，钉钉失败应保留真实失败记录，不能把零个本地收件人误记为成功降级。
- 上述接课无账号、仅停用账号、多账号同UID、根账号无教师绑定等边界以最终数据库/通知记录验证；默认角色不因此改变，Teacher.active不等同AppUser.enabled。ADR-0014追加说明这一身份与交付边界，旧历史段落不改写。

## 整套测试的异步卫生

实读support/DatabaseResetExtension.beforeEach：它会直接TRUNCATE业务表/Teacher/通知记录，但保留app_user与角色，没有等待后台通知。新异步交付后，前案消息若在重置后才落库，会污染后案，不能靠偶然执行很快当作隔离。

06写集应包括这个既有测试基础设施：在重置数据库之前，有界等待专用通知executor队列与活动任务真正空闲，超时明确失败，不能静默truncate。使用公开框架资源状态做清理协调，不mock业务发送结果、不引入产品测试端点，也不把生产换成同步发送来让所有测试看起来绿。涉及通知结果的既有测试仍需在动作之后等待该案可观察日志/外部stub结果；重置屏障仅负责隔离，不代替业务断言。专用阻塞/失败测试在finally释放外部latch并等交付收尾；不可用固定sleep赌时序。

通用notify门面与所有调用者要一起盘点：保留旧模板/设置值但不让退役模板再被漏掉的旧业务入口触发。只隐藏控件不足以证明无推送。相关调用图由t06-caller-inventory.md补证，未读部分明确未知，不把研究当实现。
