# 03 Module / Interface / Seam 实施约束草案

2026-11-11，**04整改增量双轴复核已放行，03开工**。产品所有者已明确回复采用推荐保护：钉钉ID人工修改仅超级管理员、关联管理员账号的首次绑定须超级管理员确认，普通老师自动配对不变。具体分片与接口定稿见 `t03-wire-contract.md`，下文保留实施不变量。

## Module 与 Interface

- 外部身份 Module：沿用现有 `DingTalkClient` 这个真实 Seam，已有 HTTP/Fake 两个 Adapter；authCode交换返回内部可信的 userid/name，而非让前端自报姓名。HTTP协议以 `dingtalk-official-research.md` 核实的H5流程为依据，保留本项目token方式，不顺便引入扫码/OAuth或新供应商SDK。
- 免登编排 Module：现有 `DingTalkAuthProvider` 负责启用检查、外部身份调用、原因码映射和调用本地身份 Module。它不持有跨网络的数据库事务，也不再吞掉失败后静默走密码页。
- 本地身份 Module：一个小 Interface 接受已验证的身份、返回本地账号标识；Implementation 隐藏UID优先查询、唯一姓名配对、锁后重读、既有账号状态判断、自动建号和同事务审计。可用独立Spring bean承载短事务，避免自调用绕过事务代理。测试从HTTP跨同一个Seam进入，不测私有配对函数。
- 账号写保护 Module：优先让现有超管锚点锁成为一个具体共享 Module，Interface说明“必须在事务内，先锁再读取/变更”。现有账号写、自动开号、后续同步停用共享同一顺序；不发明锁策略接口/工厂或通用回调框架。
- 原因说明 Module：前端按稳定原因码显示未开通/重名无法确认/账号停用/钉钉关闭/钉钉调用失败，必要时增加已确认的新原因；管理员密码入口必须明确绕过本次自动免登，避免回到登录页又立刻循环免登。

## 已确认的不变量

1. 网络先完成，之后才进入本地短事务。锁序协调为账号写锚点→教师/账号；禁止持锚点等待外部HTTP。
2. 同一UID同时首次登录只建一个账号；两个UID竞争唯一同名教师时，后到者必须重读并重新判断，不能覆盖先到者UID。仅“先查后插”不够。
3. 现有教师UID没有唯一索引、教师可能有多个历史账号；不能盲加唯一约束破坏旧库。重复UID/姓名应给安全失败，不凭返回顺序随便认人。
4. 姓名歧义判定不能先丢掉一个同名档案再声称唯一。`Teacher.active`是排课资格，不等同于账号enabled；新登录策略不得偷偷拿它替代账号停用。软删除及同名候选口径需依据规格/既有生命周期语义明确记录。
5. 有启用账号就复用（多个时需确定性选择），只有停用账号则拒绝，不自动另开号、改身份或重新启用。配对失败/停用拒绝不留下半写。
6. 新钉钉账号明确DINGTALK登录类型、无密码；旧账号迁移默认保留PASSWORD及原hash。密码登录和重置密码拒绝DINGTALK；提升管理身份不改登录类型；JWT加载也要兼容无密码账号。
7. 自动账号名≤现有64字符且不会碰撞后复用不相关账号；唯一冲突处理必须在有效事务边界，不能在PG已中止的事务中捕获后继续写。
8. 配对与开号各一条同事务审计，targetUserId已真实生成；按02统一入口和allowlist。必要时只扩充UID/登录类型等业务字段，任何authCode/token/密钥/hash都不进入日志、响应或审计。

## 已确认保护与施工前必须复核

- 保护已经用户确认：教务可修改教师基本档案，但不能更改钉钉UID（无变化的普通编辑不能误拒）。权限判断沿用 `integration:manage`，当前预置角色仅超级管理员持有，端点不写角色字符串。
- 管理员账号保护包含已有的启用/停用管理员账号，不能先给停用管理员弱绑定，等日后启用后冒用。首次免登只凭姓名不得绑定这些档案；普通老师仍可唯一姓名自动配对。
- 检查所有UID写入来源（手工、导入、AI导入、同步、事件等），不能让无人值守弱匹配先绑定，再绕过免登保护。最小可信确认可使用超级管理员在教师档案显式绑定UID，不需要新增审批队列；预演确认若允许高权限首次绑定，必须能证明其具体教师/UID为本次明确确认项，不能把旧一键sync等同于逐人确认。
- 自动事件不得把现有非空UID静默改绑；普通教师自动首次配对仍允许，受保护教师只能复用已可信绑定的UID。历史ADR不改写，新ADR记录这次已确认的安全例外。
- Story9“密码总钥匙随时可用”在引入DINGTALK超管后是否需要保留一个启用PASSWORD超管：仅保留任意类型超管可能丢失钉钉故障回退。作为统筹验收重点复核，不用username字面值硬编码身份。
- 改教师UID前要在写字段之前验证权限，并与账号锁序一致；未改变UID的普通档案编辑不得误拒。若需要刷新managed教师，必须在字段变更前做，防止覆盖本次修改。
- 外部异常只能映射成固定安全原因，不把含access_token URL、响应正文或凭证的ex.getMessage返回/写日志；检查现有client token缓存是否随真实保存的凭据变化失效，未核实前不宣称已有缺陷。

## 验收入口

- HTTP+假外部Adapter：已绑定、唯一同名、同名多位、档案不存在、仅停用账号、重复登录、并发首次登录/竞争配对、账号名碰撞、两种登录类型、管理员密码回退及提升后仍免登。
- HTTP Adapter契约：官方H5路径/方法/请求/响应解析/失败脱敏与超时；假端到端不能代替真实Adapter协议检查。
- 公开页面：原因码展示及手动密码入口；实际浏览器覆盖首登/失败说明，不读取组件内部状态。沿用工作区临时目录、严格真实退出码和定向测试规则。

这是有实际行为深度的Module划分，不是要求额外创建同名空壳类；具体类名和最小改动以02复核后的实际源码为准。主体源码、产品定稿与验收证据仍以本目录spec/issues/delivery为准。
