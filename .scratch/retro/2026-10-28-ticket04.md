# Retro：票 04 重复提交单飞（诊断 → 评审 → 部署）

日期：2026-10-28
范围：整本导入重复提交竞态；两轴独立评审；官方门禁；生产部署与冒烟。

## 发生了什么

- 用两个「都读到 PREVIEW」的会话快照稳定复现「多建一份草稿」（期望 2 份、实际 3 份）。
- `COMMITTING` 短事务认领修复；两轴评审无阻塞，补齐 HTTP 200/409 契约、Playwright 瞬时状态用例、恢复页轮询、历史共享状态词表。
- 官方门禁 869/401/91；CI 四 job 全绿（含真实 `PostgresContainerIT`）；部署 `a355dde`；生产冒烟 200/409/只新增 1 份草稿。
- 冒烟第一次失败：CSV 把生产作息 label「上午第1节」原样写入，导入的节次解析只认「第1节 / 1」，整行被判「无法识别节次」并合并成 0 行；改用 `1` 后通过。

## 候选改进（按严重度）

### 1. 票据状态是历史快照，会误导下一个 agent（导航）

证据：`phase1-closeout` 三张票勾选全 `[x]` 却仍是 `ready-for-agent`；`phase4-onboarding` 五张票未勾选但功能已上线；`phase11/14` 写「未实现」而功能已上线；`constraint-entries/spec.md` 仍 `ready-for-agent` 而六票已完成并部署。

建议：在 `AGENTS.md` 或 `docs/agents/issue-tracker.md` 加一条强指针：「票据 Status/复选框可能是历史快照；开工前以 `HANDOFF.md`、`git log` 和线上事实为准。」并做一次性状态回填（done / superseded）。可加 `scripts/check-ticket-status.sh` 拦截「全部勾选却 ready-for-agent」这一类，接入 `verify.sh`。

### 2. 节次别名缺口（自动化检查）

证据：`SlotText.periodNo("上午第1节")` 返回空，生产冒烟第一次得到 0 行；2026-10-22 的 retro 已把「前后端共享星期/节次别名 fixture」列为待做。

建议：`SlotTextTest` 增加 `上午/下午/晚上 + 第 N 节` 与 `第N节 / N` 的用例，并让解析接受这些前缀；部署跑册补一条工作簿冒烟配方（CSV 节次写 `1`，避免踩同一个坑）。

### 3. 本地 surefire 分叉与 Mockito 自附加不稳定（环境 / 自动化检查）

证据：JDK 21 + 360 安全软件注入 agent；首次 `WorkbookCommitRaceTest` 报 Mockito inline mock maker 初始化失败；6 个测试类的 forked run 出现「forked VM terminated without properly saying goodbye」；`-DforkCount=0` + 预载 byte-buddy agent 稳定通过。官方 `verify.sh --full` 本次通过，属间歇问题。

建议：`backend/pom.xml` 的 surefire `argLine` 加 `-Djdk.attach.allowAttachSelf=true`；`AGENTS.md` 本地开发段加一行「分叉/Mockito 异常时用 `-DforkCount=0` 兜底」；或给 `verify.sh` 加 `--no-fork`。

### 4. 竞态测试的 seam 规则未写入标准（编码标准）

证据：Standards 评审质疑 `WorkbookCommitRaceTest` 直调 service，Spec 评审质疑 barrier 可能串行；最终以「服务层用陈旧快照强制交错 + HTTP 不变量测试 + E2E 只测稳定可见状态」解决。

建议：`CODING_STANDARDS.md` 的「测试」加一条判断规则：并发/状态机测试用陈旧快照在服务层强制交错，另配一条 HTTP 级不变量；瞬时状态用 stub 渲染，E2E 不追求真实并发时序。

### 5. 部署跑册只有文本导入冒烟（信息获取）

证据：`docs/runbooks/deploy.md` 的「导入冒烟配方」只覆盖文本导入；票 04 的工作簿冒烟需要 CSV、轮询、两次 commit 和草稿计数 SQL，本次是现场拼出来的。

建议：补「工作簿冒烟配方」：上传 1 行 CSV（节次 `1`）→ 轮询到 PREVIEW → 两次 `POST .../commit`（期望 200/409）→ `select count(*) from timetable_draft where id > <before>` 断言 1；附只读查询现有班级/课程/教师/作息的 psql 片段。

### 6. 全局 `AGENTS.md` 的云服务器段落（全局 steering）

证据：全局文件里的 Lightsail 运维细节很长，与排课仓库无关；「启动门槛：资源与前置」在本次只触发一次，接近 no-op。2026-10-22 的 retro 已列「云服务器章节可移到单独文档」。

建议：移到独立的 `OPS.md`，全局 `AGENTS.md` 只留两行指针；保留「先读 MEMORY + 快照」的硬约束。

### 7. 约束页选择器在满套件下偶发丢选择（自动化检查）

证据：2026-10-28 两次全量 Playwright 都在 `constraints-target-entries.spec.ts:102` 失败，报「未选课程」；单独重跑该规格 5/5 通过。失败点在 `pickOption(second, 'constraint-entry-course', …)` 之后摘要仍为空，像是满套件负载下下拉选择被重渲染吃掉。

已落地（2026-10-28）：`pickOption` 对 `filterable` 下拉改走「输入精确名称 → ArrowDown → Enter」的确定性路径，非 filterable 下拉保留原点击路径；整个约束组 39/39 通过，随后重跑全量闸门。
