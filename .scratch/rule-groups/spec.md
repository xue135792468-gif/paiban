# 排课规则页重做 + 自定义分组 + 沿用往期规则

Status: ready-for-agent
Feature: rule-groups
Date: 2026-11-07
来源：产品所有者与 Hark 的 grill（2026-11-07），逐题确认；未回答题按推荐处理。

## Problem Statement

教务管理员觉得排课规则页"太难用"：

- 自己拼出来的句子自己看不懂（如「王老师 的 课 在 周五第 5、6、7 节 不排」）；拼的时候要先选「要求」，和说话顺序相反。
- 有些东西藏在右上角「按类型配置」里，那里的「其它类型规则」「本页未覆盖的规则」「规则模板」看不懂是干什么的。
- 想给一批老师（如「教导主任」）、一批课（如体育、美术、音乐 =「技能课」）、一段时间（如第 1–4 节 =「上午」）一次性定规则，现在只能一个个选。
- 新学期想直接沿用上学期或上上学期的那套规则。

## Solution

1. **一句话规则**：规则按主谓宾读，例如「王老师 周五下午 不上课」「技能课 不排在 上午」；拼装顺序为 谁 → 什么课 → 什么时候 → 怎么样，边选边长出句子；强度只有「必须 / 尽量」两档。
2. **只有一个规则页**：去掉「按类型配置」第二入口；积木补齐"一句选多天""只管某个班"，不再有积木装不下的规则；两条系统底线置顶、写成大白话、标「系统自带，不能关」。
3. **自定义分组**：老师、课程、时间三类可自定义分组，名字随意。分组只是批量选择：一个成员可在多个组；组成员变化，引用该组的规则自动跟着变。教师/课程/作息列表与规则下拉里显示组名后缀（「王老师 · 教导主任」），列表可按组筛选。「上午/下午」变成两个预建、可编辑的时间组。
4. **沿用往期规则**：新学期「从以前的学期复制规则」，可选任一往期学期；整套替换前提醒；本学期用不上的规则单列、先关闭。
5. 测试阶段：上线时清空现有规则，只保留两条系统底线。

## User Stories

1. 作为教务管理员，我想规则读起来像一句话（谁 + 什么时候 + 怎么样），以便不看说明就能读懂每条规则。
2. 作为教务管理员，我想按「谁 → 什么课 → 什么时候 → 怎么样」的顺序拼规则，以便和说话顺序一致。
3. 作为教务管理员，我想边选边看到句子成形，以便随时知道自己在写什么。
4. 作为教务管理员，我想句子里出现「上午/下午」或分组名，而不是一串节次，以便句子短而清楚。
5. 作为教务管理员，我想规则强度只在「必须」和「尽量」之间选，以便不用理解分量数字。
6. 作为教务管理员，我想一句规则选好几天（如「周一、周三下午」），以便不用拆成几条。
7. 作为教务管理员，我想一句规则只管某一个班，以便处理个别班级的特殊情况。
8. 作为教务管理员，我想所有规则都在同一个页面，以便不用到处找。
9. 作为教务管理员，我想在规则页顶部看到两条系统底线并知道它们不能关，以便理解系统一直在保证什么。
10. 作为教务管理员，我想上线时旧规则被清空，以便从干净的状态按新写法重新录入（测试阶段）。
11. 作为教务管理员，我想建一个老师分组（如「教导主任」）并挑选成员，以便之后一次选中这批老师。
12. 作为教务管理员，我想建一个课程分组（如「技能课」= 体育、美术、音乐），以便一次约束这批课。
13. 作为教务管理员，我想建一个时间分组（如「上午」= 第 1–4 节），以便在规则里直接选「上午」。
14. 作为教务管理员，我想系统预建好「上午」「下午」两个时间组并允许我修改，以便开箱可用又能按本校作息调整。
15. 作为教务管理员，我想一个老师（或课、节次）能同时属于多个组，以便「教导主任」和「语文组」可以重叠。
16. 作为教务管理员，我想给组加人或减人后，引用这个组的规则自动作用到新成员，以便不用逐条改规则。
17. 作为教务管理员，我想在规则页的分组区统一查看和修改所有分组，以便集中管理。
18. 作为教务管理员，我想写规则时直接在下拉里「新建分组」，以便不中断思路。
19. 作为教务管理员，我想在教师、课程、作息列表里看到成员所属组的小后缀，以便一眼知道谁在哪个组。
20. 作为教务管理员，我想在这三张列表里按分组筛选，以便快速找到一组成员。
21. 作为教务管理员，我想在规则下拉里看到组后缀，以便选人时不选错。
22. 作为教务管理员，我想删除被规则引用的分组时，先看到哪些规则在用它，并选择先改规则或一起删除，以便不留下坏规则。
23. 作为教务管理员，我想保存规则时，如果同一个老师/课/节次被两条必须规则互相卡住，系统提醒我是哪两条，以便我自己决定怎么改。
24. 作为教务管理员，我想老师组和课程组换学期后仍然存在，以便只调整人员不用重建。
25. 作为教务管理员，我想时间组跟着每个学期的作息表走，以便节数变化时不出错。
26. 作为教务管理员，我想在新学期从任一往期学期复制整套规则，以便沿用上学期或上上学期的做法。
27. 作为教务管理员，我想复制前被提醒会整套替换当前学期的规则，以便不误删。
28. 作为教务管理员，我想复制时引用了已不存在的老师、节次或时间组的规则被单列、标「本学期用不上」并先关闭，以便我决定改还是删。
29. 作为教务管理员，我想复制过来的规则里的「上午」按新学期自己的「上午」组计算，以便规则随新作息生效。
30. 作为教务管理员，我想分组和新写法的规则对自动排课、草稿校验、调代校验同时生效，以便各处判断一致。

## Implementation Decisions

- **一份约束快照不变**：自动排课、草稿校验、调代校验、只读 CLI 继续共用同一份约束快照；不新建第二套评估器。分组在**构建快照时展开**为单个教师/课程/课节，因此「组成员变化，规则跟着变」无需重写规则。求解器不感知分组。
- **规则存储**：积木规则继续编译为现有约束配置/约束条目（含 groupKey、enabled、hard）。条目参数允许引用分组（教师组、课程组、时间组）以替代单个对象或节次列表；展开发生在快照构建处，是本特性唯一的后端评估改动点。
- **强度**：界面只暴露「必须 / 尽量」。「尽量」使用各类型现有默认分量，界面不显示分量数字。
- **积木补齐**：「什么时候」支持多天多节与时间组；「对谁」支持单个班级（含现有「除了某班」例外）。目标是现有 16 类积木类型的全部参数组合都能用一句话表达，从而「按类型配置」可以退役。
- **句子渲染**：句子由一处纯函数按「主语（谁/什么课）+ 时间 + 谓语（要求）」生成；优先用分组名和「上午/下午」，去掉「的 课 在」之类虚词。表单槽位顺序改为 谁 → 什么课 → 什么时候 → 要求。
- **单页**：移除「按类型配置」入口和路由（旧路由重定向回规则页），以及挂在它上面的旧「规则模板」栏。两条系统底线（教师不冲突、班级不冲突）作为只读、不可关闭的两句置顶显示。
- **清空旧规则**：一次性 Flyway 迁移（从 V56 续号）删除所有学期的非系统约束配置/条目和旧规则模板数据，仅保留两条系统底线。产品所有者已确认处于测试阶段，可以清空。
- **分组数据模型**：新增「分组」及「分组成员」两张表（随后的迁移续号）。分组有类型（教师/课程/时间）和名称；教师组、课程组为全局（教师、课程本来就是全局实体，跨学期保留）；时间组归属学期（成员为该学期作息的课节）。同一类型内组名唯一（时间组在同一学期内唯一）。成员可属于多个组。
- **预建时间组**：每个学期自动拥有可编辑的「上午」「下午」两个时间组，初始成员按现有作息时间折算（取代当前前端按时间折算的上午/下午快捷项）。
- **分组也是可删实体**：删除走现有「删除 + 7 天可撤销」机制；被规则引用时先返回影响清单（哪些规则），用户选择先改规则或连同规则一起删除。
- **冲突提醒**：保存规则时做一次静态检查。至少覆盖：展开分组后，同一教师/课程/课节同时被必须规则要求「不排」和「排在」同一时段。只提示涉及的两条规则和受影响成员，不阻止保存，也不自动选择。
- **复制往期规则**：新增「从某学期复制规则到当前学期」的操作，与现有「学期复制」（作息、年级、班级、授课任务）分开。语义为整套替换，替换前确认。教师和课程按 id 直接对应（全局实体）；时间组按名称对应目标学期的同名组；节次按「星期 + 第几节」对应目标作息。对应不上（教师已停用/删除、节次不存在、无同名时间组）的规则照样复制，但设为停用并标记「本学期用不上」，在规则页单独列出。
- **概念放开**：「不引入新概念」仅为「分组」放开；不做规则模板、课表版本、生效日期。

## Testing Decisions

- 只测外部行为：给定规则（含分组）→ 快照展开后的约束结果；给定界面操作 → 读到的句子与保存结果。不测内部数据结构。
- 主测试接缝（尽量只用这一个）：**约束快照构建**。用后端集成测试验证：分组规则展开正确；改组成员后无需改规则即可生效；草稿校验与调代校验对同一规则给出一致结论。可参考现有约束快照、草稿校验、换课/调代集成测试。
- 前端：句子渲染与编译做纯函数单测（参考现有规则编译器单测）；表单顺序、分组新建、单页、底线置顶各用一条组件测试；端到端每张票补一条 Playwright 主路径（参考现有规则页与换课的 e2e）。
- 迁移：清空迁移与分组建表迁移在 PostgreSQL 容器里跑一遍（沿用现有迁移测试方式）。
- 复制往期规则：集成测试覆盖可对应、教师已删、节次不存在、时间组无同名四种情况。

## Out of Scope

- 规则模板（有名字、与学期无关的规则集）；按日期自动切换规则。
- 班级分组（按年级选即可）。
- 自然语言生成规则（继续冻结）。
- 排课算法、发布模型（仍整校一次）的任何改动。
- 课表格子里显示分组后缀。
- 新增约束类型。

## Further Notes

- 跨票实现约定见 [contracts.md](contracts.md)；票面与它冲突时以契约为准。
- 上线顺序：句子与单页（票 01–03）→ AI 面板搬迁（票 03b）→ 分组（票 04–07）→ 复制往期规则（票 08）。
- 代码事实（2026-11-07 读码）：当前实际是 18 类约束（2 条系统 + 16 类积木），收敛规格写的是 19 类；积木表单当前顺序为 要求 → 对谁 → 哪些课 → 什么时候；「按类型配置」页承载两条系统底线、16 类的填表写法与分量、积木装不下的写法（跨多天、指定班级）和旧规则模板栏。
- 教师、课程为全局实体；约束配置与约束条目按学期存放；现有「学期复制」不复制规则。
- 本特性与收敛规格中「不引入新概念」那条冲突，产品所有者已明确只为分组放开。
