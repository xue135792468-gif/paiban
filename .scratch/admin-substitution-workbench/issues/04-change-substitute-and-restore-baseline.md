# 04: 课前更换代课人与恢复原安排

**What to build:** 允许课前对仍有效的授课实例再次修订：A→B 后可预览改为 C，或预览恢复基线教师 A。新修订经审批前旧安排 B 继续执行；确认后以新版本替代当前有效安排，历史保留完整。净代入/代出统计按最终有效安排计算，解除和接替教师均收到去重通知。

**Blocked by:** 03:管理员指定代课：预览、代发与亲自确认

**Status:** ready-for-agent

- [ ] HTTP 端到端完成 A→B 后再次预览 B→C；待审批期间当前教师仍为 B，批准后当前教师为 C。
- [ ] HTTP 端到端预览并确认恢复 A；当前安排回到基线，历史 A→B 与恢复修订仍可追溯。
- [ ] 修改代课人或恢复基线均展示新的左右对照和变化清单，不能直接改写或删除历史事件。
- [ ] 按当前实际安排计算代入/代出：A→B→C 时 A 被代一次、C 代课一次、B 不计当前代课；恢复 A 后本次代入/代出为零。
- [ ] 当前课表、教师/班级/教室视图及导出一致；旧代课人不再看到该课，新代课人只看到一次。
- [ ] 每次生效修订向调整前后受影响教师并集发送通知，包括解除安排的教师；相同修订重试不重复通知。
- [ ] 同一实例已有活跃待审批修改时阻止并行新单并引导查看原单；不静默取消他人申请。
- [ ] 两管理员基于同一旧版本竞争时最多一个修订生效，另一方得到冲突，上一有效安排保持完整。
- [ ] 截止前可修订；开课时刻等于或晚于截止拒绝，包括恢复基线；旧预览不得跨截止确认。
- [ ] Playwright 覆盖查看当前 B、发起改 C/恢复 A、审批状态和当前有效结果。

## 规格依据

`spec.md`「课前再次调整与截止」「统计、历史与通知」「Testing Decisions」。
