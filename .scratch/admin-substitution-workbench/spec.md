# 管理员调代工作台规格草案

Status: needs-info

版本：2026-10-28。用户已确认首轮业务选择；完整规格、细化边界和测试缝待确认。确认后才发布 ready-for-agent 规格与逐票文件，本次准备工作不启动实现。

背景与代码证据见同目录 `decisions.md`，建议拆票见 `ticket-plan.md`。本规格对九期已有能力做增量扩展。

## Problem Statement

管理员需要统筹全校临时调代，但当前界面只支持教师提交自己的申请，以及管理员处理待审批事项。未绑定教师身份的管理员无法代人操作，也无法围绕某位教师或某个班级的实际安排完成协调。

审批目前主要依赖文字移动清单。管理员无法在同屏核对本次调整前后的课表；已发布课表无法通过拖拽表达目标位置。某次安排批准后，即使尚未开课，也不能继续更换代课教师或调整时间。

此外，当前读取逻辑把某笔调代持续叠加到以后各周，与按具体日期临时调代的目标不一致；多次修订还可能重复计入统计。全站导航与内容共用页面滚动，长菜单、长页面和切换菜单后的定位也影响操作。

## Solution

增加管理员调代工作台：管理员可以查看任意教师或行政班的实际日期课表，选择一节课指定代课教师，或通过选择目标、拖拽来生成同班调课方案。每次操作先展示左右对照及全部变化，再选择提交审批或亲自确认生效。

调代以具体的一次授课为单位。课前可以基于当前安排继续调整，历史保留；已经开始的授课冻结。调代只改变方案列出的日期，不改变以后每周的常规安排。教师、班级、教室、全校视图、导出、通知与统计采用相同的最终有效安排。

全站固定导航和内容各自的滚动边界，切换菜单后内容回到顶部。

## Implementation Decisions

### 1. 范围、权限与入口

- 管理工作台作为调代模块中的管理入口，教师保留自助入口；课表查看页可选中课节并进入同一操作流程。管理员无须关联教师。
- 查看任意教师或全校课表要求全校课表查看权限；代人发起要求提交及审批权限；直接确认还要求审批权限。待审批队列和仅查看页面分别按现有权限开放，路由与导航不能只检查教师提交权限。
- 后端以权限常量授权；仅有查看全部调代记录的权限不赋予代发或批准能力。普通教师和班主任的现有数据范围不扩大。
- 独立记录真实操作账号、代发对象、基线原任课教师、调整前实际教师、调整后实际教师和审批人，不能用管理员绑定的教师身份代替操作者。
- 管理员的“提交审批”明确进入待审批，即使学校教师自助模式是直接生效也如此；管理员的“确认生效”代表本人显式批准。两种管理动作不依赖全局教师自助模式切换。
- 原有教师调课仍须教务批准；管理员直接确认是教务本人批准，不构成自动批准。

### 2. 授课实例、日期读取与历史兼容

- 授课实例以学期、基线课表条目和原始授课日期建立稳定身份；当前实际日期、课节、教师和教室为可修订的安排。移动后身份不变，同一基线条目下一周的一次授课是另一个实例。
- 保存实际来源和目标日期；不能仅保存星期，也不能仅按基线条目选最后一笔事件。一个窗口内同一周期课节的多个日期必须能同时出现并保持独立身份。
- 最新课表按所选实际日期所在的周展示，列头标日期；每列解析该日的授课实例。跨周预览允许切换受影响周，普通日期选择与导出采用同样的周边界。原始视图仍是该周对应的只读基线投影。
- 所有生效修订先投影到完整日程，再按最终教师、班级、教室过滤，禁止被解除代课的教师仍保留这节课。
- 班级、教师、教室、全校、求解快照、独立校验、导出和只读 CLI 使用一致的日期与实例语义。不能只修页面而让审批或导出继续长期覆盖。
- 已发布基线不修改。旧生效行和历史日志保留，新增实例及修订关系可采用增量结构；具体数据库命名、索引与迁移版本在实施时确定。
- **历史解释变更是显式迁移范围**：新旧调代统一按具体授课日期解释。迁移前生成旧视图/新视图差异清单，明确哪些后续周会恢复原常规安排；不能声称从字段推断出了学校原来是否想长期调整。
- 历史代课从原申请还原日期；调课从原方案移动恢复来源和目标日期。遇到缺失来源、无对应移动、版本冲突或无法唯一解释的记录时，列明阻塞记录并停止转换，保留旧数据。历史影响清单须在部署前由教务确认；该确认是数据切换门，不授权本轮修改线上数据。
- 本功能不提供永久改变每周安排的入口。迁移中识别出确属长期安排的记录时，单独处理其业务归属，不能静默转成一次性事件。
- 实施按扩展兼容、转换历史、正式切换的顺序推进，允许新旧格式在中间提交并存。新管理流程只写已明确日期语义的实例，旧格式未转换的相关实例保持只读并提示转换状态；完整交付前必须通过历史转换与兼容验收，不把中间状态视为最终功能。

### 3. 代课与调课

- 代课保持课程、行政班、当前实际日期、课节和教室，只改教师；选择对象为启用教师。排除当前教师；教师恢复基线时可走“恢复原安排”动作。
- 同科优先、跨科显示提示并允许管理员选择；“同科”不是新增硬约束。教师、班级、教室冲突及启用的约束仍由后端判断，管理员不能强行绕过。
- 调课固定一个授课实例的目标实际日期及课节，在同班当前已有课的槽位内生成闭合置换环。保留每个实例的课程、当前教师和教室、班级每天节数以及方案整体课程集合。
- 空格、跨班、跨学期、超出窗口和已经开始的槽位不是有效目标。某方案在选定目标下无解时说明原因，不改写目标或悄悄替换方案。
- 保留确定性搜索、最多三个候选、已有三个排序预设和窗口配置。默认窗口 7 个自然日，配置范围 1–30；目标与参与日期均在当前来源日期起的窗口及学期范围内。最小影响预设优先同日，其余预设按现有语义比较。
- 目标 API 必须接受明确日期并回传实际日期；不能只按目标星期推算一个最接近的日期。本期保留窗口从来源日期向后展开的方向，不增加向前搜索。
- 表单选择与拖拽进入同一预览、选择方案和确认路径。拖拽只表达意图，不直接写入已发布课表；教师视角发起时，目标网格明确锁定源课所在行政班，不能混淆教师空闲格与本班目标格。
- 鼠标拖拽面向桌面；日期与课节选择提供等价操作。小屏仍能逐一查看对照面板与清单，保持明确的调整前后标签。

### 4. 对照、清单与预览生命周期

- 左侧为同一快照上的本次调整前最新安排，右侧为应用当前所选方案后的安排。两侧对象、视角、日期范围联动；默认显示源课行政班，可切换受影响教师，返回后保持方案。
- 受影响教师、行政班与日期清单必须完整，包括原教师离开、代课教师接替和参与置换的所有教师。跨周移动能够从清单定位对应日期；不只显示当前屏幕的一部分变化。
- 来源格、目标格和仅教师变化的格子有高亮及文字说明。变化清单逐项列课程、班级、调整前后实际日期/节次、教师及教室；统计、面板和清单来自同一方案投影。
- 另设只读基线参考，保持“学期初原始”与“本次调整前”的名称区分；基线不是提交前差异的计算起点。
- 取消预览、切换方案、无解或校验失败时，原生效安排不变，不产生申请、生效事件或通知。预览可保存短期凭证，不当作待审批申请。
- 预览凭证绑定操作者、来源实例及当前修订、目标、整份快照、选定方案、相关规则/设置、过期时间；服务端返回权威截止时间。生存期沿用最多 30 分钟，且不得晚于开课截止。
- 再次预览以当前有效安排重新计算。快照或当前修订变化、选定方案过期时返回明确冲突并保留用户意图用于重新预览，不能自动确认新的方案。

### 5. 提交审批、亲自批准与并发

- 提交审批保存申请和所选意图/方案、操作者及当前修订关系，但不改变最新课表，也不发出“已生效”通知；进入现有待审批工作流。
- 审批人可以批准同一有效预览中的方案。若改变代课人或调课方案，必须先看到对应的新对照，再确认。待审批期间旧生效安排继续执行。
- 管理员亲自确认通过与普通批准相同的校验、审计和写入事务；不能先调用一个会自动生效的创建动作，再补审批或修复历史。
- 同一业务动作内完成申请/修订认领、当前版本判断、当前权限与开课截止复核、最新快照/规则校验、生效投影更新、方案/申请状态、审计和通知事件。保留学期级串行写入边界，失败整单零生效写入。
- 求解器剪枝与独立校验器继续分离。普通硬规则按 ADR-0025 的差分语义拒绝新引入违反；教师/班级/教室同刻唯一、每天节数等核心不变量仍绝对检查。软提示可显示，硬错误不得确认。
- 同一确认凭证或幂等键的相同重试返回第一次操作结果；参数改变不复用已消费凭证。两位管理员从相同旧版本同时修改时最多一份新修订生效，其余返回冲突。
- 同一授课实例同一时间最多有一笔活跃待审批修改；当前管理员不能靠连续新建绕过去重。已有待审批申请时展示并引导处理该单；旧单未结束时不创建并行修改，也不静默取消他人的单。
- 通知事件按修订去重，外部 IM 网络调用不放在业务事务里；沿用现有发送及降级方式，不扩大为新的通用消息基础设施项目。

### 6. 课前再次调整与截止

- 本期学校时区固定为 Asia/Shanghai。使用服务端权威时钟，把实际日期与当前作息开始时间组合成开课时刻；浏览器时区、页面停留时间与服务器默认时区不作为依据。
- 对本次将改变的每个实例，取当前安排和拟生效安排的开课时刻；本单截止为这些时刻的最小值。仅当当前时间严格小于截止值时可确认。等于或晚于截止时刻均拒绝。
- 此规则用于创建/提交、批准、直接生效、恢复基线与再次调整；预览即使尚未过 30 分钟，也不能跨过开课截止生效。等待行锁后必须重新读取时间，避免排队跨点。
- 移动后再次调整以当前安排判断，不因追溯用的原始基线日期已经过去而单独锁死；同时不能把当前未来授课移到过去，或移动已开始的授课。
- 时区、日期或课节开始时间不能确定时拒绝写入并说明缺失项；缺作息不使用默认时间猜测。
- A→B 后改为 C 是同一实例的新修订；B→C 的申请批准前仍由 B 承担，批准后才由 C 接替。历史保留 A、B、C、各次原因、操作者及确认时间。
- 原先调课后的实例仍可再调课或代课，代课后也可在保留当前教师的前提下调课；恢复基线作为需预览、校验的新修订，不删除事件。
- 原置换环已有某节开始时，该实例冻结；其余实例仅在新方案不改动任何已开始实例、且仍满足全部不变量时可调整。不能按旧方案整单反向重放，也不允许为“部分撤销”留下空堂或冲突。
- 尚未生效的再次调整若被驳回、过期或校验失败，上一版安排保持生效；批准时只替代本次涉及实例的当前安排，不取消其他无关实例的历史或有效安排。

### 7. 统计、历史与通知

- 历史展示所有申请与修订，区分待审批、当前有效、已被后续安排替代、驳回等；普通课表采用唯一的当前有效安排。
- 代入/代出按当前有效授课实例与基线教师比较，不按累计事件行数计数。A→B→C 后，A 本次被代 1、C 代课 1、B 本次代课 0；改回 A 后本次代入/代出均为 0，历史仍存在。
- 调课与代课口径分离；同一实例多次移动不因修订数增加课量。调课参与次数按操作组与教师去重，已完全被替代或恢复基线的移动不作为当前有效参与；只剩部分有效移动的组按仍有效的参与教师计算。操作历史另行保留，不伪装为已实际授课次数。
- 页面分别展示基线每周常规节数与当前学期按实际授课日期计算的净课量，避免把“每周基线”加“学期事件次数”得出一个无时间单位的总数。净课量注明包含尚未上课但已确认的安排，不宣称考勤或实际完成课量。
- 通知范围覆盖调整前后受影响教师的并集，包括被解除安排的教师；班主任、教务、年级负责人沿用现有通知设置。再次调整通知明确指出前后变化及其取代的版本。
- 旧通知和审计保留；点击历史通知时显示其历史状态并可查看最新安排，避免把旧安排当成当前安排。重复确认不重复生成生效通知。
- 受影响教师可查看本人相关实例的变化经过；班主任只看本班；不因多教师方案把其他班级的完整课表泄漏给普通教师。
- 导出当前课表和当前有效统计遵循相同日期/修订口径；导出历史记录时明确包含被替代版本，不把历史行当成当前安排。

### 8. 全站滚动布局

- 应用外壳约束到视口；左侧导航区域独立滚动，右侧内容区域独立滚动。顶部栏和导航标识保持可见，菜单项较多时均可到达。
- 左导航切换到不同菜单页，右内容滚动到顶部，左导航保留滚动位置。前后页面内容高度不同不应造成整个窗口共同滚动。
- 同一菜单内修改筛选、切换页签或更换日期不因查询参数变化而无条件回顶。帮助页锚点等已有页内定位继续可达，弹窗内部滚动不与主内容混淆。
- 全站布局修复是独立可验收切片，不依赖调代数据结构。

## Testing Decisions

### 主要验收缝（待用户确认）

1. **既有 HTTP 集成缝**为业务验收主入口：在测试数据库内建立教师、行政班、作息与已发布基线，经过预览/申请/批准/再次调整的真实 HTTP 流程，断言课表、数据库有效版本、审计、通知、统计与导出。复用现有调代与跨日调课的集成测试和发布 fixture，不以内部方法调用代替用户行为。
2. **既有 Playwright 缝**验证管理员完整操作与全站滚动：使用现有登录、种子数据及公共交互 helper，覆盖选教师、指定代课、左右对比、变化清单、拖拽、待审批和再次调整。关键页面与滚动位置保留截图/可观察断言。

只在现有纯求解器、独立校验器缝补必要的实例身份、同周期槽多个日期、显式目标日期和再次调整边界；不另起测试专用业务端点。测试外部结果，不固定私有方法、算法搜索步骤或组件内部状态。

### 必须覆盖的场景

- 未绑定教师的管理员可代人操作；教师不能代其他教师发起；只有查看权限者不能写；班主任/教师看不到超范围完整课表。
- 代课提交审批不生效；管理员亲自确认后只改变指定实例；同科优先与跨科提示不替代硬校验。
- 周五代课不影响下一周同一基线课节；跨日移出、移入各显示一次；后续周恢复常规安排；同一周槽两个不同周的实例可同时出现在窗口内。
- 调代后的班级、教师、教室、全校、导出和求解快照一致；解除 B 后 B 不再有这节课，C 恰有一节，A 不重复承担。
- 二人环、多人环、跨日和跨周方案，固定目标实际日期；同星期下一周不被误判为原槽；空格/跨班/窗口外拒绝。
- 左右面板及变化清单对同一方案完全一致；切方案、切教师、切周不漏掉环内其他变化；基线参考不改变差异起点。
- 预览取消/失败零申请、零生效、零通知；待审批修改期间旧安排继续执行；批准、驳回及过期的可见结果正确。
- A→B→C、恢复 A、已移动课继续移动、代课后调课及调课后代课；历史完整、统计不计中间安排、解除和新接替教师均有通知。
- 固定服务端时钟在截止前一瞬、恰好开课、开课后；覆盖当天尚未开课、目标早于当前安排、多日整单最早时刻、等待锁跨点，以及原始基线日已过去但当前实际课未开始的情况。
- 旧环部分已开始：冻结已开始实例；剩余合法新方案可生效，必须动到已开始实例的方案拒绝；失败不回滚旧安排。
- 两个管理员使用同一旧版本强制交错竞争；同凭证重试；不同确认争用同一实例；快照、约束或作息变化后旧预览失效；断言整单版本、有效行、状态及通知数量。
- 既有规则违反但本次未新增时沿用差分语义；本次新增硬违反与核心不变量失败均拒绝。
- 历史转换的明确可恢复样例、缺失方案移动、歧义和冲突样例；真实 PostgreSQL 验证迁移及版本唯一性，失败保留原数据。
- 长导航与长内容互不带动；切不同菜单右侧回顶且左侧位置不变；页内筛选不无故回顶；帮助锚点仍可到达。

时序边界用固定时钟和服务层可控交错配合 HTTP 不变量验证，不用真实时间等待或脆弱的浏览器并发计时。UI 测试按容器定位稳定可观察结果，不依赖重复姓名的全页文本和 toast。

每票跑有意义的定向测试；集成完成后统一跑仓库全量门禁。发布验证包括真实 PostgreSQL 要求；本次文档准备不执行测试、构建、外部模型或生产业务操作。

## Out of Scope

- 修改已发布基线、永久更换每周常规教师或课节、重新发布一个学期。
- 跨班联合置换、空格只挪不补、改变课程或行政班、独立更换教室。
- 向来源日期之前搜索、跨学期、超出配置窗口、批量多天请假或整周重排。
- 修改已开始/结束的授课，补录或纠正过去实际授课事实。
- 教师端新增管理员式拖拽权限、多人会签、学生家长通知。
- AI 参与可行性判断、搜索或自动批准；已有手动推荐可继续作为可选能力，本功能不依赖 AI。
- 实际考勤、代课费计算、自动结算、多学校时区配置、新消息平台或通用消息队列重构。
- 本轮直接实现代码、调用真实业务 API、迁移生产数据、提交部署或发布新版本。
