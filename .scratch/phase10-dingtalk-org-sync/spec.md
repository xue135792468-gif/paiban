# 排课系统十期规格：钉钉通讯录递归同步与预演确认

Status: ready-for-agent

票据：`issues/01-recursive-org-sync.md`、`issues/02-sync-preview-and-merge.md`

---

## Problem Statement

钉钉通讯录同步目前只导入了根部门直属的 2 位教师，学校里其余 300 多位教职工全部漏掉。

根因已经定位并有证据：`HttpDingTalkClient` 把 `dept_id` 写死为 `1`，而 `topapi/v2/user/list` 不递归子部门。云端实测：

- 根部门直属：2 人（与同步结果完全吻合）；
- 整个通讯录：50 个部门、368 个去重用户；
- 「全校教职工」子树：35 个部门、161 人；
- 其它分支：学区 18、保安 5、食堂 31、离退休 16、校外 8、团委学生 36、离职 19、后勤 10、家属 15、研发 6、平板 23、教研组长 23。

另外三个坑：

1. 钉钉应用开了 IP 白名单，只放行服务器 IPv4。JVM 走 IPv6 会被拒（`errcode=88 / subcode=60020`），当前默认 IPv4 所以没暴露。
2. `家校通讯录`（dept `-7`）用 `user/list` 取不到（`errcode=41`），而且不该进 `teacher` 表。
3. 递归一开，库里 47 位 Excel 导入的教师会被重复创建：他们既无工号也无手机，现有匹配键（`dingtalk_user_id` → 工号）都命中不了。

## Solution

1. **递归拉取**：从根部门开始递归 `department/listsub`，跳过负 id 部门（含 `-7` 家校通讯录），逐部门分页拉用户并按 `userid` 去重。
2. **范围由钉钉权限决定**：程序不设部门白名单、不加 `sync-dept-id` 配置；能读到谁就导入谁，范围由学校在钉钉侧的通讯录权限与应用可见范围控制。
3. **离职处理**：部门名含「离职」或钉钉返回 `active=false` 的用户，导入为 `active=false`，不进入排课候选。
4. **预演确认**：正式落库前先返回「新增 / 补齐 / 疑似同名 / 跳过」四类结果，按部门分组，让管理员勾选排除；确认后才写库。疑似同名不自动合并，必须由管理员确认。
5. **补齐缺失信息**：命中的教师只补空字段（手机、工号等），已有非空字段不覆盖；冲突字段在预演里标出。
6. **可观测性**：成功路径输出「扫描部门 N / 用户 M / 耗时 X ms」；同步结果文案带扫描量，错误带 `sub_code`。

## User Stories

1. 作为教务管理员，我想点一次「同步通讯录」就把钉钉里我能看到的全部教职工导入，而不是只导入根部门的 2 个人。
2. 作为教务管理员，我想在真正写库前看到预演结果：新增多少人、补齐多少人、疑似同名多少人、跳过多少人，避免一键把食堂、家属、团委学生全写进教师表。
3. 作为教务管理员，我想按部门分组勾选要导入的人，像「食堂 31 人」「家属 15 人」这种可以一次划掉。
4. 作为教务管理员，我想让系统提示「王老师」与库里已有的「王老师」可能是同一人，并显示匹配依据（工号/手机/姓名+部门），由我确认是否合并。
5. 作为教务管理员，我想让合并时自动补齐库里缺失的手机和工号，但不覆盖我手工维护的非空字段。
6. 作为教务管理员，我想让离职人员导入为停用状态，不出现在排课候选里，但保留历史记录。
7. 作为教务管理员，我想在同步完成后看到「扫描 35 个部门 / 161 人」这样的数字，方便和钉钉后台核对。
8. 作为教务管理员，我想在同步失败时看到钉钉的 `sub_code`，而不是一句「同步失败」。
9. 作为系统管理员，我想让同步范围完全由钉钉权限控制：学校在钉钉侧收紧可见范围，程序下次同步就只导入范围内的人，不需要改配置。
10. 作为系统管理员，我想让「家校通讯录」和任何负 id 部门被自动跳过，不会报错也不会写库。
11. 作为系统管理员，我想让同一用户出现在多个部门时只导入一次。
12. 作为运维，我想在成功日志里看到扫描部门数、用户数和耗时，而不是成功时什么都不打。
13. 作为运维，我想在 IPv6 出口被钉钉拒绝时看到明确提示（IP 白名单），而不是一个笼统的 500。
14. 作为开发者，我想用假客户端构造多级部门树、重复用户、负 id 部门和离职用户，覆盖递归、去重、跳过、停用四条规则。
15. 作为开发者，我想让预演和正式落库共用同一套匹配逻辑，避免「预演说新增、落库却更新」。
16. 作为开发者，我想让预演接口严格只读，不产生任何 `teacher`、`audit_log` 之外的写入。
17. 作为开发者，我想让匹配顺序固定为 `dingtalk_user_id` → 工号 → 手机 → 姓名+部门建议，绝不按姓名自动合并。
18. 作为开发者，我想让同步结果结构化返回（扫描量、新增、更新、补齐、疑似同名、跳过），前端不用解析文案。
19. 作为教务管理员，我想在确认页看到每个待合并教师的「将补齐哪些字段、哪些字段冲突」，再决定是否合并。
20. 作为开发者，我想让本轮同步不自动停用「这次没看到」的教师，避免权限临时收紧导致大批教师被停用。

## Implementation Decisions

### 拉取与范围

- 递归遍历部门树：从根部门开始，用 `department/listsub` 取子部门，深度优先；部门 id 为负数的直接跳过（`-7` 家校通讯录、其它负 id）。
- 每个部门用 `user/list` 分页拉取，`cursor` 翻页到底；跨部门按 `userid` 去重。
- 不引入部门白名单或 `sync-dept-id` 设置项；能读到谁就导入谁。
- 用户字段沿用现有映射；`email` 在 `user/list` 中不返回，删除这条无效映射，字段自定义记入 backlog。
- 离职判定：部门名包含「离职」或用户 `active=false`，落库 `active=false`。
- 本轮同步不自动停用「未出现在结果里」的教师，避免权限收紧造成误停用。

### 预演与合并

- 同步接口支持预演模式：只读，返回四类结果：
  - 新增：钉钉有、库里没有；
  - 补齐：按匹配键命中，且有可补的空字段；
  - 疑似同名：姓名相同但匹配键不足，需要人工确认；
  - 跳过：负 id 部门、已排除、无有效字段等。
- 预演结果按部门分组，前端可勾选排除整个部门或单个用户。
- 确认接口接收选中的用户/部门，执行写入；预演与落库共用同一套匹配与补齐逻辑。
- 匹配顺序：`dingtalk_user_id` → 工号 → 手机 → 姓名 + 部门（仅作为疑似同名的提示，不自动合并）。
- 补齐规则：只填空字段；非空字段冲突时在预演中标记，不覆盖。
- 写入后返回结构化结果并记 `audit_log`。

### 可观测性与错误

- 成功路径输出 INFO：扫描部门数、用户数、耗时。
- `OrgSyncResult` 文案包含扫描量，不再只写「更新 2 人」。
- 钉钉错误透传 `errcode` / `sub_code`；IP 白名单错误给出明确提示（检查服务器出口 IPv4）。
- `user/list` 对负 id 部门的 `errcode=41` 不再作为整体失败。

### 前端

- 设置中心的钉钉集成页增加「同步通讯录」按钮与预演结果表。
- 预演表按部门分组，显示新增/补齐/疑似同名/跳过数量与明细，可勾选排除。
- 确认按钮显示将写入的总人数；完成后显示扫描量与四类统计。

### 数据库

- 预计不需要迁移；所需字段已在 `teacher` 表存在。
- 若实现时确需新增列，占用下一个可用迁移号，并与九期协调（九期预计使用 V21，若冲突则顺延）。

## Testing Decisions

- 测试缝：钉钉客户端接口（假客户端）+ 同步服务（纯逻辑）+ HTTP 集成。
- 假客户端要能构造：三级部门树、同一用户出现在两个部门、负 id 部门、离职部门、分页边界、`errcode=41`。
- 单元测试覆盖：递归遍历、去重、跳过负 id、离职停用、匹配顺序、只补空字段、预演只读。
- 集成测试覆盖：预演不写库；确认后新增/补齐/疑似同名按预期落库；47 位存量教师不被重复创建；审计记录。
- 云端实测：在 Lightsail 服务器上跑真实同步，核对扫描部门数/用户数与钉钉后台可见范围一致；确认 47 位存量教师没有变成 94 位。
- 先例：现有钉钉集成测试的假客户端写法；`ApiIntegrationTest` + `TestData` 的集成测试写法。

## Out of Scope

- 字段自定义（显示/隐藏、字段映射到本地列）；记入 backlog。
- 邮箱同步：`user/list` 不返回 `email`，本版删除无效映射；若后续需要，改调成员详情接口并确认企业维护了邮箱。
- 查询钉钉「应用可见范围」的接口（`qyapi_get_microapp_list`），本版不依赖它做人数断言。
- 自动停用本轮未出现的教师。
- 学生、家长、家校通讯录的导入。
- 组织架构的双向同步（本系统只读钉钉）。
- 部门层级写入本地（本地仍只维护教师，不建部门树）。
