# 02: 同步预演与确认合并

**What to build:** 正式写库前先给教务管理员一份预演：新增多少人、补齐多少人、疑似同名多少人、跳过多少人，按部门分组，可勾选排除。疑似同名会显示匹配依据（工号/手机/姓名+部门），由管理员确认是否合并；合并只补空字段，不覆盖已有值。确认后才写库，预演严格只读。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 预演接口只读：不写 `teacher`，不产生业务数据，只返回四类结果与明细
- [ ] 四类结果：新增、补齐（有可填空字段）、疑似同名（匹配键不足）、跳过（负 id 部门/已排除/无有效字段）
- [ ] 预演结果按部门分组，前端可整部门或单人勾选排除
- [ ] 匹配顺序固定：`dingtalk_user_id` → 工号 → 手机 → 姓名+部门（仅提示，不自动合并）
- [ ] 补齐只填空字段；非空字段冲突在预演中标记且不覆盖
- [ ] 确认接口接收选中范围，写入后返回结构化统计并记 `audit_log`
- [ ] 预演与正式落库共用同一套匹配/补齐逻辑，不允许「预演说新增、落库却更新」
- [ ] 47 位存量教师跑完预演后显示为「疑似同名/可补齐」，确认后仍是 47 位，不新增重复
- [ ] 集成测试覆盖：预演零写入、确认后新增/补齐/疑似同名按预期落库、重复执行幂等
- [ ] 前端同步页展示预演表、部门分组、勾选排除、确认按钮与完成统计
