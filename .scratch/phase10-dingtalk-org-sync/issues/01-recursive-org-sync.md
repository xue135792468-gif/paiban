# 01: 钉钉通讯录递归同步

**What to build:** 教务管理员点一次「同步通讯录」，系统递归遍历钉钉部门树，把应用权限内能读到的全部教职工导入本地教师表，而不是只导入根部门直属的 2 个人。负 id 部门（含 `-7` 家校通讯录）跳过；同一用户跨部门只导入一次；离职人员导入为停用；成功日志写明扫描了多少部门、多少人、耗时多久。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 从根部门递归 `department/listsub`，深度优先遍历整棵部门树；部门 id 为负数的直接跳过，不报错
- [x] 每个部门用 `user/list` 分页拉取到底，跨部门按 `userid` 去重
- [x] 不引入部门白名单或 `sync-dept-id` 设置项；导入范围完全由钉钉权限决定
- [x] 部门名含「离职」或用户 `active=false` 的用户落库为 `active=false`，不出现在排课候选
- [x] 同一用户出现在多个部门时只创建/更新一次
- [x] 成功路径输出 INFO：扫描部门数、用户数、耗时；`OrgSyncResult` 带扫描量
- [x] 钉钉错误透传 `errcode` / `sub_code`；IP 白名单错误（88/60020）给出明确提示
- [x] 假客户端单元测试覆盖：三级部门树、重复用户、负 id 部门、离职部门、分页边界、`errcode=41`
- [x] 云端实测：扫描部门数与用户数与钉钉后台可见范围一致；47 位存量教师不被重复创建

**实现说明：** 递归 `department/listsub` + 逐部门分页 `user/list`，按 `userid` 去重；负 id 部门跳过；离职部门或 `active=false` 落库停用；本轮未出现的教师不自动停用；匹配顺序 `dingtalk_user_id` → 工号 → 手机。错误透传 `errcode` / `sub_code`，IP 白名单（88/60020）有明确提示；access token 在遍历期间缓存并对异常消息脱敏。2026-10-24 云端只读预演：49 个部门 +「家校通讯录」跳过、368 人，与规格实测一致；47 位未绑定教师全部落在疑似同名/跳过，没有姓名落进新增，确认写库留给管理员手动测试。
