# 多条约束与分组折叠页面规格（原票 10）

Status: done（六票完成并上线；见 issues/06 上线记录）
批次：六项导入后修复之后。2026-10-25 用户已确认产品语义及六张拆票。
第一张交付为原型；原型需用户确认后才进入生产实现。

## Problem Statement

同一类型只能存一份参数，多位教师、多门课程会互相覆盖；二十多类表单同时展开难以浏览。直接放宽数据库唯一键还会让求解、草稿、调代分别读取不同规则。

## Solution

同类约束以多条对象条件呈现，分组折叠卡片显示摘要。启用、软硬与权重保留为类型级控制；参数条目可增加、编辑、删除。阈值允许全局默认及具体对象例外，多个评估入口使用相同对象匹配与覆盖语义。

## User Stories

1. 作为教务管理员，我想为两位教师分别设置禁排，第二条不会覆盖第一条。
2. 我想为同一教师禁排多个时段，全部生效。
3. 我想为同一教师设置多个可选偏好时段，任一匹配都算满足偏好。
4. 我想为多门课程指定条件，彼此不干扰。
5. 我想保留全局每天最多 6 节，同时对王老师单独设置 3 节。
6. 我想明确看见哪些值是默认、哪些被对象例外覆盖。
7. 我想在输入重复或互相矛盾的条目时获得错误位置，不被最后一条静默覆盖。
8. 我想按组收起表单，只看已启用数量与每条摘要。
9. 我想在添加和编辑时只看到适合这一类规则的对象和参数。
10. 我想用模板保存全部条目，再套用到适合的学期。
11. 我想升级后原有单条配置与模板仍表达相同意思。
12. 我想让求解、草稿校验、发布与调代检查读取同一套规则。
13. 我想在生成调代方案后改约束时，审批仍检查当前规则，避免旧方案绕过新要求。

## Implementation Decisions

### 已确认的控制与组合语义

- 同一类型共用 enabled、hard、weight；每条仅有稳定身份、对象与条件。请求中同类型控制不一致时明确拒绝，不靠读取顺序选最后一条。
- 禁排条目取并集；不同教师各自作用，同一教师多个时段都不能排。
- 教师偏好时段对同一教师聚合为可选集合，命中任一时段即满足。每节课不能因为没同时命中多个时段而重复扣分或永远违反硬条件。
- 同一课程的互斥教室类型要求不能并存；提示冲突并保留已保存配置。需要多种可选教室类型属于另一个需求。
- 同一阈值的同一作用域最多一条，全局默认最多一条；重复或冲突明确拒绝。不依赖数据库排序或 Map 后写覆盖。
- 完全相同目标条目拒绝重复；对同一对象且条件不可兼容的标量条目明确报错；兼容的禁排/无课日条目累积。带可选“全部”目标的规则，重叠匹配不能给同一违反事实重复计分。
- 同类共用开关：关闭类型即关闭全部条目；条目没有独立启用开关。多目标/阈值类型的空列表表示无生效条目，不隐式补一条规则；单开关类型启用时视为一条生效规则。
- **空条目语义（2026-10-26 用户拍定，方案 1）**：列表为空**只**表示该类型未配置，永不表示「全部对象」。要表达「适用于全部课程 / 全部学科 / 体育类」必须落成**一条显式条目**（对象字段留空或选「全部」，例如「课程＝全部 → 一天最多一节」）。现有 5 类「留空表示全部 / 体育类」的旧配置（`TEACHER_MEETING_BLOCKED` 的学科、`SAME_COURSE_ONCE_PER_DAY`、`SPORT_NOT_FIRST_AFTERNOON`、`COURSE_SPREAD`、`PE_LAST_PERIOD_AVOID` 的课程）在迁移时各转成一条显式条目；前端要给「全部」一个可发现的入口（勾选或明确的「全部课程」选项），不能靠留空。
- 阈值只针对自然匹配的对象：教师上限选教师、班级上限选行政班、课程上限选课程；晚自习按行政班，连续上课按教师。具体对象存在时替代该对象的全局默认，未覆盖对象仍使用全局值。只有对象例外而无全局值时，不凭空为其他对象启用一个默认阈值。

### 保存、兼容和评估

- 从“每类型唯一一行”扩展到多条时保留原有配置，不丢失参数、不偷偷改变启用状态。按条增删改须有稳定身份；整次提交先全量验证，失败不部分覆盖。
- 对象 ID 按领域归属校验：教师/课程为全局资产，行政班归当前选定学期；不能笼统说所有教师/课程都必须有 semester_id。
- 求解评分、草稿检查与发布调用、调代独立硬检查与软评分、只读 CLI 都采用同一条目集合/对象选择/覆盖语义。硬规则负责相应流程的阻断，软规则计分与解释保持各流程的既有口径，不因拆列表额外叠加。
- 为既有单条与新多条行为做对照；第一条纵向票包含兼容适配，使其余旧类型仍可运行，不能先破坏所有调用方再靠最后一票补绿。
- 调代审批继续按当前规则重验。不复用旧校验缓存；对 hash 未含约束的现状做兼容审查，不把单纯快照 hash 相同当作规则未变。**判定是差分口径**：只拒绝本次方案**新引入**的硬约束违反，基线里本来就有的违反不拦（否则基线已违规的学期永远批不了任何调代），因此收紧规则后旧方案只要不更坏仍可批；确切的语义与理由见 `docs/adr/0025` 的「2026-10-26 修订记录」。
- 模板保存全部条目与类型控制，旧单条模板可读可套用。审查原文本容量，超出时使用兼容迁移，不能静默截断。
- 跨学期模板的行政班引用需重新匹配或明确拒绝并提示，无效 ID 不得落库；不自动按同名猜测映射。教师/课程保留有效全局引用。

### 页面

- 采用分组折叠卡片；默认收起，组标题显示启用类型数/类型总数，并另外标记**具体条目**数（2026-10-25 用户拍定的口径：会落库的条目；开关型不计入），避免把类型数和参数行数混为一谈。
- 卡片头显示名称、说明、类型启用开关；软硬与权重是同类共用配置，硬约束隐藏无意义权重。保留既有学校模式的可见性。
- 体内每条一行摘要与编辑/删除；底部添加。阈值默认项、对象例外、被覆盖值有明确标签。
- 页面顶部显示已启用类型、硬约束类型、**具体条目**计数，保存动作可见；统计均来自当前渲染数据，左边导航的逐类条目数与分组头与顶部同源（同一个 `entryCountOf`）。**关闭类型时，它已配置的具体条目仍计入**——开关关闭只表示不评估，不表示配置消失；开关型（无条目）始终计 0。
- 先用合成数据原型确认密度、折叠、空状态、错误状态与较多条目表现；原型获用户确认前不得宣称页面设计完成。

## Testing Decisions

沿用公开配置/模板 REST、求解任务与草稿 REST、现有纯规则检查/调代 verifier/CLI 边界、前端组件及 Playwright。采用合成教师/课程，不调用真实 AI。

- 两教师禁排均保存且生效；同一教师两个禁排均生效。
- 同一教师两个偏好为“或”；启用为硬规则时也不能变成要求同时在两个时段。
- 教室类型冲突、重复阈值、非法范围、跨学期班级、同类型控制不一致：错误定位正确且原配置不变。
- 全局 6、教师甲 3：甲第 4 节违反，乙第 4 节不违反；删除甲例外后恢复全局；关闭类型后全局与例外都不生效。
- 五个阈值各断言计数对象与覆盖；软规则的 penalty 在多入口中不因重复匹配膨胀。
- 24 类目录逐类标记已覆盖，并比较旧单条配置的结果；不能只验证 teacherId。
- 模板多条往返、旧模板升级、容量、跨学期引用、重复套用与失败原子性。
- 生成调代方案后修改硬约束，审批在新规则下重验，不产生部分生效；只读 CLI 给出一致结论。
- 前端增删、组/页计数、空状态、摘要、例外显示、保存恢复；Playwright 截图留存。

## Out of Scope

自然语言生成、任意 DSL、每条独立硬软权重、改变发布基线、为所有阈值开放任意种类对象、默认猜测跨学期对象映射。
