# 11: 按账号和学期恢复未保存工作，跨设备冲突不覆盖

**What to build:** 教务刷新、离开或换设备后，可以恢复输入、生成建议、补齐选择及已加入但未保存的修改；同账号多设备和不同账号互不悄悄覆盖，恢复后核对变化再保存。

**Blocked by:** 10 — 校对AI建议后加入约束表，统一保存并追溯改动。

**Status:** done（2026-10-27）

2026-10-27 用户已确认本轮12票拆分及阻塞关系，正式发布；实现范围与共同约束以[正式规格](../spec.md)为准。

- [ ] 服务端未生效工作区按账号和学期保存原话、轮次、补齐、选择、表中未保存修改及其基础配置版本；恢复能继续编辑，不直接改生效配置。
- [ ] 同账号同学期跨设备可恢复，不同账号及不同学期隔离；暂存/恢复/清除的服务端权限受约束管理与本人边界保护，不能读取或写入他人的未保存工作。
- [ ] 工作区有独立版本，不与生效配置版本混用。同账号两设备竞争暂存时检测变化，保留本地分支供核对，不按最后自动保存覆盖另一设备。
- [ ] 恢复时复核教师/课程/行政班、作息与配置变化；失效或改义项保留并定位待重选，未解决不能保存。每日/下午的旧展开不因新增课节扩大。
- [ ] 生效配置已经由他人更新时，恢复不跳过保存版本校验；保留本人的未完成内容，核对最新配置后才保存。单纯恢复、暂停生成或保存失败不产生业务生效审计。
- [ ] 自动暂存失败保留当前页面并明确提示，只有服务端确认才显示可跨设备恢复；不谎称已经保存。统一保存成功后工作区与成功版本协调，不恢复出已过期的脏状态。
- [ ] 生成轮次、工作区修订与最终确认保留准确关联，原始输出不被人工覆盖；再次恢复/重放不重复生成请求、添加要求或记录独立生效。
- [ ] 用真实并发及持久化请求验证多设备版本竞争、账号/学期隔离和恢复重验；Playwright用新浏览器上下文恢复、两个设备竞争、暂存失败与最终保存，留关键截图。

验收映射：A08/A09/A17，以及A07/A12/A15的恢复与重放部分。本票把完整未保存流程连成可跨设备的纵向体验，不拆成纯后端暂存和纯前端恢复两票。
