# 07: 配置被他人修改时保留本人的工作供核对

**What to build:** 两位教务同时修改时，后保存者不会覆盖先保存者的新要求；手工保存和模板套用采用同一版本核对，冲突时保留本人的表格并查看最新配置后再保存。

**Blocked by:** 01 — 手动配置课程禁排，打通分组要求与逐项控制。

**Status:** ready-for-agent

2026-10-27 用户已确认本轮12票拆分及阻塞关系，正式发布；实现范围与共同约束以[正式规格](../spec.md)为准。

- [ ] 生效配置读取返回基础版本，完整保存要求核对该版本并原子更新；服务器检测真实竞态，不以页面保存前先读一次替代并发保护。
- [ ] 所有能改变生效约束的入口共同推进同一学期配置版本，包括手工保存、模板套用和首次配置，不留绕过路径；后续要求族迁移与模板适配沿用同一契约。
- [ ] 发生版本变化时明确冲突、零部分写入，保留本人的修改，提供最新配置与本地差异供核对；不能自动最后写入覆盖，也不能让手工修改从页面消失。
- [ ] 核对后采用最新基础版本重新保存，完整配置中未修改的类型与要求保留；重复保存不累计同一要求，成功版本和最终变化可追溯。
- [ ] 兼容旧格式时不允许无版本写入抹掉新要求；确需更新协议的旧请求给出明确错误，不为了兼容放弃防覆盖。
- [ ] 暂存工作与生效配置的版本区分；本票只完成生效配置并发，未引入后续跨设备工作区时不能宣称已能恢复未保存内容。
- [ ] 后端用真实并发请求证明两用户保存竞争及模板/保存竞争只有合法版本能生效；Playwright用两个浏览器上下文验证冲突提示、内容保留、核对重存并留截图。

验收映射：A07及A01/A10的版本保护前置。本票可在01后与各规则族迁移并行，但须在共享接口变更后做受影响定向回归。
