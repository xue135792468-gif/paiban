## 接口契约（全部已存在，禁止改动）

- 代课预览：`POST /api/substitution-workbench/previews`（返回凭证 id、deadlineAt、左右网格、变化清单）
- 调课候选与预览：`POST /api/substitution-workbench/swap-plans` → `POST /api/substitution-workbench/swap-previews`；对照 `GET /api/substitution-workbench/previews/{id}/swap-compare`
- 提交/确认：`POST .../{id}/submit-approval`、`POST .../{id}/confirm`、`.../submit-approval-swap`、`.../confirm-swap`
- 错误语义按现有实现处理：409（旧快照/已有活跃单/跨科需确认等）→ 用大白话中文提示 + 「重新生成」；凭证过期同理

## 视觉与交互契约（以 v3a 原型为准）

1. **顺序**：方案页签（仅调课，来自真实候选）→ 一句话结论卡（左侧品牌蓝竖线）→ 跨科提醒（仅跨科代课，琥珀色 + 「我已知晓，可以跨科」勾选，未勾选时两个提交按钮禁用）→ **课表怎么变** → 折叠文字明细 → 保留时间小字 → 底部操作栏。
2. **课表变化可视化（本票核心）**：
   - 每周一张迷你周表（周一~周五 × 第1/2节），表头「本周 · 10/26–10/30」，跨周再加「下周 · 11/02–11/06」；
   - 变化格：旧值灰色删除线 → 新值绿色 500 字重，左上角 ①②③ 编号；格整格淡蓝底 + 品牌色边框；数字编号与首行文字不得重叠；
   - 图例一行：「① 语文：本周三 → 下周一第1节　② 英语：下周一第1节 → 本周三」；
   - 代课：一格「课程 旧师 → 新师」；同周调课：两格对调；跨周调课：本周一格 + 下周一格；方案 B 追加 ③ 移出/移入两格；
   - 320px（≤520）：改为按天列表（「① 周三第1节 语文 张老师 → 英语 李老师」），无横向溢出。
3. **文字明细**：`<details>` 折叠；内含「项目/原来/改后」三列表（只列变化行、旧值删除线、新值绿色、末行其余不变）与按人句子清单。
4. **提交与成功态**：提交审批 → 成功态「已提交审批」（课表不变）；亲自确认 →「已生效」+ 通知说明；「再调整一节课」回步骤1并清空全部状态。取消/返回步骤2时不得产生凭证消费或写入。

## 实现说明（2026-10-30）

**做了什么**：第③步重做为 `ConfirmStep.vue`：方案页签（仅调课）→ 一句话结论卡（品牌蓝竖线）→ 修订横幅 → 跨科提醒与勾选门 → `ChangeVisualizer` 课表变化可视化（每周迷你周表、旧值删除线→新值绿色 500 字重、①②编号、跨周「本周/下周」两排、图例一行）→ `ChangeDetails` 折叠文字明细（三列对照表 + 受影响人清单）→ 底部提交审批/亲自确认与成功态（含「再调整一节课」全量重置）。请求编排与状态机收口在 `useConfirmFlow.ts`：previews / swap-plans + swap-previews / submit / confirm / 修订与恢复基线全部走真实接口，序号防竞态（慢响应与页签切换不回写旧状态）；跨科结论等动态值先转义再 v-html。可视化纯计算抽成 `changeVisual.ts` 并配 234 行单测。

**关键取舍**：
- **方案页签文案**：主标题「方案 A（推荐）」「方案 B」+ 副行「N 节课对调 · 影响 N 天」；单方案也显示单页签（统一交互，避免有/无页签两套布局）；testid 用 `swap-plan-tab-0/1` 按序号编址而非按字母，字母只出现在展示文案里。
- **confirm-error testid 约定**：生成失败、409/过期、调课无解三种错误统一把 `data-testid="confirm-error"` 挂在错误条容器（role=alert）上，e2e 只认容器 + 内部文案；无解的后端逐条原因行保留 `confirm-no-solution` 旧名，断言不绑死具体文案。
- 返回步骤 2 / 取消直接弃用凭证（invalidate），零请求零写入；重进步骤 3 按最新课表重新生成。
- **390px 与 320px 分工**：本票 spec 的窄屏用例用 390px（变化可视化按天列表 + 无横向溢出，常规手机代表宽度）；320×700 的极限宽度断言（含导航隐藏）统一落在票 03 的 `workbench-a11y.spec.ts`，避免两条近似链路重复跑。

**证据**：`workbench-confirm.spec.ts` 9 条用例（代课结论/亲自确认生效/跨科门/同周/跨周 1280×720 同屏/A-B 格数变化/返回零写入/409 错误条/窄屏按天列表）随 8 个工作台 spec 整批连跑两遍全绿（33 用例/轮，6.0m / 6.1m，退出码均 0）；全量门禁 `verify.sh --full` 退出码 0（前端单测 438 全绿、Playwright 137 全绿）；截图 `t02-01-cover-conclusion-visual.png` ~ `t02-08-narrow-change-list.png`（`.scratch/workbench-ui-redesign/acceptance/`）。
