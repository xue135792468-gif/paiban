## Problem Statement

整本工作簿虽按 40 行取值，却仍在一次请求内同步完成。进度、停止与失败重试只覆盖旧的单目标路径；任何一批失败可能丢失前面已得到的结果与工具轨迹，页面只能长时间等响应。

## Solution

规划与取值进入既有独立导入线程，持久化计划和每批结果，页面可恢复进度；停止保留结果供检查，放弃不写业务数据；只重试失败/未完成批次，成功批次不重调模型。

## User Stories

1. 上传后我能看到会话和解析阶段，不必等同步请求全部完成。
2. 刷新或切页回来后能看到已经完成的批次。
3. 我能看到工作表、完成/总批次及失败范围。
4. 我能停止后续调用，保留已完成结果。
5. 放弃后旧请求晚返回也不能把会话改回可入库。
6. 我能只重试失败/未完成范围，不重复付出成功批次调用。
7. 重试合并仍按槽位去重，并保留原始 AI 输出。
8. 有失败或未覆盖范围时系统不生成缺班的业务课表。

## Implementation Decisions

- 复用八期的单独导入执行器与可恢复会话原则，与求解线程隔离，先串行，避免自动增加并发请求。
- 后台范围包括工具规划与取值，页面能区分阶段；计划完成前进度不得伪造固定总批次。
- 稳定批次身份必须带工作表、数据范围、结构/计划版本。旧的“每班一批”数据结构需要兼容适配，不能直接套用索引。
- 规划失败或重启时若尚无确认结构/持久化计划，提供用户显式“重新规划”入口，记录新一轮结构版本；这不属于批次重试。已有确认计划后，批次重试不重新规划，不重跑成功批次。
- 工具轮次与批次原文及时落审计；AI 调用在事务外，结果与阶段/计数在短事务内一致写入。
- 单批失败记录后继续其他批次；重启使遗留运行标记为可恢复，不自动无限重放外部请求。
- 停止在批次间生效，不承诺能撤销已发出的 HTTP 调用；晚返回保留审计，但不改变已停止/放弃/被新运行替代的有效预览。
- 保留运行身份和乐观版本，解决停止、放弃、重试、提交竞态。同一会话不同时启动两轮有效执行。
- 沿用八期“不默认部分入库”：有失败、待执行、停止造成的未覆盖范围时禁止提交。停止保留结果不是允许缺班入库。
- 重试只处理失败/未覆盖工作；成功批次不重调。重合并使用整本现有跨表去重、空课位和类别规则，不累计重复预览行。
- 解析/重试不写业务主数据；显式提交继续按类别分事务，原始输出、工作预览、确认与最终结果分开。
- 上传、查询和停止/重试保持会话权限、旧单目标路径及历史会话兼容。

## Testing Decisions

复用八期 REST＋可阻塞假 AI 网关、现有竞争/分发失败测试、整本跨表合并样例与 Playwright stub，不调用真实模型。

- 多表多批可轮询观察中间计数，刷新后恢复；后台规划失败可见且没有假完成。
- 成功、失败、成功三批：两批结果保留，第三批仍执行，失败范围可追溯，不可提交。
- 停止与晚响应、放弃与晚响应、新一轮重试与旧响应、重复点击各自有稳定回归。
- 仅重试失败/未覆盖批次，成功批次调用次数不增加；跨表重复槽位最终仍只有一节。
- 重启恢复、执行器拒绝、审计持久化失败不能卡成永远 PARSING 或自动变成可提交。
- 单目标导入功能继续通过，未覆盖范围提交在前后端都拒绝。

本批六项修复、自然语言约束、按班并发、自动无限重试、部分课表入库、取消已到达供应商的请求。
