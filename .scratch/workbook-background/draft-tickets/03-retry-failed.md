# 草案 03: 只重试失败或未覆盖范围并正确重合并

**What to build:** 用户能只重跑失败/未完成的工作簿批次，成功批次保留，合并结果不重复，完整后才允许确认。
**Blocked by:** 01
**Status:** draft
**Execution:** 下一批；推荐 02 后串行集成
**Spec:** ../spec.md

- [ ] 失败/未覆盖计划可重试；成功批次不重复调模型，不重新猜结构或重复建会话。
- [ ] 无确认计划的规划失败转向 01 的显式重新规划入口，不冒充批次重试；已有计划的重试保持原结构版本。
- [ ] 同一会话只有一轮有效运行；新旧响应、重复重试、提交竞争有明确身份/版本保护。
- [ ] 重试后的跨表合并沿用槽位去重和完整行优先，预览/类别计数不重复累加。
- [ ] 原始每轮工具/批次输出、最终工作预览与用户确认分离可追溯。
- [ ] 有任何未完成/失败范围仍拒绝提交；全成功后可进入现有按类别事务的确认流程。
- [ ] 受控假网关断言成功批次调用数不增加、失败批次仅重试一次，覆盖新旧响应竞争与跨表重复槽位；旧单目标回归保持通过。
- [ ] 先红后绿，独立评审、完整闸门及整本流程截图。

**依赖说明：** 重试依赖 01 的计划和运行身份，不依赖 02 的停止按钮；若 02 已落地，增加停止后重试和晚响应的联合回归。
