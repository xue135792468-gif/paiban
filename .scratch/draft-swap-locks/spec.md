# 草稿直接换位、联动方案与批量锁定

## 目标与范围

教务在自动排课生成的草稿上直接拖拽换位、批量锁定授课，并基于这份草稿继续优化。成功操作即时保存；最终发布仍必须通过整表规则与完整性检查。

仅改善发布前草稿。已发布基线保持只读，具体日期临时调整继续走既有调代流程。原有显式跨班换人入口保留并服从锁定，不把拖拽到别班课程解释为换教师。

## 一、直接拖拽

- 行政班与教师视角均支持拖拽。以来源授课的行政班为操作范围，教师视角不会把不同班级的授课隐式交换。
- A拖到同班B：先对两节课的完整交换做校验，不能因为落点目前被B占用就当作单课移动失败。合法则两节一起保存，无须再从列表选择B或二次确认。
- A拖到本班可用空格：合法则直接移动，原位留空，周课时不减少；每周必须留空的位置不可作为落点。
- A、B的课程、行政班和任课教师随各自授课保留；移动本身不改变任课归属。固定教室和专用教室规则按现有统一规则处理，不盲目交换教室。
- 拖回原位不产生变更；来源锁定、落点授课锁定或跨班落点均明确拒绝，不绕开锁定另找替代目标。
- 无法唯一识别落点授课（例如既有冲突导致同格多课）时，不随机选择；提示先选择明确课节或修复该格问题。

## 二、自动列出联动方案

- 当A到B的直接交换有硬冲突时，自动搜索并展示最多三个方案；不增加“帮我找其他方案”的前置按钮。
- 方案必须让A到达用户指定落点，并在同一行政班的本周周期课表中用其他未锁定授课完成闭环换位，保留授课集合。不跨班、不跨到下一周。
- 预览明确列出每一节课的前后位置、教师、移动课节数、去重教师人数和软偏好变化；用户选择并确认应用后才修改其他课程。
- 全方案一起生效或完全不生效，不允许只移动其中一部分。
- 来源班以外的授课必须参加教师等冲突检查，但不会被本次搜索移动。
- 按搜索资源预算区分“在当前范围和上限内无可用方案”与“本次搜索未完成”；预算耗尽仍找到方案时可以展示已独立验证的方案，但不得声称已穷尽或全局最优。
- 旧预览失效、锁定变化、课表被他人修改或规则变化时，应用前重新核对；不能拿过期预览直接落库。

## 三、共用方案设置

草稿换课和发布后调课共用一处配置和持久化值：

| 设置 | 决定 |
|---|---|
| 最多变动几节课 | 2–10，默认6，沿用原设置值与兼容接口；包含来源课，限制闭环长度 |
| 方案排序 | 沿用最小影响、最少教师、最稳课表三种预设与相同排序含义 |
| 搜索多少天 | 只用于发布后具体日期调课；不截断草稿的本周有效星期范围 |
| 审批和通知 | 保持发布后调代的适用范围，不施加到草稿即时保存 |

原“方案教师上限”的代码实际限制环长，因此改为“最多变动几节课”，不把旧值重新解释为仅限制去重人数。去重教师数是另外一项展示与排序指标。

新方案使用最新设置，旧预览失效后重新生成；设置页面注明修改会同时影响两处。直接合法交换仍优先，不强制为了排序而先等待联动搜索。

周期草稿的影响天数按涉及星期去重；所有候选均在同一周，排序中的同周条件自然相同，不使用任意虚构日期让排序失真。

## 四、课节锁定

- 锁定保护具体一节授课的时间与任课教师；相同课程一周多次授课可分别锁定，不能混淆为锁定所有数学课。
- 支持单节、多选、当前行政班某一天、当前行政班整张表上锁和解锁。批量操作前显示数量和范围；批次整单成功或失败，失败指出原因。
- 刷新或重开页面后锁定仍存在；表上有可辨识的锁定标记。多选模式与拖拽模式要有明确区分，键盘/点击入口可完成同等操作。
- 直接移动、两课交换、联动方案、显式跨班换教师、撤销及继续自动优化均服从锁定；不能通过另一接口绕过。
- 未排上时间的授课不能锁住不存在的位置；说明原因。已经违规但有明确位置的课可以被锁定，但保留违规提示，锁定不证明合规。
- 锁定课与新规则冲突时，不自动解锁或放宽规则；指出冲突，由用户处理，未修复不能发布。

## 五、自动保存与撤销

- 成功操作自动保存，自动保存不等于发布。失败不改变现有安排，界面与服务端保持一致。
- 支持逐步撤销已成功的位置调整，整个联动方案作为一步撤销；不只撤回其中一节。
- 撤销以当前权限、规则、课表和锁定状态重新校验。操作后新增锁定导致无法撤销时，提示先解锁，不能默默解除保护。
- 沿用现有最近20步、当前编辑会话的撤销范围；跨刷新恢复历史与重做不作为本版新增目标。锁定状态的持久化不依赖撤销栈。

## 六、基于当前草稿继续自动优化

- 显式以用户当前这份草稿及锁定状态为输入，未锁定的当前安排也是初始解来源；不能因默认热启动优先级而换用已发布基线或最早草稿。
- 生成另一份草稿供比较，原草稿保留；对应授课的锁定时间和教师必须保持，新草稿继续带锁。
- 锁定身份不依赖两份草稿偶然相同的数据库行ID；匹配授课任务及具体授课身份，不能用不稳定的任意顺序冒认同科多节课。
- 授课任务已变更、来源引用失效或锁定映射不唯一时，停止并说明，不静默漏锁或回退另一个来源。
- 全部锁定时明确说明无可优化课程，不假称已改善。锁定与硬规则冲突或本次求解无法达到发布标准时，报告阻碍/未完成状态；原草稿保留，不解锁、不放宽规则、不宣称成功或可发布。
- 普通“新建自动排课”继续保留既有默认来源策略。本功能单独增加显式“基于当前草稿继续优化”的路径。

## 七、最终合格的判定

- 整表无硬冲突、无未完成授课任务、作息/教师/班级等引用有效，满足现有发布完整性与流程门槛，才允许发布。
- 偏好类约束下降可提醒，不作为硬冲突拦截。用户认为必须满足的要求应配置为硬约束；求解器分数、找到一个交换方案、成功保存三者均不替代发布检查。
- 对已有不合格草稿允许逐步修复，但不能引入不同的新硬冲突；不能只比较冲突总数，让“修一处同时新增另一处”蒙混通过。剩余问题持续展示，发布仍作全量绝对检查。
- 手动调整、联动搜索、独立验证与最终发布共用基础规则定义；搜索剪枝不充当最终验证。最终算法判断与验收结论由主模型负责。

## 技术保障（主模型提出，服务于上述产品决定）

- 写入时执行权限、草稿所属关系、可编辑状态、锁定和并发一致性检查；事务保护交换、方案与批量锁定。确认/预览与提交之间发生变化则拒绝过期请求并刷新。
- 锁定由服务端强制执行，不能只禁用前端拖拽；对授课删除/覆盖等旁路不得静默丢弃锁定，明确拒绝或要求先解锁。
- 复用基础规则与排序语义；草稿与按日期调代各自适配输入、生命周期和写入边界，不将审批/日期身份直接移植到周期草稿。独立校验不依赖搜索剪枝保证正确性。
- 补充审计与可理解错误，遵守仓库权限、事务、模块边界、前端拆分规范。共享设置旧键兼容迁移，Flyway编号实施前查各分支。
- 搜索预算与并发资源限额由实施阶段验证，不能因为参数上限提高而无限搜索或增加求解器线程；未完成搜索必须如实反馈。

## 工作拆分（正式票据已发布）

1. **持久化锁定与所有写入口保护**：字段/接口、权限、批量事务、锁定身份契约。
2. **共用设置与草稿联动规划/独立校验**：更正上限名称、兼容旧值、复用排序，输出可应用的整单方案。
3. **直接拖拽、自动候选与整单撤销**：明确落点，交换/移动、预览应用、自动保存和并发失败反馈。
4. **单节与批量锁定交互**：多选、整天/整表，标记和等价点击/键盘入口。
5. **指定草稿继续优化**：显式来源、锁定继承、新草稿对比、失败保护。
6. **统一验收与收尾**：修复路径、全量发布检查、交叉接口防绕过、回归与使用帮助。

以上为能力顺序概览；正式细拆为九票，见[ticket-plan.md](ticket-plan.md)和[跨票契约](contracts.md)。全部ready-for-agent且未认领；初始可开工集合01、03。锁定领域契约先稳定，实际并行只安排互不改写同一文件的前沿任务，本轮不派发实施。

## 必须提供的验收证据

- 合法A/B一拖完成，两节都更新，重载后保持；空格移动和拖回自身行为正确。
- 直接交换失败自动列方案；选中一个方案后所有移动一起生效；取消/无解/超时不改课表。
- 多节课由同一教师授课时，移动课节数和去重人数分别准确，上限按课节数约束；三个排序遵循现有语义。
- 锁定来源、落点、中间课均不会被移动；刷新仍锁定；批量混合错误不得部分生效；跨班换人和撤销不能绕锁。
- 他人操作、规则/设置/锁定变化后不能应用旧方案；强制交错服务级验证加可观察HTTP结果，避免仅依赖脆弱E2E时序。
- 修复已有冲突可逐步推进，不引入另一种新冲突；最终全量硬规则和完整性失败均不可发布。
- 继续优化使用指定草稿，保留原稿和全部锁；同科多节可区分，授课任务变更不会静默漏锁；不合格结果不标成功。
- 班级/教师视角、批量选择与键盘入口有真实用户操作E2E；后台集成测试覆盖事务、权限、锁定和原子性。
- 按仓库流程复审，定向测试后冻结源码跑统一门禁；文档与实际结果一致。合并、部署需按后续用户授权执行，不自动修改生产课表。
