# 课程周课时数、任课表方阵导入与班主任自动分组

Status: done
Feature: course-weekly-hours-and-teaching-matrix
Date: 2026-11-26
来源：产品所有者三轮 `/grill-with-docs` 访谈确认（Q1–Q12），决策记录见 ADR-0038。

## Problem Statement

教务管理员在学期初准备排课数据时面临三处高频摩擦：

1. **课程看不到每周几节，录入重复劳动高**：在「课程管理」页面只能维护课程名称、学科、连堂与颜色，看不到一门课常规一周上几节；每次新建或批量导入授课任务都得反复填写每周节数。
2. **学校现成的「班级任课表」Excel 无法直接作为排课数据源**：教务处日常流转的是按年级编排的二维方阵表（行是班级，列依次为「班级、人数、班主任、语文、数学、英语、科学、历史地理、道德与法治……」），而系统现有的授课任务页只有竖向列表，授课任务导入也只认「一行一条」的模板格式；刚建好空学期时，无法把这张现成的任课表直接导入来初始化班级、人数、班主任、教师、课程与授课任务，更无法在网页里像看大表格一样一目了然地浏览、换老师或清空单科任务。
3. **班主任排课规则需要手工逐个勾人**：排课规则页虽然支持教师分组，但系统不会根据行政班的班主任信息自动建立「班主任」分组；学校既可能给全校班主任统一设规则（如全校班主任例会），也可能只给某个年级班主任设规则（如八年级班主任教研），手工维护极易遗漏或过时。

## Solution

1. **课程目录新增可选「周课时数」**：在课程管理列表、表单及课程 Excel 导入/导出模板中新增「周课时数」（1–20 或空），定位为新建或导入授课任务时的默认每周节数；后续修改课程默认值不回溯影响已有授课任务。
2. **数据管理新增「任课表」方阵页面**：按「学期 + 年级」以「行政班 × 课程」二维方阵展示现有授课任务，左侧附带班级人数与班主任列；点击任意格子可新建授课任务、更换任课教师、调整该班每周节数，或经二次确认后软删除该格任务并立即提供一键撤销（同时进 7 天回收站兜底）。任课表与授课任务共用同一份底层数据，修改即刻生效于自动排课。
3. **支持任课表二维矩阵 Excel 导入、导出与模板下载**：采用两阶段暂存导入（只读预演 → 单事务原子提交）。用户选定目标学期与年级后上传表格，系统将「班级 / 人数 / 班主任」解析为班级元数据，将各学科列逆透视为授课任务：
   - 已有班级按年级内班号匹配，缺失班级在预览确认后按「年级名（班号）班」自动新建，同时写入或更新学生人数与班主任；
   - 缺失的教师与课程在预览清单中显式列出，确认后自动新建；同名教师阻断报错不猜测；
   - 缺周课时或需要按本年级临时调整周课时的课程，可在预览弹窗中行内填写/微调，并可顺带回写为课程默认值；
   - 重复导入采用幂等合并写入，只新增或更新表内出现的学科，绝不误删未列出的学科，空格跳过。
4. **自动维护「班主任分组」**：依托排课规则的教师分组与自动填充机制，按当前学期行政班的班主任自动同步维护全校总组「班主任」以及各年级「{年级名}班主任」分组；任课表导入、行政班页修改或切换当前学期时自动刷新成员；一旦用户手工编辑某个自动分组，即转为手动分组不再被自动覆盖。

## User Stories

1. 作为教务管理员，我想在课程管理列表里直接看到每门课程的「周课时数」，以便一眼掌握各科常规一周几节。
2. 作为教务管理员，我想在新建或编辑课程时选填「周课时数」（1–20 的整数，可留空清空），以便给常规课程设定默认节数，同时允许特殊课程暂不设默认值。
3. 作为教务管理员，我想通过课程 Excel 导入模板批量导入、导出带「周课时数」的课程，以便沿用表格批量建课的习惯。
4. 作为教务管理员，我想修改某门课程的「周课时数」后，已经存在的授课任务保持原有每周节数不变，以便个别班级已经调好的特殊节数不会被意外冲掉。
5. 作为教务管理员，我想在「数据管理」里看到一个「任课表」页签，以便按「学期 + 年级」在一张二维大表格里看完本年级所有班级的各科任课老师。
6. 作为教务管理员，我想在任课表的每一行左侧同时看到该行政班的学生人数与班主任姓名，以便核对班级基本信息与任课安排是否一致。
7. 作为教务管理员，我想在任课表每门课程的列头看到该课程的默认周课时数，当某班某科实际每周节数与课程默认值不同时能有明显标记，以便快速发现特殊节数的班级。
8. 作为教务管理员，我想点击任课表里的空白格子直接挑选任课教师并带出课程默认周课时数，以便快速给该班新建一条授课任务。
9. 作为教务管理员，我想点击任课表里已有老师的格子快速更换任课教师或微调该班这门课的每周节数，以便像改表格一样完成临时换师。
10. 作为教务管理员，我想在新建授课任务碰撞到回收站中已软删除的同班同课记录时，看到清晰可读的提示（指引去回收站恢复或等待清理），以便知道为什么创建失败。
11. 作为教务管理员，我想点击任课表格子里的「删除」按钮时先看到二次确认框（说明涉及的班级、课程及草稿影响），以便防止手滑误删一门课。
12. 作为教务管理员，我想在任课表确认删除某一格后立刻看到一个「撤销」按钮，点一下就能原地恢复，以便误删后不用跳转页面就能秒还原。
13. 作为教务管理员，我想即便关掉了即时撤销提示，在任课表里删掉的授课任务依然留在「设置 → 最近删除」里保存 7 天可恢复，以便与全站删除安全机制一致。
14. 作为教务管理员，我想在任课表改完任意格子后，去「授课任务」页和自动排课里立刻生效，以便不需要做任何手动同步。
15. 作为教务管理员，我想直接上传学校现成的二维任课表 Excel（含「班级、人数、班主任」与若干学科列），以便不用手工拆成「一行一条」的模板格式。
16. 作为教务管理员，我想允许表格首行上方有学校标题行、表头里带空格或换行（如「道德与法\n治」），以便教务处导出的原始表格不用手工清洗就能直接识别。
17. 作为教务管理员，我想在上传任课表前选定目标学期和目标年级，以便表格里只写了纯数字班号（如 1–14）时系统明确知道归属哪个年级。
18. 作为教务管理员，我想在已有班级的年级导入纯数字班号（如「1」）时，系统按班名中的数字自动匹配到本年级对应的行政班（如「八（1）」），若同一数字命中多个班级则报错阻断，以便既省心又不串班。
19. 作为教务管理员，我想在刚建好的空学期直接导入任课表时，系统自动规划补建缺失的行政班（按「年级名（班号）班」命名）、缺失的教师和缺失的课程，并在导入前预览清单中明确展示「将新建」的数量与明细，以便开局靠一张表完成基础建档。
20. 作为教务管理员，我想导入任课表时顺带把表里的「人数」和「班主任」写入或更新到对应的行政班，以便一张表同时维护好班级台账和任课安排。
21. 作为教务管理员，我想在任课表导入预览页看到所有缺少周课时数的课程（含即将新建的课程）并直接在弹窗里填写每科每周节数，以便无需退出导入流程反复切页面。
22. 作为教务管理员，我想在预览弹窗里对已有默认周课时的课程也支持本次导入临时覆盖（如九年级数学按 6 节导），并可选择是否顺带保存为该课程以后的默认周课时，以便兼顾不同年级的课时差异。
23. 作为教务管理员，我想在预览页看到清晰的分类统计（将新建/更新多少班级、教师、课程、授课任务，以及每行的动作标记：新建 / 改老师 / 不变），以便确认无误后再真正写入数据库。
24. 作为教务管理员，我想在表格里遇到同名教师（库中存在多名同名教师）或非法人数（非正整数）时，系统在预览阶段标出具体行号与原因并阻止提交，以便不出现乱猜老师或写一半脏数据的情况。
25. 作为教务管理员，我想在任课表只包含部分学科（如仅 6 门主科）并重复导入更新换师时，系统只新增或更新表内出现的学科，绝不删除班级已有的体育、托管等其他授课任务，以便支持分批补充与多次微调重导。
26. 作为教务管理员，我想表里的空单元格被静默跳过（既不新建也不删除原任务），以便个别班未开设某科时不受影响。
27. 作为教务管理员，我想在预览页看到班级总周课时是否超过当前学期作息表可用节次的预警提示，以便在排课前提前发现排不下的风险。
28. 作为教务管理员，我想从任课表页面一键下载按当前年级预填好班级的标准任课表模板，或将当前年级的任课表导出为同格式 Excel，以便发给年级组长核对后再导回。
29. 作为教务管理员，我想在导入任课表或在行政班页设置班主任后，排课规则页自动拥有全校总组「班主任」和对应年级的「{年级名}班主任」教师分组，以便无需手工逐人拉组就能给全校或单个年级的班主任批量设排课规则。
30. 作为教务管理员，我想当某个行政班更换班主任或移除班主任后，自动维护的「班主任」和「{年级名}班主任」分组实时同步增减成员，以便引用这些分组的排课规则永远准确。
31. 作为教务管理员，我想在排课规则页手工编辑过「班主任」或「八年级班主任」分组后，系统记住我的手工调整不再自动覆盖，以便满足学校特殊口径（如将副班主任或年级组长也放进该组）。
32. 作为教务管理员，我想切换当前学期时，自动维护的班主任分组自动跟随新当前学期的行政班班主任刷新，以便跨学期规则无缝衔接。

## Implementation Decisions

- **课程周课时数模型（迁移续号自 V64 起）**：
  - 给课程实体增加可空整型字段 `weeklyHours`（数据库列 `weekly_hours`，约束为 `NULL` 或 `1..20`），不回填存量课程。开工前须按仓库规范核查所有分支/worktree 已占用的最高迁移号，避开已被占用的版本。
  - 课程查询、保存接口及课程 Excel 导入/导出/模板同步增加「周课时数」字段（选填；导入校验非整数报错、越界 1–20 报错）。
  - 采用创建时复制（Copy-on-Create）语义：仅作为新建授课任务与任课表导入时的默认周课时，不修改排课求解器读取 `Assignment.weeklyLessons` 的既有路径，也不回溯修改已有授课任务。
- **任课表与授课任务共源**：
  - 不新建独立任课表数据表。前端数据管理导航新增「任课表」二级入口，直接聚合现有学期、年级、行政班、课程、教师选项与授课任务接口，以纯函数构建「行政班 × 课程」二维方阵。
  - 单元格编辑直接调用现有授课任务的新建/更新接口；单元格删除复用现有删除影响查询、软删除与回收站恢复接口，删除成功后在页面提供即时「撤销」操作条（调用最近删除批次恢复接口）。
  - 授课任务新建/更新碰撞到已软删除的同班同课记录时，后端返回明确指引去回收站恢复的可读冲突提示（409）。
  - 不修改已接近体积上限的既有「授课任务」列表页面文件；保持「任课表」独立组件与纯函数模块拆分，遵守前端单文件体积门禁。
- **任课表二维矩阵 Excel 通道（两阶段暂存导入 + 导出 + 模板）**：
  - 在授课任务控制器下提供同权限（`assignment:manage`）的矩阵模板下载、矩阵导出、矩阵导入预演与矩阵导入提交四个端点。
  - 表头探测：跳过首行上方标题行，定位首个包含「班级」列的表头行（清洗普通空格、全角空格与换行符）。固定识别「班级」（必填）、「人数」（选填）、「班主任」（选填），其余非空表头列均视为学科/课程列。
  - 上下文绑定与实体消歧：调用方必须绑定目标学期与目标年级。班级按年级内班名提取数字进行唯一匹配（先精确匹配同名，再按编号匹配；唯一命中则更新，未命中则在允许新建模式下规划为「年级名（班号）班」，命中多班则报错）；教师按姓名精确匹配（库内多名同名直接报错阻断，未命中规划新建）；课程按清洗后的名称精确匹配（未命中规划新建）。
  - 缺课时与覆盖机制：预演响应返回每门涉及课程的解析状态（已存在/将新建、当前默认周课时、是否缺少周课时）以及新建实体清单、行级动作明细（新建/改老师/不变）、错误列表与班级周总课时容量预警。预演与提交接口均接收可选的「课程周课时覆盖表」及「是否同步回写为课程默认周课时」选项；任何待新建授课任务所涉课程若既无默认值又无覆盖值，则预演标出缺失项、提交予以拒绝。
  - 事务与幂等：预演严格只读，零写入；提交在单个事务内 all-or-nothing 执行（只要存在任一校验错误即拒绝全部写入并记录审计），按「教师 → 课程 → 行政班（含人数与班主任）→ 授课任务 Upsert → 审计日志」顺序落库。只增改表内非空单元格涉及的学科，不删除未出现的学科，跳过空单元格。
- **班主任自动规则分组（领域事件解耦）**：
  - 遵循仓库模块边界规范（基础数据与排课模块通过中立领域事件解耦，不产生反向依赖）：在行政班创建/更新/软删/恢复、任课表矩阵提交更新班主任、以及切换当前学期时，发布班主任变更领域事件。
  - 规则分组服务监听该事件，基于当前学期全部未删除行政班的非空班主任，复用既有教师规则分组与 `auto_filled` 标记：
    - 全校总组：名称固定为「班主任」，收集当前学期所有班主任（去重）；
    - 分年级组：对当前学期每个至少有一位班主任的年级，维护名称为「{年级名}班主任」的教师组；
    - 保护人工编辑：若某个同名分组已存在且 `auto_filled = false`（用户曾手工创建或编辑过），同步逻辑一律跳过，绝不覆盖用户手改；若当前学期无班主任则不强建空组（已有自动组且成员归零时清空成员或按既有分组规则保留，不误删已被规则引用的分组）。
- **帮助文档与术语表**：
  - 术语表已同步登记「周课时数」「任课表」「班主任分组」；帮助中心补齐任课表使用与矩阵导入说明。

## Testing Decisions

- **测试原则**：只测外部可观察行为（HTTP API 响应、数据库落库状态、约束快照展开结果、用户可交互的界面渲染与端到端实测），不耦合内部私有方法或临时数据结构。
- **核心测试接缝（聚焦两条高价值接缝）**：
  1. **后端 HTTP / 服务集成接缝**（参考现有基础数据导入、授课任务集成测试与规则分组快照集成测试）：
     - 课程周课时数：校验 1–20 边界、可空清空、课程 Excel 导入导出往返，以及修改课程默认值不影响已有授课任务；
     - 任课表矩阵导入：覆盖空学期自动建班/建师/建课、老学期按班号匹配与更新人数/班主任、预览补填/覆盖周课时并可选回写默认值、幂等重导不误删未列学科、空格跳过、同名教师阻断与事务全回滚、软删除授课任务冲突可读提示、模板与导出往返；
     - 班主任自动分组：覆盖任课表导入与行政班修改触发全校「班主任」及「{年级名}班主任」同步、分组规则在排课约束快照中的展开生效、人工编辑分组后不再被自动覆盖、以及切换当前学期后的同步行为；
     - 迁移校验：确保新增迁移在 H2 与真实 PostgreSQL 容器（CI / `--deploy`）下顺序通过，且通过仓库迁移重复号检查。
  2. **前端纯函数/组件单测 + 端到端 Playwright 实测接缝**（复用项目现有 Vitest 套件与 `.agents/skills/verify-paiban/` 端到端实测体系）：
     - 前端单测覆盖课程管理周课时列/表单、任课表方阵构建纯函数、点格新建/换师/删除二次确认与即时撤销、矩阵导入预演补课时交互；
     - 新增端到端 Playwright 主路径：新学期上传图二格式任课表 Excel → 预览补填缺失周课时并确认新建清单 → 提交入库 → 在「任课表」页面验证班级人数/班主任/各科教师、测试点格删除+一键撤销 → 到「排课规则」页确认自动出现「班主任」与「八年级班主任」教师分组并能用于建规则 → 发起自动排课验证求解成功。

## Out of Scope

- 不修改 Timefold 自动排课求解器、草稿编辑器、课表发布与调代课核心逻辑。
- 不新建独立的「课程 × 年级」周课时配置表，不做修改课程默认值后批量回刷已有授课任务的功能。
- 不修改现有「手动导入」课表网格导入页或 AI 整本工作簿课表导入管线。
- 不修改既有「授课任务」列表主页面（保持单文件体积不超标；该页新建弹窗按课程带出默认节数留作后续独立小票）。
- 不做按老师学科强校验（允许同一教师跨学科任教，如同时教历史地理与道德与法治）。
- 不自动根据班主任字段创建或变更登录账号权限（`head_teacher` 角色账号仍由账号管理页维护）。
