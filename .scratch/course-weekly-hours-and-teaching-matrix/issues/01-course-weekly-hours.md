# 01: 课程管理支持可选「周课时数」

**What to build:** 让教务管理员在课程管理全链路中维护每门课程的可选「周课时数」（1–20 的整数或留空），作为新建授课任务和导入任课表时的默认每周节数：打开「课程管理」列表即可直接看到每门课的周课时数，在新建与编辑课程弹窗中可填写或清空该值，使用课程 Excel 导入、导出和模板下载也能完整往返这一列；后续修改课程的周课时数不会回溯改写已经存在的授课任务。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 数据库新增向后兼容的可空迁移（按全仓库及所有活跃分支/worktree 核对后从 V64 续号），存量课程保持为空，迁移重复号检查通过且 H2 与 PostgreSQL 语法兼容。
- [x] 课程读写接口支持可选的 `weeklyHours` 字段（1–20 整数或 `null`）；传入 `0`、`21` 或非整数时返回 400 校验错误，传入 `null` 可清空已有值。
- [x] 修改某门课程的周课时数后，该课程已存在的授课任务仍保持各自原有的每周节数不变，自动排课求解行为不受影响。
- [x] 课程 Excel 导入模板与导出表格均包含「周课时数」列；导入时合法正整数写入课程、留空保持未设置、非整数或越界报明确行号错误，缺少该列的旧版 Excel 模板仍可正常导入。
- [x] 「课程管理」页面列表新增「周课时数」列（未设置显示占位符），新建与编辑弹窗提供 1–20 可清空输入框并支持表单校验与保存回显。
- [x] 后端集成测试、前端单测、前端 lint/build 及单文件体积门禁全部通过。

## 交付记录

课程默认节数通过课程表单、JSON 接口和 Excel 往返。新任务可复制默认值，修改默认值时各班已有的授课任务继续使用自己已保存的每周节数。V64 在 H2 和 PostgreSQL 16 上验证，PostgreSQL 从 V63 升级保留了未设置节数的存量课程。
