# 每周不上课时段与三项算法修复

Status: in-progress
日期：2026-11-01（Asia/Shanghai）
基点：main `4c1cc191bcd286e99e42e4e4a8b7a3ebcd68ba1d`
阶段：用户已显式调用 implement-spec 授权实施；在 codex/weekly-no-class 集成分支按依赖推进，尚未完成整体评审与门禁，不部署生产。

## Problem Statement

教务希望指定全校或部分行政班每周某些课节不上课。当前只能限制教师或课程，不能直接要求某班某课节留空；手工移走一次也不能让后续自动排课记住留空要求。

本次亲自审查还复现了三个算法缺口：晚自习阈值把全天课程计入；调课搜索提前排除可由后续轮换消除的课程冲突；减少空堂的求解评分与校验评分不一致。基础求解器和独立校验器继续保留，修正这些有界行为。

## Solution

在既有约束设置中增加“每周不上课时段”。教务明确选择“全校”或“指定班级”，可选择多个行政班与多个星期/节次。启用时必须遵守，可以暂停或删除要求。

原有授课任务的每周节数保持不变，课必须排到其他可用课节。界面将主动留空与未排课区分；自动排课、手工微调、发布检查和发布后调课共同遵守。

修复三个算法问题，并保留可重复的反例回归测试。用户仍在熟悉的约束页、草稿编辑器和调代工作台完成工作。

## User Stories

1. 作为教务，我希望指定一个行政班每周三第3节不上课，让自动排课持续遵守。
2. 作为教务，我希望一次选择多个行政班和多个课节，减少重复设置。
3. 作为教务，我希望明确选择全校，让本学期所有行政班都遵守，后续新增班级也自动适用。
4. 作为教务，我希望暂停或删除要求，恢复该位置的可用性。
5. 作为教务，我希望所有课程周课时仍然保留，不把“留空”误当成减少教学任务。
6. 作为教务，我希望可用位置不足时看到具体班级、所需节数、可用位置和差额。
7. 作为教务，我希望在草稿班级视图看见“不上课”，并知道那里不能拖入课程。
8. 作为教务，我希望违反要求的导入草稿能显示冲突且不能发布，不静默删除导入内容。
9. 作为教务，我希望新增要求后能重新排课修复旧草稿的占位，但系统不承诺已经失效的初始课表必然可修好。
10. 作为教务，我希望主动留空不被“班级尽量不空堂”当成错误。
11. 作为教务，我希望手工移动、同班换位和发布后调课都不能把课程放入禁排位置。
12. 作为教务，我希望保存、刷新、跨设备恢复和模板往返保留要求，不把指定班级误变成全校。
13. 作为教务，我希望跨学期套用模板时显式确认班级映射。
14. 作为教务，我希望只有真正的晚自习课程计入晚自习上限。
15. 作为教务，我希望合法的三节课轮换能被找到，不因中间状态而误报无方案。
16. 作为教务，我希望可避免的空堂越多，算法越有动力改善。
17. 作为管理员，我希望变更有权限检查、配置版本核对和审计，失败时不写半份配置。

## Implementation Decisions

### 已确认范围与采用的推荐默认

- 用户已确认：第一版仅支持每周固定留空，全校或部分行政班，原课时转移到其他位置。
- 采用推荐默认：沿用既有约束页，不增加独立设置页面；在初中/高中模式均显示。
- 采用推荐默认：新增要求始终为硬约束，用户只能启停，不能改为“尽量”。后端拒绝弱化请求，不仅隐藏前端开关。
- 采用推荐默认：配置保存可以保留一个暂不可排的方案；保存/预览提示容量问题，真正提交排课时对明确不足作阻断。不给用户以“保存成功即保证可排”的错觉。
- 采用推荐默认：这批不增加“拖两节课立即交换”的新交互，不改变已有换课确认步骤。
- 用户澄清：全天节次连续编号。上午4节、下午3节、晚上2节就是第1–9节；“晚自习”仅为第8、9节所属时间段，不另立课表、不重复计算周课时。针对第8、9节可直接设置不上课或禁排要求。晚自习上限修复只调整该可选规则的计数范围，不改变普通课节的编号、排课和拖拽方式。

### 领域含义与范围

- “每周不上课时段”：在本学期某星期/节次，对全校或指定行政班明确禁止排课的要求。
- “主动留空”：已配置为不上课、没有授课任务应落在此处的位置。它不等同于有授课任务但没有安排位置的“未排课”。
- 范围属于学期。全校作用于本学期当前及以后新增行政班；指定班级只认已选的本学期班级身份。
- 多条要求取并集；重叠不重复计分，不提供“班级例外覆盖全校禁排”的放行能力。暂停一条要求不撤销其他仍生效的覆盖。
- 只选择真实存在的星期/节次。悬空课节、跨学期/已删除班级明确报错，不能退化成全校。

### 配置、兼容与模型

- 在既有条目/分组/版本/审计模型中增加一种行政班禁排类型，目录从25类扩展到26类；复用可选行政班引用及星期/节次字段，不建立第二套规则存储。
- 前端明确二选一“全校/指定班级”；指定班级模式必须非空。全校行不携带班级引用；多个指定班级展开为共享要求身份的班级/课节条目，保存后恢复原分组。
- 新类型默认不启用、没有条目时无效果，旧学期与旧模板行为保持原样。已有学期也要能看到新类型；若需数据迁移，实施时核对所有分支后分配版本。
- 新类型进入模板、配置版本冲突、未保存工作区、跨设备恢复和审计的既有通道。跨学期指定班级引用按既有显式映射规则处理，全校范围不冻结成源学期班级列表。
- 既有AI建议、评测、固定目录数量和旧数据兼容要审查。这批通过手工表单配置新规则，不宣称自然语言已支持第26类；AI遇到新需求必须明确暂不支持，不能改写为教师/课程禁排等不同含义，也不能丢失已有手工规则。
- 实施票04收录已确认领域词汇；涉及规则与基线的重要取舍按项目要求记录，不能把规划记录当成实现证明。

### 一条规则贯穿所有裁决入口

- 同一匹配语义用于自动排课、草稿校验、单节移动、批量/换课、发布、调课搜索、独立校验和只读CLI。
- 普通教师/教室冲突规则保持原义。行政班留空只限制所选班级，不限制同一老师给其他未选班级上课。
- warm start 里的旧课节若落入新禁排位置，需要释放/修复该占位，不能将旧课表视为当前规则下必然合格。未受影响课程仍可作为初始参考；不减少授课任务，不修改源草稿/基线。
- 新增规则不自动删除或改写已发布课表。存量占位如与新规则冲突，应提示“现有安排尚未调整”，不把有课的格子覆盖成空格。后续调课不得新放入禁排位置；历史既有冲突的容忍/修复遵循既有按变更前后判断的语义。
- 正式基线仍只读。本批不新增整学期重新发布或批量改写已发布课表的通道。

### 容量与可解释失败

- 以真实作息课节集合减去本班有效禁排位置，计算每班可用周位置；重复覆盖只减一次。
- 若本班授课任务周节数大于可用位置，排课前返回班级名称、周课时、可用位置、差额与“减少禁排或调整授课任务”的建议，不启动无意义搜索。
- 排队开始真正求解时再次以实际使用的配置核验，避免排队期间修改规则漏过检查。
- 这只是必要条件检查，不宣称能证明所有教师冲突和组合约束可满足。其他无解仍显示真实冲突/未排任务，禁止发布。
- 配置保存、草稿修复和容量查询不修改授课任务节数，不删除课节来伪造排完。

### 课表显示与空堂

- 草稿班级视图的有效空位置显示“不上课”，可查看范围/原因，并阻止拖入；教师/教室视角不把某班禁排误画成该教师/教室全局禁排。
- 整草稿仍展示真实未排任务数量。主动留空位置不计未排任务，实际没有落位的授课任务照常计数。
- 有课程占在禁排位置时保留课程卡片和冲突提示，不能隐藏课程或直接删除。
- 减少空堂只数本班当天最早与最晚已排课程之间、真实存在且允许上课而未排课的位置；不存在的作息位置与主动留空位置不扣分。其他连堂/教师连续授课含义保持不变，留空不会把相隔课程变成真正连堂。

### 三项算法修复

1. 晚自习上限只统计晚自习分段；上午/下午不计入。按班级例外、软硬设置、全局设置和求解/校验口径保持一致。
2. 同班置换环的搜索不能用中间课表上、最终会由本轮移出的同课程占位直接判无解。只保留对任意后续扩展都安全的提前排除；最终同时应用整组移动后，用既有独立校验确认。保留冻结、搜索窗口、人数/规模和预算边界，不为找出反例方案而无限放宽搜索。
3. 减少空堂的软扣分按有效空位数量乘权重，求解器与校验器一致；硬配置仍回答是否违反，不把硬违规数与软扣分强行混为一谈。本批不顺带改完所有教学偏好或阈值的评分梯度。

## Testing Decisions

- 先将三个已复现反例做成会失败的回归测试，再修行为。晚自习例子：上限0、只有一节上午课应0硬违规；空堂例子：空1格扣40、空3格扣120；调课例子见审查证据文档。
- 以同一输入比较求解评分与规则校验，硬约束比较违规有无，软约束比较约定扣分；明确区分空洞罚分、固定教室和偏好奖励等既有刻度差异。
- 新规则以已有约束保存HTTP接口到草稿/发布结果为主要业务测试边界；同时通过纯评分入口覆盖求解器，并通过纯方案入口覆盖调课独立校验，避免只测表单序列化。
- 覆盖单班、多班、全校、重叠、暂停、删除、非法引用、权限、版本冲突、模板跨学期映射及工作区恢复。
- 每周位置40、任务39、禁排2时提示差1；重叠禁排不重复扣容量。位置足够但教师冲突无解时不误报保证可排。
- 覆盖导入占位、warm start 需修复、空堂硬/软配置、未排任务不被抹掉、既有正式基线不变，以及发布后调课目标拦截。
- Playwright：设置→保存→刷新→排课/查看草稿→拖入拒绝→合法调整→发布检查；最终在隔离数据库操作，不制造生产测试课表。
- 每票定向测试；全部修复和票面记录完成后冻结源码，做两轴复审及一次完整门禁。真实PostgreSQL以部署门禁或同提交CI证据验证。
