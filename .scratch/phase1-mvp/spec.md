# 排课系统一期 MVP 规格

Status: ready-for-agent

---

## Problem Statement

国内中学的教务老师每学期开学都面临同一个痛点：把几百个"班级 × 课程 × 教师"的授课任务分配到一周的课节与教室里，同时满足一大堆约束（同一教师不能同时出现在两个教室、体育不能排在下午第一节、某教师周三下午有教研活动不能排课、连堂课要连着排……）。

目前主流做法是 Excel 手工排，费时费力且容易出错；学期中教师请假需要调代课时，靠微信群、电话、纸质通知，消息容易丢，期末统计代课费更是一笔糊涂账。

已有的开源方案要么是学生毕设级的遗传算法 demo（无法处理真实约束），要么是大学级别的重型系统（UniTime 之类，对中学是杀鸡用牛刀），**没有任何开源项目同时满足：中学场景适配 + 现代化技术栈 + 钉钉/飞书集成 + 可私有化部署 + AI 扩展预留**。

## Solution

构建一个面向国内单一中学的排课系统，采用"Java + Spring Boot + Timefold Solver"的技术底座，以私有化部署为主、钉钉集成为可选增强的形态交付。

教务老师的使用路径：
1. **初始化**：通过可选向导或 Excel 导入学校基础数据（年级/班级/教师/教室/课程/作息表）
2. **排课**：录入授课任务 → 勾选约束规则 → 提交自动排课（异步）→ 在草稿上拖拽微调（实时冲突校验）→ 发布课表
3. **调代**：教师请假时提交调代申请 → 教务审批（或直接生效，可配置）→ 相关人员收到钉钉/系统内通知 → 课表自动叠加显示代课教师
4. **追溯**：期末可查询任意教师的代课次数、任意班级的课表变更历史

系统在无钉钉、无 AI 的纯净环境下完整可用；启用钉钉后获得免登、组织同步、工作通知能力；AI 特性预留接口但默认全部关闭。

## User Stories

### 基础数据管理

1. 作为**教务管理员**，我希望能通过 Excel 批量导入教师名单，以便开学时不用逐条录入几十上百个教师。
2. 作为**教务管理员**，我希望能在系统里直接录入/编辑/删除教师，以便处理临时入职或 Excel 里遗漏的情况。
3. 作为**教务管理员**，我希望能通过 Excel 批量导入年级与班级，以便快速建立学校组织架构。
4. 作为**教务管理员**，我希望能录入教室信息（名称、容量、类型如"普通教室/实验室/操场"），以便排课时考虑场地约束。
5. 作为**教务管理员**，我希望能维护课程目录（课程名、所属学科、是否允许连堂等元数据），以便后续排课时引用。
6. 作为**教务管理员**，我希望能配置作息表（每天几节课、每节课时长、午休、晚自习），以便排课引擎知道"一周有多少个可用课节"。
7. 作为**教务管理员**，我希望教师/教室/课程是跨学期共享的全局数据，以便下学期不用重复录入。
8. 作为**教务管理员**，我希望班级/授课任务/课表严格按学期隔离，以便历史学期数据不会污染当前学期。
9. 作为**教务管理员**，我希望新学期能从上学期复制班级结构与授课任务作为起点，以便减少重复劳动。
10. 作为**教务管理员**，我希望首次登录时有初始化向导引导我按顺序录入数据，以便不用自己琢磨先后顺序。
11. 作为**教务管理员**，我希望能跳过初始化向导直接进主界面，以便第二个学期不用重走流程。

### 授课任务与约束

12. 作为**教务管理员**，我希望能录入授课任务（如"高一 1 班数学每周 5 节，张老师任教"），以便排课引擎知道要排什么。
13. 作为**教务管理员**，我希望能通过 Excel 批量导入授课任务，以便从现有的教务表格迁移数据。
14. 作为**教务管理员**，我希望能看到预置约束库（如"体育不在下午第一节""同一教师一天最多 4 节"），以便勾选启用而不是从零写规则。
15. 作为**教务管理员**，我希望能为每条约束调整权重（硬约束不可违反 / 软约束可设优先级），以便表达"必须满足"和"尽量满足"的差别。
16. 作为**教务管理员**，我希望能为特定教师配置禁排时段（如"张老师周三下午教研"），以便排课时避开。
17. 作为**教务管理员**，我希望能为特定课程配置规则（如"体育必须在室外场地"），以便满足学科特殊需求。
18. 作为**教务管理员**，我希望约束配置可以保存为模板，以便下学期直接复用。

### 自动排课

19. 作为**教务管理员**，我希望能一键提交排课任务，以便让算法帮我把所有授课任务分配到课节与教室。
20. 作为**教务管理员**，我希望排课是异步的，能看到求解进度（当前得分、已耗时、预估剩余），以便知道还要等多久。
21. 作为**教务管理员**，我希望同一时刻只能运行一个排课任务，以便避免资源争抢导致结果混乱。
22. 作为**教务管理员**，我希望能取消正在运行的排课任务，以便发现参数配错时及时止损。
23. 作为**教务管理员**，我希望排课失败时能看到清晰的失败原因（哪条约束导致无解），以便调整约束而不是盲目重试。
24. 作为**教务管理员**，我希望能保存多个排课草稿（"方案 A""方案 B"），以便并排比较后选最优的发布。

### 手工微调

25. 作为**教务管理员**，我希望能在课表草稿上拖拽某节课到另一个时段，以便调整算法生成结果中不满意的部分。
26. 作为**教务管理员**，我希望拖拽过程中系统能实时校验冲突，以便在放下鼠标前就知道这个位置能不能放。
27. 作为**教务管理员**，我希望冲突时能看到具体原因（"张老师此时在 3 班有数学课"），以便决定换一个位置还是换教师。
28. 作为**教务管理员**，我希望拖拽时可用时段以绿色高亮、冲突时段以红色高亮，以便直观判断。
29. 作为**教务管理员**，我希望能看到"未排课时抽屉"（尚未分配的授课任务列表），以便手工把它们拖进课表。
30. 作为**教务管理员**，我希望能看到当前草稿的冲突总数与得分，以便评估这版方案的质量。

### 课表发布与查看

31. 作为**教务管理员**，我希望能把满意的草稿"发布"为正式课表，以便让全校教师看到。
32. 作为**教务管理员**，我希望发布后的课表基线变为只读，以便后续所有变更都通过调代流程留下痕迹。
33. 作为**教务管理员**，我希望能按班级查看课表，以便打印张贴到教室。
34. 作为**教师**，我希望能查看自己的个人课表，以便知道每周什么时候有课。
35. 作为**班主任**，我希望能查看本班课表，以便掌握班级每天的课程安排。
36. 作为**教务管理员**，我希望能查看教室占用表，以便知道哪些教室在什么时段空闲。
37. 作为**教务管理员**，我希望能查看全校大课表（所有班级平铺），以便宏观把握排课结果。
38. 作为**教务管理员**，我希望能把课表导出为 Excel，以便发给不使用系统的老师。
39. 作为**教务管理员**，我希望能把课表导出为 PDF，以便打印张贴。

### 调代课

40. 作为**教师**，我希望能在系统中提交调代申请（哪天哪节课请假、原因），以便走正式流程而不是私下找人。
41. 作为**教师**，我希望提交调代申请时能指定期望的代课教师，以便让教务知道我的偏好。
42. 作为**教务管理员**，我希望能在待办列表里看到所有待审批的调代申请，以便集中处理。
43. 作为**教务管理员**，我希望能批准或驳回调代申请，以便控制课表变更。
44. 作为**教务管理员**，我希望能把审批模式切换为"直接生效"，以便适应管理风格较宽松的学校。
45. 作为**教师（代课人）**，我希望调代批准后能收到通知（钉钉或系统内），以便知道我要代哪节课。
46. 作为**教师（原任课）**，我希望调代批准后能收到通知，以便确认我的课已被妥善安排。
47. 作为**班主任**，我希望本班发生调代时能收到通知，以便掌握班级课表变化。
48. 作为**教务管理员**，我希望调代生效后课表上能显示代课教师并标注"（代）"，以便区分原始安排与变更。
49. 作为**教务管理员**，我希望能查看课表的"原始版本"（不含调代），以便对比学期初计划与实际执行。
50. 作为**教务管理员**，我希望能查看某教师本学期的所有调代记录，以便期末统计代课工作量。

### 用户与权限

51. 作为**教务管理员**，我希望能创建本地账号并分配角色，以便让教师、班主任登录系统。
52. 作为**教务管理员**，我希望能通过 Excel 批量创建教师账号，以便不用逐个手工注册。
53. 作为**系统**，我希望基于 RBAC 模型控制权限（教务管理员全权、教师查看个人课表与提交调代、班主任额外查看本班课表），以便不同角色看到不同功能。
54. 作为**教务管理员**，我希望能重置教师密码，以便教师忘记密码时恢复访问。

### 钉钉集成（可选启用）

55. 作为**教务管理员**，我希望能启用钉钉集成并配置企业凭证，以便让教师用钉钉账号登录。
56. 作为**教师**，我希望能在钉钉工作台里点击应用图标直接免登进入系统，以便不用记密码。
57. 作为**教务管理员**，我希望能从钉钉同步教职工名单，以便入离职自动同步减少手工维护。
58. 作为**教务管理员**，我希望关闭钉钉集成后系统依然完整可用，以便不被钉钉绑定。
59. 作为**系统**，我希望调代批准时能发送钉钉工作通知（支持 Markdown 与跳转链接），以便教师一键查看详情。
60. 作为**系统**，我希望在钉钉不可达时降级为系统内消息，以便通知功能不中断。

### 设置中心

61. 作为**教务管理员**，我希望能在设置中心切换调代审批模式（审批 / 直接生效），以便匹配学校管理风格。
62. 作为**教务管理员**，我希望能配置通知触达范围（是否包含年级组长、教务），以便控制消息轰炸。
63. 作为**教务管理员**，我希望能看到 AI 特性的开关（默认全部关闭），以便了解未来可以启用哪些能力。
64. 作为**教务管理员**，我希望切换审批模式时只影响新提交的申请，以便不打断已在流程中的调代。

### 部署与运维

65. 作为**学校信息科管理员**，我希望能用 docker-compose 一键部署整套系统，以便降低运维门槛。
66. 作为**学校信息科管理员**，我希望能用 Jar + 脚本的方式部署（不依赖 Docker），以便适应没有 Docker 的环境。
67. 作为**学校信息科管理员**，我希望系统能跑在学校内网（无公网），以便满足数据不出校的安全要求。
68. 作为**开发者**，我希望能在自己笔记本上完整跑起系统并调试钉钉集成，以便不需要为开发环境准备公网域名。

## Implementation Decisions

### 架构总览

**单体式后端 + 内嵌求解器内核**：
- Spring Boot 3 单体应用，Timefold Solver 以 Maven 依赖形式内嵌，同 JVM 进程调用
- 不引入微服务、不引入消息队列中间件（任务队列用数据库表 + Spring `@Async`）
- 前端 Vue 3 SPA 通过 REST API 与后端交互
- PostgreSQL 单库

### 模块划分

按业务边界划分 7 个顶层模块（每个对应一个 Spring 包）：

1. **foundation**：学校、学期、年级、班级、教师、教室、课程、作息表等基础数据
2. **scheduling**：授课任务、约束配置、排课任务、草稿课表
3. **timetable**：课表基线、课表发布、课表查询（合并视图）
4. **substitution**：调代申请、审批流、调代记录
5. **identity**：用户、角色、权限、认证
6. **integration**：钉钉/飞书/本地三种适配器的实现与路由
7. **notification**：通知模板、发送记录、降级策略

模块间通过 Spring Bean 依赖注入协作，不允许跨模块直接访问对方的数据表（通过 Service 接口调用）。

### 数据库 Schema 关键决策

- **学期隔离**：`admin_class` / `teaching_class` / `assignment` / `timetable_entry` / `substitution` 都带 `semester_id` 外键 + 索引
- **教学班预留**：`teaching_class` 与 `admin_class` 是两张独立表，`assignment` 关联到 `teaching_class`；一期 UI 强制一个 admin_class 对应一个 teaching_class（一对一映射），二期放开
- **基线 + 叠加**：`timetable_entry`（发布后只读）与 `substitution`（追加型事件）分离；查询时实时合并
- **RBAC**：`user` / `role` / `permission` 三表，`user_role` 与 `role_permission` 关联表
- **多来源身份**：`teacher` 表主键是本地 ID，`dingtalk_user_id` / `feishu_user_id` 是可空的外部映射字段
- **约束配置**：`constraint_config` 表存储"约束类型 + 参数 JSON + 权重 + 启用状态 + 学期"
- **排课任务**：`scheduling_job` 表存储任务状态、进度、结果草稿（JSON）、错误信息

### Timefold 集成

- **Planning Entity**：`Lesson`（对应一节待排的授课任务实例）
- **Planning Variable**：`timeslot`（课节）、`room`（教室）
- **约束实现**：用 Constraint Streams API 实现预置约束库的每一条，硬约束 / 软约束分离
- **增量校验**：手工微调时调用 `ScoreManager.updateScore()`，毫秒级返回冲突
- **完整求解**：提交到 `SolverManager.solve()` 异步执行，前端轮询 `jobId` 对应的进度
- **约束插件 SPI**：定义 `CustomConstraint` 接口，启动时用 `ServiceLoader` 扫描 `plugins/` 目录加载第三方约束

### 钉钉集成

- **应用形态**：钉钉企业内部应用 H5 微应用，前端代码与浏览器 Web 应用同一份
- **免登**：`dd.getAuthCode` 拿到 `authCode` → 后端调 `/v1.0/oauth/users/auth` 换 `userId` → 颁发系统 JWT
- **组织同步**：启动时全量拉取 + Stream 模式（WebSocket 长连接）接收增量事件
- **消息通知**：工作通知 API，支持 Markdown + ActionCard；失败时降级为系统内消息
- **可插拔**：`OrgDataProvider` / `AuthProvider` / `NotificationChannel` 三个接口 + 钉钉/本地两组实现，配置项 `integration.dingtalk.enabled` 控制启用

### 权限模型

- 基于 Spring Security + `@PreAuthorize("hasAuthority('xxx')")`
- 权限点命名规范：`<resource>:<action>`（如 `timetable:publish`、`substitution:approve`）
- 一期预置 3 角色：`admin`（教务管理员）、`teacher`（教师）、`head_teacher`（班主任）
- 数据权限：教师只能看自己的课表与调代记录；班主任额外能看本班课表

### 排课引擎调用模式

- **完整求解**：POST `/api/scheduling-jobs` → 返回 `jobId` → 前端每秒轮询 GET `/api/scheduling-jobs/{id}` → 状态变为 `completed` 时展示草稿
- **增量校验**：POST `/api/timetable-drafts/{id}/validate-move`（body 包含要移动的 lesson 与目标 timeslot/room）→ 返回冲突列表
- **并发控制**：同一学期同一时刻只允许一个 `running` 状态的排课任务

### 课表合并视图

- Repository 层封装 `TimetableViewRepository`，对外暴露 `getClassTimetable(classId, dateRange)` 等方法
- 内部实现：查 `timetable_entry` 基线 + 查 dateRange 内生效的 `substitution` 记录 + 内存合并
- 支持 `view=baseline` 参数切换"原始 / 最新"视图

### 调代状态机

```
SUBMITTED → PENDING_APPROVAL → APPROVED / REJECTED → EFFECTIVE
                              ↘ (直接生效模式) → EFFECTIVE
```

- 状态流转由配置项 `substitution.approval_mode` 控制
- 已在流程中的申请按提交时的模式走完，不受后续配置切换影响
- 所有状态变更记录到 `substitution_history` 表

### 通知模板与降级

- 通知模板用 Thymeleaf 字符串模板，变量包括课程名、时间、原/新教师、教室、原因
- `NotificationChannel` 接口定义 `send(recipients, template, variables)` 方法
- `CompositeNotificationChannel` 实现降级：先发钉钉 → 失败则发系统内消息 → 记录发送结果
- 所有通知记录到 `notification_log` 表

### Excel 导入导出

- 导入：Apache POI 解析，每类实体（教师/班级/教室/授课任务）有独立模板
- 导出：Excel 用 POI，PDF 用 OpenPDF 渲染 HTML 模板
- 导入前做 dry-run 校验（返回错误清单），用户确认后才真正入库
- 所有导入操作记录审计日志（谁、何时、导入了什么、成功/失败行数）

### 性能优化

- 课表合并视图：`substitution (entry_id, effective_date)` 联合索引
- 学期数据查询：所有学期隔离实体的 `semester_id` 字段都建索引
- 全校总表：后端一次性返回所有班级数据，前端虚拟滚动渲染（不分页，因为总量 < 1000 行）
- 排课任务：`@Async` 线程池大小限制为 2（避免并发求解抢占资源）

### 配置项汇总

所有可配置项集中在 `application.yml`，前缀 `paiban.*`：

- `paiban.integration.dingtalk.enabled`：钉钉集成开关
- `paiban.integration.dingtalk.app-key` / `app-secret`：钉钉凭证
- `paiban.substitution.approval-mode`：调代审批模式（`approval` / `direct`）
- `paiban.notification.scope`：通知范围（`minimal` / `with-grade-leader` / `with-admin`）
- `paiban.ai.features.*`：AI 特性开关（一期占位，全部默认 false）
- `paiban.scheduling.max-concurrent-jobs`：排课任务并发数（默认 1）

## Testing Decisions

### 什么是好测试

- **只测外部行为，不测内部实现**：测试通过公开接口（REST API / Java 接口）调用系统，断言外部可见的结果；不 mock 内部 Service、不断言私有方法调用
- **测试应该读起来像文档**：测试名用完整句子描述业务场景（"调代批准后，课表查询应返回代课教师"）
- **测试数据最小化**：每个测试只构造它关心的数据，用 Builder/Fixture 而不是共享 SQL 脚本

### 五条测试接缝

1. **REST API 接缝（主力）**：用 REST Assured 在 Controller 层测业务行为。覆盖 80% 的测试场景。数据库用 Testcontainers 起 PostgreSQL。
2. **排课引擎接缝**：用 JUnit 在 `SchedulingEngine` 接口层测约束正确性。每条预置约束至少一个测试（启用约束 → 构造输入 → 求解 → 断言结果满足约束）。
3. **IM 适配层接缝**：单元测试用 fake 实现验证业务逻辑（调代批准 → 断言 `NotificationChannel.send` 被调用且参数正确）；少量集成测试用真实钉钉沙箱租户手动跑（不进 CI）。
4. **E2E UI 接缝**：用 Playwright 只测 ADR-0016 的三个验收场景。E2E 测试数量严格控制在 10 个以内。
5. **Excel 导入导出接缝**：准备一组真实 Excel 样本（正确、缺列、多余列、合并单元格、中文表头、超长字段、公式），断言导入结果与错误提示。

### 先验

- Timefold 官方 `school-timetabling` quickstart 的测试方式是先验（引擎接口层测约束）
- Spring Boot 官方测试指南的 REST Assured 模式是先验（Controller 层测业务）

### 测试基础设施

- 所有测试用 Testcontainers 起真实 PostgreSQL，不用 H2
- E2E 测试用独立的 `application-e2e.yml` 配置，禁用钉钉集成（验证 ADR-0005 的可插拔承诺）
- CI 上必须能通过：`./mvnw verify`（单元 + 集成）与 `npm run test:e2e`（E2E）

## Out of Scope

以下能力**明确不在一期交付范围**，二期或更后处理：

- 学生/家长端
- 升学向导（毕业班归档、新生入学、留级、转学）
- 多学期横向对比分析报表
- 代课费 / 教师课时统计报表（一期只留数据，二期做报表）
- 教室预约 / 借用
- 考试排考
- 移动端专属 UI（一期用响应式 H5 即可）
- AI 功能本体（一期只预留接口与开关）
- 自定义约束 DSL（一期只预留 SPI）
- 飞书集成（一期只预留适配层接口）
- 多租户 SaaS
- 新高考走班（一期 UI 与算法只做行政班，但模型预留）
