# 01: 工具循环骨架

**What to build:** 上传工作簿后，模型不再靠一次调用猜整张表，而是用一组只读工具自己浏览文件：列出工作表、按页读取、查询系统里已有的行政班/课程/教师/教室，最后宣告每张表的类别与列映射。预览页展示这份结构判断与完整的调用轨迹。本票不产出数据行。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 上传多工作表 Excel 后，会话记录里出现至少一次「列出工作表」的调用与结果
- [x] 模型可按表名与区间请求读取，后端分页返回原始网格，单页长度有上限
- [x] 模型可查询系统已有的行政班、课程、教师、教室，返回匹配项与总数
- [x] 「宣告结构」的回复包含每张表的类别（课表/教师名单/课程表/说明/未知）与列映射
- [x] 6 轮内未宣告结构时，仍返回预览并带「结构未确认，请人工核对」标记，不整次作废
- [x] 预览页显示每张表的类别与列映射，以及每轮工具调用的名称、参数与结果摘要
- [x] 工具轨迹持久化，刷新或重进页面仍可看到
- [x] 图片与纯文本通道的行为保持不变
- [x] 未配置 AI 时仍给出原有的「请先配置 AI 供应商」提示

**实现说明：** `WorkbookPlanner` 用纯 JSON 请求实现只读工具循环（`list_sheets` / `read_sheet` / `lookup` / `finish`），最多 6 轮；未收敛时由 `WorkbookPlan.fallback` 按表头与表名给出确定性判断并标记「结构未确认」。每轮（工具名、参数、结果摘要）写入 `ai_import_log.tool_trace_json`（迁移 V23），刷新后仍可回放。`lookup` 走 `ImportMappingService.lookupNames`，只读不写。轨迹每轮记录工具名、参数、模型原始回复与工具结果摘要；`read_sheet` 返回的是规整后的网格（首行是列名，已拆分的派生列在末尾），这样模型映射的列名与它读到的列一一对应。文本与图片通道、未配置 AI 的提示均未改动。
