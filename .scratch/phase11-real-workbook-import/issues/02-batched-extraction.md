# 02: 按确认结构分批取值

**What to build:** 结构宣告之后，按已确认的列映射分批把数据抄出来，而不是每批重新猜一遍。行上限放宽到 5000，每批 40 行；复合单元格按映射拆成多个字段；没有表头的工作表不再丢掉首行数据。

**Blocked by:** 01

**Status:** done-with-followup

- [x] 数据按每批 40 行切分并逐批取值，批量大小可配置
- [x] 工作表行数上限由 500 提到 5000，超出时给出可读错误（含实际行数与上限）
- [x] `八（1）|星期一|1` 这类复合单元格按映射拆成行政班、星期、节次三个字段
- [x] 无表头工作表的首行数据不被当作表头吞掉
- [x] 560 行的单表数据在预览中得到 560 条课节行，六个字段全部有值（含 14 条课程与教师为空的空课位）
- [ ] 进度按批更新，停止与重试失败批次沿用现有语义（整本工作簿取值在请求内同步完成；旧的单目标批量路径保留进度与停止/重试）
- [x] 批次之间使用同一份列映射，不出现同一文件前后两批判定不一致

**实现说明：** `WorkbookExtractor` 在 `finish` 之后按已确认的列映射抄值，默认 40 行一批（`paiban.ai.import.batch-size` / `PAIBAN_AI_IMPORT_BATCH_SIZE` 可配置）。行上限由 500 提到 5000（`ExcelTableReader.MAX_GRID_ROWS`、`AiImportService`/`AiImportParser` 的 5000 行），错误里带实际行数与上限。复合列由 `CompositeColumns` 确定性拆成派生列；无表头由 `HeaderDetection` 判定为 0 行表头，首行数据保留。批量取值在本次请求内同步完成，批次不进入后台队列，因此进度条与「停止/重试失败批次」仍只作用于旧的单目标批量路径（见下方未勾选项）。
