# 10: 约束条目支持多条（+/-），并重排约束页布局

**What to build:** 约束配置目前「一个学期 + 一个类型 + 一份参数」（`uk_constraint_semester_type`），求解器也只读一个 `teacherId`。因此凡是带参数的约束，**一次只能设一条**：教师禁排时段只能设一位老师、课程指定教室类型只能设一门课，设第二条会覆盖第一条。真实学校几乎都是多条（多位老师各自禁排、多门课指定教室、多个阈值）。

同时约束页把 20 多个约束和它们的表单铺在一起，信息密度过高。已有的分组折叠（冲突/资源/教学/偏好）要保留并加强：卡片内按"条目"列出，用 **+ / −** 增删条数，默认只显示摘要。

**Blocked by:** None（2026-10-25 用户提出，扩展自原"只支持一个老师"）

**Status:** needs-triage

## 数据与求解

- [ ] 去掉 `uk_constraint_semester_type`，同一类型允许 N 行；迁移保留既有单条数据（旧配置升级后行为不变）
- [ ] `ConstraintSettings` 由 type→Rule 改为 type→List<Rule>；`PaibanConstraintProvider` 所有按人/按课程的分支遍历全部条目
- [ ] 约束分三类处理：
  - **目标型**（每条指定对象 + 条件）：教师禁排时段、教师偏好时段、教师不排第一节、教师固定无课日、课程指定教室类型、课程不排晚自习、连堂课、主科排上午 → 多条相加
  - **阈值型**（数值）：教师一天最多 N 节、班级一天最多 N 节、课程一天最多 N 节、晚自习最多 N 节、教师连续上课上限 → 每条增加"作用对象"（全局 / 某教师 / 某课程 / 某班级），精确对象优先于全局；未指定＝全局默认
  - **开关型**（无参数）：教师/班级/教室不冲突、教室容量足够、班级尽量不空堂 → 只有开关与权重，不出现 +/−
- [ ] 服务层按条增删改（现在整表替换），校验仍走 `ConstraintType` 声明的参数 schema
- [ ] 约束模板（constraint_template）能保存/套用多条目

## 界面（信息密度）

- [ ] 保留分组折叠，组标题显示「已启用 x / 共 y 条」；默认全部收起
- [ ] 每个约束一张卡片，卡片头＝名称 + 一句话说明 + 启用开关（硬约束不显示权重）
- [ ] 卡片体内是**条目列表**：每条一行摘要（对象 · 条件，例如「金林墨 · 周三第 7 节」），右侧「编辑 / 删除」
- [ ] 列表底部 **「+ 添加一条」**；行内可**「−」删除**；条目为空时显示默认说明
- [ ] 页面顶部：生效条数、硬约束条数、被覆盖的旧参数提示；「保存配置」按钮吸顶
- [ ] 约束页单元测试：增删条目、组内计数、空状态；Playwright 截图存档
