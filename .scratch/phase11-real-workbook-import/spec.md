# 排课系统十一期规格：真实教务工作簿直接导入

Status: ready-for-agent

票据：`issues/01-tool-loop-and-sheets.md` 起（依赖关系见各票 Blocked by）。

---

## Problem Statement

教务老师手里拿到的不是我们的导入模板，而是从别的系统导出的**查询型工作簿**：一个文件里同时有「数据源」「班级课表」「教师课表」「每日考勤表」「使用说明」五张表；数据源 560 行、没有表头、A 列是 `八（1）|星期一|1` 这样的复合键，另有 14 个「星期五第 7 节」的空课位。

现有 AI 导入对这类文件的假设全部不成立：

- 读取器遇到多个有数据的工作表直接报错；
- 单表上限 500 行，560 行直接拒收；
- 表头固定占前 1–2 行，无表头文件会被静默吞掉前两行数据；
- 复合键所在的列无法拆成班级/星期/节次三个字段；
- 导入目标必须在上传前手选，模型只能事后建议；
- 班级/课程/教师名称必须已在系统中，否则整批阻止。

结果是每来一份真实表格都要人工拆表、加表头、删行、分批——用户的判断很直接：「如果都要按固定格式来，那我为什么不用脚本，非要上 AI？」

## Solution

把「读懂这张表」真正交给模型，把「写入契约」保持确定：

1. **上传不再选目标**。模型通过一组只读工具自己浏览工作簿：有哪些工作表、每张多大、哪张是课表、哪张是教师名单、哪张只是说明。
2. **多表全读**。所有有数据的工作表都参与识别；纯说明类工作表按保守规则跳过；其它表按课节槽位合并去重。
3. **一次确认，多类入库**。预览页列出「工作表 / 数据类别 / 识别行数 / 去重后新增」；确认后按依赖顺序写入：教师 → 课程 → 班级 → 课表，产物仍是 `DRAFT` 草稿。
4. **缺什么就空什么**。教师只要求姓名；工号、手机、邮箱、学科有就填、没有就留空。
5. **阻塞点给出可执行入口**。缺学期给跳转；缺作息给「一键生成默认作息（上午 4 + 下午 4，周一至周五）」。
6. **大表不再被硬拦**。行上限提到 5000，分批 40 行一次调用，560 行的文件约 14 次调用。

## User Stories

1. 作为教务管理员，我想直接把手上那份 Excel 原样上传，这样我不必先拆表、改表头、删行。
2. 作为教务管理员，我想让系统自己判断哪张工作表是课表、哪张是说明，这样我不用理解「工作表」这个概念。
3. 作为教务管理员，我想在上传前不选「导入目标」，因为我自己也分不清这份文件算教师数据还是课表数据。
4. 作为教务管理员，我想一次上传就同时导入教师、课程、班级和课表，这样不用把同一份文件传四遍。
5. 作为教务管理员，我想看到每张工作表最终贡献了多少行，这样我能立刻发现某张表被跳过或全是重复。
6. 作为教务管理员，我想看到系统对每张表的结构判断（这是什么表、每列是什么），这样判断错了我在写库前就能发现。
7. 作为教务管理员，我想在写库前必须确认一次，因为写进数据库不可逆。
8. 作为教务管理员，我想让「星期五第 7 节」这类没课的槽位被跳过并告知数量，而不是让整份表因为 14 行空值全部失败。
9. 作为教务管理员，我想让同一节课在「数据源」和「班级课表」里重复出现时只保留一份，并且优先保留课程与教师都齐全的那份。
10. 作为教务管理员，我想让没有表头的表格也能导入，而不是丢掉前两行数据。
11. 作为教务管理员，我想让 `八（1）|星期一|1` 这种挤在一列的三个字段被自动拆开，而不是让我先在 Excel 里分列。
12. 作为教务管理员，我想让名字已经在系统里的教师/课程/班级只补齐空字段，不覆盖我改过的值。
13. 作为教务管理员，我想让导入过程中新建的教师、课程、班级与课表分成不同步骤，这样某一类失败时已经建好的不会白建。
14. 作为教务管理员，我想在预览里一键全选所有未匹配项并批量新建，而不是逐个点 48 位教师、16 门课程、14 个班级。
15. 作为教务管理员，我想在缺学期时被明确告知并一键跳到学期管理，而不是只看到「导入失败」。
16. 作为教务管理员，我想在缺作息时一键生成默认作息，而不是先去另一个页面手工配置 40 个课节。
17. 作为教务管理员，我想看到模型在浏览文件时调用了哪些工具、看到了什么，以便排查它为什么判断错了。
18. 作为教务管理员，我想在模型反复翻表超过上限时仍能拿到一份带「结构未确认」标记的预览，而不是整次导入作废。
19. 作为教务管理员，我想让 60 个班、约 2400 个槽位的大学校文件也能导入，而不是被 500 行拦住。
20. 作为系统管理员，我想在 AI 不可用时仍能用原有的模板导入完成基础数据录入，这样关闭 AI 不影响系统可用。
21. 作为开发人员，我想让这条管道的每一轮工具调用和模型原始输出都能回放，这样线上的错误可以复现。
22. 作为开发人员，我想让非课表导入（教师模板导入等）继续走原来的读取逻辑，这样这次改动不会波及其他三个调用方。

## Implementation Decisions

### 工具循环（替代「每次重新猜结构」）

- 用**纯 JSON 请求循环**实现，不改动四个供应商适配器（现有 OpenAI 兼容策略会显式拒绝 `tool_calls`）。模型每轮返回一个动作对象，后端执行后把结果作为下一轮的用户消息追加。
- 只读工具共四个：`list_sheets`（表名、行×列、前几行预览）、`read_sheet(sheet, offset, limit)`（按需翻页，突破单次 500 行）、`lookup(type, names[])`（查已有行政班/课程/教师/教室）、`finish(structure)`（宣告每张表的类别与列映射）。
- 最多 6 轮；到顶仍无 `finish` 时，带着已获得的信息生成预览，并标记「结构未确认，请人工核对」。
- 每轮请求、回复、工具结果都写入导入会话，供预览展示与事后排查。
- `finish` 之后才进入批量取值；批量阶段不再重新推断结构，只按已确认的映射抄值。

### 读取与规整

- 新增「读取所有非空工作表」的能力；现有只读第一张表的读取方法保持原语义，`FoundationImportService`、`UserImportService`、`AssignmentImportService` 三个调用方不受影响。
- 行上限由 500 提到 5000，列上限保持 60。
- 说明类工作表按保守规则确定性跳过：非空单元格少于 5 个**或**少于 2 列。被跳过的表在预览里显示原因。
- 表头按字段词表识别（班级/行政班、星期/周、节次/课节、课程/科目、教师/老师、教室/场地），识别不到即视为无表头（0 行表头），修掉无表头文件丢掉前两行的问题。标题行（非空单元格 ≤2）仍然跳过。
- 复合列拆分是确定性纯函数：同列 ≥80% 的非空值含同一分隔符（`|`、`｜`、`·`、`/`、`—`）且切分后含星期或节次特征时，拆成多个派生列；不满足条件的列原样保留。提示词同时告知模型「已拆分的派生列」与「可能未拆分的复合单元格」。

### 合并与写入

- 槽位键为「行政班 + 星期 + 节次」。同一槽位多行时，课程与教师齐全者优先；残缺行丢弃并计数，在预览与结果中展示「丢弃 N 行（信息不全）」。
- 空课位（班级/星期/节次齐全，课程与教师皆空）跳过并计入警告；其余任一行错误仍整批阻止，维持「先全量校验再写入」的既有约束。
- 自动入库类别：教师、课程、行政班、课表。年级由班级名推断，缺失时按推断结果创建。
- 学期、作息仍由人工建立；导入页对「缺学期」「缺课节」两类阻塞给出可执行入口，作息复用已有的默认作息生成能力。
- 同名实体（教师按姓名、课程按名称、行政班按名称）按「补齐空字段、不覆盖已有值」处理，与钉钉同步的既有语义一致。
- 写库按类别分事务执行：成功类别保留，失败类别单独报告并可重试；不因为一类失败回滚全部。

### 对外契约

- 上传接口不再依赖「目标」参数决定解析路径；响应中新增工作簿与类别的结构化摘要（每张表的名称、判定类别、识别行数、去重后新增行数、跳过原因）。
- 预览响应新增警告列表（空课位、丢弃行、结构未确认等）。
- 会话记录新增工具轨迹字段，用于回放与审计（需要一次数据库迁移，纯新增可空列）。

### 兼容

- 历史导入会话按原字段读取展示，不做数据迁移。
- 原有模板导入、教师/课程/班级的常规 Excel 导入全部保留。

## Testing Decisions

**好的测试只断言外部行为**：从 REST 契约出发，断言「上传后预览里有哪些行、确认后库里有哪些记录」，不断言内部方法调用顺序与私有结构。

**测试缝（复用现有两个高缝，不新开）**

1. 后端 `POST/GET /api/ai/import/*` 契约，配脚本化的假 AI 网关：覆盖工具循环、多表读取、分批、合并去重、空课位、多类入库。
2. 前端 Playwright + 本地 AI stub：覆盖上传、类别清单展示、确认、草稿生成。
3. 三处确定性纯函数（复合列拆分、表头识别、槽位合并）配单元测试——它们没有 IO，用表驱动用例最快。

**关键用例**

- 多工作表工作簿：说明表被跳过、课表与透视表都识别、去重后行数正确。
- 无表头：首行数据不被吞。
- 复合列：`八（1）|星期一|1` 被拆成三个字段；普通列不被误拆。
- 空课位：14 行空槽被跳过并产生警告，其余 546 行入库。
- 同槽位冲突：完整行胜出，残缺行计入丢弃数。
- 工具循环：`finish` 后不再调用工具；6 轮未收敛时仍产出带标记的预览。
- 多类入库：教师先于课表创建；课表失败时教师保留。
- 行上限：5000 行文件可通过，超过则给出可读错误。

**先例**：`AiImportIntegrationTest`（REST + FakeAiGateway）、`TimetableImportServiceTest`（槽位规则）、`frontend/e2e/ai-import.spec.ts`（Playwright + AI stub）。

## Out of Scope

- 教室的自动创建（真实数据里通常没有教室列）。
- 学期与作息的自动创建（作息提供一键生成的显式入口）。
- 原生 function calling 与多供应商工具协议适配。
- 把客户真实姓名写进仓库的测试资源；真实文件只在服务器上做人工验收。
- 调代功能本身的修改（本次只做部署后的冒烟验收）。
- 让模型直接写库：写入仍由确定性代码完成。
