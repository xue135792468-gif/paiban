# 真实工作簿导入后六项修复：补充规格

Status: ready-for-agent
准备日期：2026-10-25。用户已确认本轮产品决定；由后续 agent 实现。
原票仍为唯一工单，不重新编号或按前后端拆票。执行顺序：11 → 12 → 13 → 07 → 08 → 09。

## Problem Statement

导入成功不等于课表可继续使用：保存作息会损坏草稿引用，自动建班人数与手工编辑不一致，绿色校验无法预测发布结果，缺教室和缺节次没有可执行出口，可疑教师名会进入主数据。六项修复应补齐这条业务链，不重写导入状态机。

## Solution

保存已有数据时保护引用；统一人数与发布前检查；通过两项显式确认动作补齐教室和课节；将可疑姓名以非阻断提示交给教务处理。

## User Stories

1. 作为教务管理员，我想保存课节时间与标签后仍能打开、校验原草稿，避免重新导入。
2. 我想在删除被草稿使用的节次前看到原因，保留已有草稿。
3. 我想让导入建班的缺省人数与手工建班一致，随后可以正常编辑。
4. 我想看见实际阻止发布的缺失项，避免先看到通过再发布失败。
5. 我想用一次显式动作给缺教室课节按行政班分配固定普通教室。
6. 我想保留已经填写的教室，并对专用教室要求或冲突获得具体说明。
7. 我想在导入预览中看到缺少的星期和节次，提交前就能处理。
8. 我想确认拟新增的起止时间；推算不可靠时由我人工处理。
9. 我想看到疑似占位教师名，但仍能自行决定是否导入。
10. 我想在教师管理改名后原课节引用仍然有效。
11. 我想让重复点击和刷新不重复创建教室或作息。
12. 我想在操作失败时看到明确结果，已有数据保持完整。

## Implementation Decisions

### 11：作息引用完整性

- 同一学期相同“星期＋节次”的课节在保存时保留身份，允许修改标签、起止时间与时段；新增槽位创建新记录。
- 删除仍有草稿引用的课节时整次拒绝并说明原因，不静默清空引用。删除未使用槽位允许成功。
- 已发布学期保持拒绝修改的既有语义，包括生成默认作息入口。
- 加数据库外键或等效强制一致性保护；优先外键。迁移前先查历史悬空引用并出具修复计划，不能用固定 id 偏移猜测关联。
- 审查全部课节引用，包括草稿、发布条目、调代申请/生效记录、目标节次和置换方案。保留身份和已发布禁改共同保护历史。
- 学期删除、复制、新建、默认作息、并发保存/导入/发布都要检查是否会绕过保护。保持原有效行为，不顺手拓展新的删除策略。
- 安全迁移无法成立时中止部署并说明数据问题，不擅自删除草稿。

### 12：导入班级人数

- 缺少人数时使用既有默认 45；明确给出的人数必须为正整数，与手工接口一致。
- 覆盖整本自动建班与映射新建班级两条业务入口；不改已有正整数人数，不把真实人数全部重置为 45。
- 历史 0 人班级如存在，列入可审查的数据修正方案，区分“缺省”与用户明确填写。线上执行前备份；本规格不授权准备阶段改库。
- 需要导入人数的后续草稿/容量检查读取正确人数；仅用于只读网格布局的临时值不构成数据修复对象。

### 13：整草稿检查与发布一致

- 整草稿检查包含未排课、课节引用失效、缺教室和现有规则检查。缺教室草稿不得再以绿色“通过”展示。
- 整草稿检查与发布共用前置判定；可增加发布状态/原因字段，但兼容现有响应消费者。
- 区分“结构或资源不完整”与“排课冲突”，页面给出对应动作。单节移动、批量移动的局部验证不能被其他尚未补齐的课节全部阻断。
- 保留空草稿、已发布草稿、学期已有基线等现有发布守卫；不把“无冲突”文案误当作无条件保证发布。
- 发布依然拒绝残缺数据；不通过放宽教室要求来让测试变绿。

### 07：显式按行政班补固定普通教室

- 草稿有缺失教室时显示数量与入口；确认前说明会为哪些行政班建立固定普通教室、容量依据、涉及课节数。
- 用户已选择“显式确认后创建”，不是在导入时自动创建。新教室容量至少容纳对应班级，不能按 0 人推算。
- 只填空 room；已人工分配的值保持不变。同一行政班本次补齐的课节使用同一固定教室。
- 重复调用可复用本动作已为该班建立的安全关联，不重复建室；同名但无法确认关联或容量/类型不合适的旧教室不能被自动冒用或扩容。
- 先对整组拟变更做校验，再在一个事务内创建教室并分配。若任何拟变更不安全，整次不写，列出需人工处理项。
- 专用教室要求、同槽教室冲突等不靠 force 绕过；已有其他无关冲突可以继续显示，不伪称补教室已解决所有冲突。
- 写入复用服务层语义，不能循环调用 force 修改或直接改库。创建主数据与编辑课表两类权限都要校验；学期已有发布基线时拒绝本动作，即使目标是同学期另一份未发布草稿。
- 定向范围说明见 ADR-0027：导入解析仍不建室，草稿确认动作可建室。

### 08：预览缺节差集并安全追加

- 从已保存预览提取可识别的“星期＋节次”，与选定学期比较，去重列出差集。不可识别值保持原行错误，不猜数字。
- 对可以可靠推算的项展示标签、时段、起止时间。沿用相邻已有课节的时长/间隔；内部缺口必须能放进上下锚点，不能碰撞已有作息。
- 无当天参照、间隔为负、已有时间矛盾、跨午休/时段无可靠依据、跨午夜等情况标记“需人工”，提供作息管理入口。
- 用户确认的是可推算的新增项；只追加，既有课节 id、时间、标签和草稿引用保持不变。若只补了可靠子集，其余差集仍可见，不显示全部完成。
- 重复确认不重复建，提交时再次核对学期、已有课节与发布状态，拒绝过期的时间方案。
- 补后重新读取会话/差集，不重新解析工作簿、不增加模型调用。缺整个学期或整个作息仍沿用既有明确入口。
- 已发布学期只显示不可补的原因，直接调用写接口仍拒绝。

### 09：可疑教师名提示

- 使用确定性规则：与课程名称精确相同、规范化后互为子串、命中明确岗位/占位词时提示；不引入模糊相似度或 AI 判姓名。
- 固定词至少覆盖老师、教师、待定、暂无、机房、自习，并包含问题样例“信息技术”。“信息技术/信息科技”近似本身不是子串规则，不能写一个实际上不命中的验收。
- 预览行/教师清单标黄，结果页列去重清单与原因；同一教师的多个课节不刷重复警告。
- 警告使用独立非阻断通道，不把 row=0 的警告当作缺学期等页面 blocker。有警告仍可确认、入库并生成草稿。
- 整本工作簿预览现为只读，首版采用原票允许的“入库后教师页改名”，提供清晰入口；课节继续按 id 关联。
- 入库前编辑整本预览属于单独需求，本票不新增编辑、分类重算、确认覆盖 AI 原始输出的流程。

## Testing Decisions

采用原十一期已确认的高层边界：公开 REST＋受控假 AI 网关、Playwright＋本地 stub；只有无 IO 的差集/时间推算/提示规则使用纯函数测试。断言用户可见行为，不验证私有方法调用顺序。外部模型不进入本地回归。

| 票 | 必须先红的行为 | 通过标准 |
|---|---|---|
| 11 | 导入草稿后保存作息导致引用变化/失效 | 保存后草稿课节仍存在且校验可用；有效非空请求删除被占用槽位被拒绝且全量回滚；未使用槽位可删；发布后不可改 |
| 12 | 自动/映射建班缺人数为 0，编辑失败 | 两入口缺省 45、正数不覆盖、非法值拒绝；导入后改名保存成功 |
| 13 | 无教室草稿整表通过但发布失败 | 无教室整表不通过并明确原因；补齐后通过且可发布；局部移动不被无关缺失项锁死 |
| 07 | 缺教室草稿没有批量出口 | 显式确认补齐两班并成功发布；原值保留；重复请求无新增；容量/专用类型/冲突/无权限/已发布反例不产生部分写入 |
| 08 | 文件缺 3 个槽位提交才失败 | 预览列出 3 项，确认可靠项后阻塞相应消失；原 id 不变，无新增模型调用；不可推算/已发布/过期方案仍受保护 |
| 09 | 占位名无提示 | 同名/包含/固定词命中，正常合成姓名不命中；警告仍可入库；结果可追溯、改名后草稿关联不变 |

数据库约束需在 H2 及真实 PostgreSQL 迁移/写入边界验证，正常空 period 的未排课草稿仍允许保存。测试截图只使用合成数据，不写入真实教师姓名。

## Out of Scope
