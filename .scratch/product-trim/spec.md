# 排课系统收敛规格

Status: ready-for-agent
Feature: product-trim
Date: 2026-11-03

## Problem Statement

系统已经覆盖 11 个开发期、23 个规格目录、553 条需求、26 个页面。对当前唯一的真实场景（一所初中、两名教务人员、课表主要靠导入现成工作簿）来说，功能面太宽：同一件事有多套入口（导入 4 套、换课/调代 4 套），很多要素用不上（教室、晚自习、审批链、飞书、初中/高中双模式），而真正要用的地方又不够顺（教师视图不能换课、导入格式一变就要靠 AI、约束要记 26 个技术名词、很多列表只能增不能删）。

用户要的不是重写，而是把系统收敛成一套轻量、模块化、可复用的工具：保留主链，删掉不用的要素，合并重复实现，让日常操作不被系统过度限制。

## Solution

把 26 个页面收敛成 7 个一级页面：

1. **总览**：到哪一步、还差什么、下一步点哪。
2. **课表工作台**：草稿 → 编辑 → 发布 → 撤回；班级/教师/全校三视图。
3. **调代课**：按日期对已发布课表做代课/调课。
4. **排课规则**：用“对谁 / 哪些课 / 什么时候 / 要求”的积木拼规则。
5. **数据管理**：学期作息、年级/班级/教师/课程、授课任务、导入、导入配方。
6. **AI 助手**：供应商、模型、任务绑定、AI 记录。
7. **设置**：学校、账号、钉钉、导出、备份。

关键取舍：

- 没有教室、实验室、操场、晚自习、每日考勤、教研组、班主任、活动课。
- 班会就是普通课程，教师可在授课任务里选。
- 空槽就是不上课。
- 已发布课表可以撤回为草稿；只撤回基线，调代历史保留。
- 导入默认走“配方”（不调用 AI），AI 只负责在遇到新格式时帮用户写配方。
- 规则从 26 类收敛为 19 类，使用三种句型；删除 7 类。
- 删除分三档，所有删除保留 7 天可撤销。
- 锁定只影响自动排课/换课找方案，不限制手动拖动和删除草稿。

## User Stories

1. 作为教务管理员，我想在一个页面看到当前学期、数据完整度和待办，以便知道今天该做什么。
2. 作为教务管理员，我想从总览一键跳到导入、排课、发布、调代、新建规则，以便少点几次菜单。
3. 作为教务管理员，我想在课表工作台创建空白草稿、从导入生成草稿、或从自动排课生成草稿，以便按不同起点开始。
4. 作为教务管理员，我想在草稿里拖拽课程、同班换位、撤销，以便快速微调。
5. 作为教务管理员，我想锁定某些课，让它们在自动排课和换课找方案时不被移动，但不影响我手动拖动或删除草稿。

## Implementation Decisions

### 信息架构与路由

- 一级导航固定 7 项：总览、课表工作台、调代课、排课规则、数据管理、AI 助手、设置。
- 旧路由保留兼容重定向：`/admin/semesters`、`/admin/teachers`、`/admin/courses`、`/admin/classes`、`/admin/grades`、`/admin/assignments`、`/admin/ai-import` 归入数据管理；`/admin/drafts/:id`、`/timetable`、`/admin/scheduling` 归入课表工作台；`/substitutions`、`/substitutions/workbench` 归入调代课；`/admin/constraints` 归入排课规则；`/admin/ai-providers` 归入 AI 助手；`/admin/settings`、`/admin/users` 归入设置。
- 删除导航入口：教室、通知中心、AI 操作历史、飞书绑定、初始化向导独立页。
- 帮助改为抽屉；登录/403 保留为系统页。

### 数据模型

- 作息只保留星期、第几节、开始时间、结束时间；删除 `PeriodSection`（上午/下午/晚自习）语义。上午/下午只在前端按时间折算成节次，规则存节次。
- 删除教室实体与相关约束：教室冲突、教室容量、课程指定教室类型、固定教室、补教室。发布不再要求 `roomId`。
- 年级增加入学年（entry year）；年级显示名与入学年分离；班级挂入学级，显示名按学年生成。
- 课程增加“班会”作为普通课程；不增加活动课类型，不做班主任自动跟随。
- 新增 `import_recipe`：布局、指纹、列映射、清洗、校验、样例与预期结果、版本、启用状态。
- 删除/撤销：为可删实体增加软删除标记或统一的“最近删除”表；保留 7 天。
- 规则不新建第二套存储：积木规则编译为现有 `constraint_config` / `constraint_entry`（含 `groupKey`、`enabled`、`hard`、`weight`），求解器、草稿校验、调代校验、CLI 继续共用同一套约束快照。

### 约束积木

- 语法：对谁（全校/年级/班级/教师）× 哪些课（全部/某课程/某学科）× 什么时候（星期/节次/最后一节/每天/每周）× 要求（不排/必须排/固定为/最多 N/至少 N/连堂 N/分散/不空堂/连续不超过 N）。
- 三种句型：时段型、数量型、形态型；强度必须/尽量。
- 26 类保留 19 类：17 类积木 + 2 类系统规则（教师不冲突、班级不冲突）。
- 删除 7 类：教室 3、晚自习 2、教研活动禁排、班主任课优先第一节。
- 规则卡支持 2–3 句、共用开关和删除；例外用“但是”句。
- 规则编译器负责把句型映射到现有 `ConstraintType` 参数；未保留的 7 类从目录与 UI 中移除。
- 规则界面提供搜索下拉、实时句子预览、保存前影响预览、删除影响提示。

### 导入配方

- 导入主路径：指纹匹配 → 配方解析 → 预览 → 入库；不调用 AI。
- 无配方时：手动选列映射（不依赖 AI）；可选 AI 分析辅助；确认后保存为新配方。
- 配方指纹：sheet 名、表头行、列数、列类型、分隔符、布局。
- 配方测试：样例文件 + 预期结果（槽数、有课数、空槽数、教师数）；改配方必须通过样例测试才能保存。
- 指纹相近时用配方解析，但预览标黄变化；结果差异过大时提示。
- 真实工作簿作为第一份配方：560 槽、546 有课、14 空槽（周五第 7 节）、48 教师、16 课程；空槽生成“全校周五第 7 节不上课”规则。
- 占位教师名标黄，不静默创建。

### 排课与发布

- 自动排课增加年级范围：只排选中的年级；其他年级课作为固定占用；共享教师的“每天最多 N 节/连续不超过 N 节”按全校总账计算。
- 发布仍整校一次；发布检查不要求教室。
- 撤回为草稿：只撤回已发布基线；调代记录保留为历史，不写入草稿；撤回前列出未来日期会失效的调代；撤回后可编辑、重新发布。
- 不再引入课表版本/生效日期的额外概念。

### 教师视图换课

- 教师视图每节显示班级、课程、教师。
- 点课返回可换格子：绿色=可换（含对方班级、课程、教师），灰色=不可换（含原因）。
- 只支持同班换课，复用现有同班换位接口；跨班换人冻结。

### 删除与撤销

- 三档：被已发布/调代引用→只能停用；只被草稿/规则/授课任务/配方引用→可删并列出影响，提供“一起删/改为停用”；无引用→直接删。
- 所有删除进入 7 天“最近删除”，可撤销。
- 覆盖规则、授课任务、教师、班级、课程、年级、学期、用户、草稿、配方、AI 供应商/模型、钉钉配置。

### 测试接缝

- **约束**：现有 `ConstraintChecker` + 约束目录是唯一接缝；积木编译器只产出既有 `constraint_entry`，不为新句型新增第二套评估器。
- **导入**：新增“配方解析器”纯接口（指纹匹配 + 列映射 + 预览），与 `AiImportService` 会话边界解耦；HTTP 层只负责上传/预览/入库。
- **课表变更**：草稿换位、教师视图换课、调代共用现有 `DraftValidator` / 约束检查；不为教师视图新增一套换课算法。
- **发布/撤回**：现有 `timetable` 发布服务与 `timetable_publish` 表；撤回只改发布状态，不新增版本表。
- **UI**：7 条一级路由的 Playwright 冒烟 + 关键流程 E2E。

### 保留 / 冻结 / 删除

- **保留**：登录/RBAC、总览、课表工作台、调代课、排课规则、数据管理、AI 助手、设置、导入、发布/撤回、Excel 导出、备份。
- **冻结**：自动排课入口（高级）、自然语言生成规则、钉钉（先留代码不配）、飞书、PDF 导出、跨班换人、教师自助调代、通知中心、AI 调代推荐、帮助中心、部分高级约束。
- **删除（最后做）**：教室整套、晚自习、每日考勤、飞书整套、平台切换、初中/高中模式、模型评测、AI 操作历史页、只读 CLI、PDF 导出、草稿锁定带来的限制（锁本身保留）、审批链/修订链/开课截止/历史转换。

## Testing Decisions

- 好测试只验证外部行为：HTTP 契约、规则编译后的评估结果、导入预览与入库、发布/撤回状态、删除/撤销结果；不断言组件内部实现。
- **单元**：
  - 规则编译器：19 类逐类编译到现有约束参数；删除的 7 类不再出现；例外/多句共用开关。
  - 配方指纹与匹配：完全匹配/相近/不匹配；样例预期结果校验。
  - 年级范围：共享教师数量规则跨年级合计。
  - 撤回：只撤基线、调代历史保留、未来调代失效提示。
- **集成**：
  - 导入 API：真实工作簿 fixture → 配方解析 → 预览 → 入库 → 第二次不调用 AI。
  - 规则 API：三种句型创建/保存/评估/删除。
  - 发布/撤回 API：发布 → 撤回 → 重新发布，旧调代历史仍在。
  - 删除/撤销 API：三档删除、7 天恢复。
- **E2E**：7 页导航冒烟；导入 → 草稿 → 发布 → 撤回 → 再发布；教师视图绿/灰换课；规则积木创建 + 删除；调代直接生效 + 撤销。
- 先例：`ConstraintChecker` / `EngineConstraintTest`、`WorkbookImportFlow` 集成测试、`draft-swap-locks` 的 Playwright 用例、`workbench-a11y` 的 320px 检查。

## Out of Scope

- 多校/多租户。
- 教师自助登录与教师端提交调代。
- 每日考勤、晚自习、上午/下午硬分区。
- 教室、实验室、操场、机房管理，以及撞场限制。
- 教研组、班主任、活动课等细分角色/类型。
- 正式审批链、修订链、开课截止、历史转换。
- 模型评测、AI 操作历史独立页、只读 CLI。
- 跨班换人、跨班换位、空格补课。
- 飞书、平台切换、PDF 导出、初中/高中双模式。
- 整体重写求解器或导入管线。
