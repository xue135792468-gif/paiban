# 自动排课把每个班钉在自己的固定教室，课表不再展示教室

## 背景

求解器把「教室」当作自由规划变量，只约束同一时刻不撞教室、容量足够、课程要求的教室类型匹配。真实数据里一个年级的十几间普通教室容量和类型完全相同，对求解器来说可以互换，于是每个班的课会被分散到全校所有教室。教室名又按「学期-年级班名-固定教室」命名，班级课表的第二行就会显示成别的班的名字，看起来像「串班」。

用户明确不需要区分普通教室、操场、机房等类型，只需要每个班有一间教室，课表里不展示教室。

## 决策

1. 自动排课沿用「补固定教室」已经建立的命名约定
   `学期名-年级名班名-固定教室`，由 `RoomFillPlanner.fixedRooms` 纯函数解析每个班的固定教室；名字两侧空白会被忽略。
2. `TimetableProblemBuilder` 把固定教室同时写入 `Lesson.fixedRoom` 和初始 `room`；求解器新增一条常开的硬约束
   「班级固定教室」，普通课程的课离开本班教室即硬违规。只有专用教室类型的课节豁免：`requiredRoomType` 去掉两侧空白后不等于 `NORMAL`（如 `LAB`、`PLAYGROUND`）才视为专用，仍由课程要求决定教室；`NORMAL`（含 `" NORMAL "`、小写等形式）视为普通课，仍钉本班固定教室。
3. 只有在找不到同名固定教室、或同一间房被两个班同时认领时才不钉住，退化为原来的自由分配，避免坏数据让整个问题不可行。容量与教室类型不作为约束：用户确认每个班默认都有足够大的固定教室，且教室一定存在。
4. 班级课表（草稿与已发布）和 Excel/PDF 导出不再显示教室名；AI 导入预览仍保留教室列，便于核对导入行。

## 结果

- 每个班的普通课只落在本班固定教室；教室冲突自然消失，求解空间也明显变小。
- 「补固定教室」和导入流程不变；没有固定教室数据的学期仍按旧逻辑自由分配。
- 课表页面不再出现别班名字；教室类型不再影响这个用户的使用方式。
- 手工把课节拖到别的教室仍然允许（固定教室只在求解时约束），但界面不展示教室，不影响班级课表的可读性。
