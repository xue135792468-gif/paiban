# 排课引擎调用：异步任务 + 前端轮询，手工微调用增量校验接口

**完整排课**：教务点"开始排课"→ 后端创建异步任务（提交到任务队列）→ 前端每秒轮询任务状态 → 完成后展示结果。支持求解进度展示（当前得分、已耗时、预估剩余）。

**手工微调实时校验**：走独立的轻量接口，调用 Timefold 增量评分（毫秒级），前端拖拽过程中实时反馈冲突。

## 为什么

- 中学规模完整求解通常 10-60 秒，同步调用会触到 Web 超时边界
- WebSocket 推送（C 方案）在校园内网环境可能遇到代理穿透问题，复杂度高收益低
- 增量校验与完整求解是两种不同的计算模式，本就该分开

## Consequences

- 后端需要任务队列抽象（一期可用 Spring 的 `@Async` + 数据库任务表，不引入 RabbitMQ/Redis 等中间件）
- 任务状态机：pending → running → completed / failed / cancelled
- 同一学期同一时刻只允许一个排课任务运行，避免资源争抢
