# 性能指标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 学校规模上限 | 100 个班 / 500 教师 / 200 教室 | 足够覆盖大学校 |
| 完整排课耗时 | < 5 分钟（100 班规模） | Timefold 通常 30 秒内，留足余量 |
| 手工微调冲突校验 | < 500ms | 拖拽时的实时反馈 |
| 课表查询 | < 200ms | 单个班级/教师/教室视图 |
| 全校总表加载 | < 2s | 100 班 × 5 天 × 8 节的大表 |
| 并发用户 | 50 同时在线 | 教务 + 教师高峰期 |

## 为什么

排课系统是低并发、重计算、调用稀疏的系统。这些指标不是挑战极限，而是"够用到不会成为抱怨来源"的底线。

## Consequences

- 完整排课走异步任务（见 ADR-0013），不占用 Web 请求线程
- 全校总表加载必须做后端分页或前端虚拟滚动，不能一次吐全量
- 课表查询走"基线 + 叠加"合并逻辑（见 ADR-0008），需要在 `substitution` 表的 `entry_id + effective_date` 上建联合索引
