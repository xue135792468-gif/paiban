# 一期交付范围（MVP）与明确的二期边界

## 一期交付（13 项核心能力）

1. 基础数据管理：年级/班级/教师/教室/课程 CRUD + Excel 导入导出
2. 作息表配置：每天几节课、每节时长、午休晚自习
3. 授课任务录入：班级 × 课程 × 周节次 × 任课教师
4. 约束配置：预置约束库（20-30 条）+ 权重调整
5. 自动排课：异步任务 + 进度轮询
6. 手工微调：拖拽 + 实时冲突校验 + 冲突原因提示
7. 课表发布：草稿 → 发布 → 基线只读
8. 调代课：申请（审批/直接生效可切换）+ 通知 + 叠加展示
9. 课表查看：班级 / 教师 / 教室 / 全校总表
10. 课表导出：Excel + PDF
11. 用户与权限：本地账号 + RBAC 三角色
12. 钉钉集成（可选启用）：免登、教职工同步、工作通知（Stream 模式）
13. 设置中心：审批模式、通知范围、AI 特性开关（占位）

## 一期明确不做（二期或更后）

- 学生/家长端
- 升学向导（毕业、新生、留级、转学）
- 多学期对比分析报表
- 代课费 / 教师课时统计报表（一期留数据）
- 教室预约 / 借用
- 考试排考
- 移动端专属 UI（H5 响应式即可）
- AI 功能本体（预留接口与开关）
- 自定义约束 DSL（预留 SPI）
- 飞书集成（预留适配层）
- 多租户 SaaS

## 为什么

把"不做"写下来和"要做"同等重要——这些"不"是项目边界的承重墙，避免开发过程中范围蔓延导致一期烂尾。每一条"不做"都对应一个明确的扩展接口或数据预留，二期拾起时不需要返工。

## Consequences

- 一期交付时要在 README 里明确列出"本版本不支持"清单，避免教务期望错位
- 数据库 schema 与 API 设计必须为二期清单中的每一项预留扩展点（特别是 AI 网关、约束 SPI、IM 适配层）
