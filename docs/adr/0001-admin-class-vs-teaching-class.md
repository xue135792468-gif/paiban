# 行政班与教学班在数据模型上分层，但第一版 UI 与算法只做行政班

国内中学分两类：固定班（一个班级一张课表）与新高考走班（学生按选科分到不同教学班，与行政班解耦）。我们决定数据模型从第一天起就区分 **AdminClass** 与 **TeachingClass**，排课引擎的输入单元 **Assignment** 关联到 TeachingClass（行政班作为 TeachingClass 的特例存在）；但第一版 UI 只允许按行政班录入与展示课表，算法也只为行政班场景做优化。

## 为什么

- **难反转**：如果第一版模型里"班"只有一个概念，二期加入走班时需要把 Assignment、Timetable、Conflict、Substitution 全部重写，相当于重做核心。
- **UI/算法简化成本可控**：UI 与算法的简化不进入模型层，只是"TeachingClass 暂时只允许一对一映射到 AdminClass"的约束，二期放开即可。

## Considered Options

- **只做行政班，二期再拆**：被否。模型层重写代价远高于第一版多带一个抽象。
- **第一版就做完整走班**：被否。算法与 UI 复杂度陡增（选科组合爆炸、教室冲突维度增加），第一版周期会被拉长到不可接受。
