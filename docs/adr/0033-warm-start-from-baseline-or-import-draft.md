# 自动排课从已发布基线或导入草稿热身起步

## 背景

评分修复后，求解器不再用“留空”省分，但在一份 546 节、每班 39/40 个时段的真实数据上，从空课表起步仍会停在 2 处教师冲突 + 2 节教室不对，60 秒和 300 秒结果相同；`CHEAPEST_INSERTION` 把教师冲突降到 0，却仍留下 1 处班级冲突和 3 节机房占用。与此同时，同一学期的已发布基线（以及新学期的完整导入草稿）本身就是一份完整、0 硬冲突的同一套班级/课程/教师安排。

## 决策

- 构建求解问题时，优先用 `timetable_entry` 的已发布基线作为初始课表：按 `(班级, 课程, 教师)` 把基线条目的时段分给对应授课任务的课节。
- 新学期还没有基线时，回退到该学期**最早的一份完整草稿**（通常是导入草稿；所有课节都有作息时段才算完整）。
- 教室仍由 ADR-0031 的固定教室规则决定，不从基线复制；固定教室没解析到的课节保持未分配，由构造启发式补。
- 授课任务在发布后被改过、或没有对应基线/草稿条目的课节，保持未分配，由 `CHEAPEST_INSERTION` 从头构造。

## 结果

- 已有基线或导入草稿的学期，自动排课从一份可直接发布的课表起步；局部搜索不会接受更差的硬分，因此草稿保持 0 硬冲突、全部课节有时间+教室、每班一间教室。
- 同城没有基线、也没有完整草稿的学期，仍走“评分修复 + CHEAPEST_INSERTION”的从零搜索；这条路不保证一次到 0，但不会再以留空作为省分手段。
- warm start 只是初始解，不是约束：求解器仍可在不增加硬冲突的前提下调整课节。
