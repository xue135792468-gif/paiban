# AI 数据导入管道：多通道输入 → 预览 → 人机接力 → 入库

AI 数据导入是二期核心能力。支持 Excel/CSV、纯文本粘贴、图片（视觉模型）三种输入通道，统一走"AI 解析 → 目标格式预览 → 用户确认/微调 → 入库"流程。

## 管道设计

```
输入通道：
  Excel/CSV → Apache POI 解析为中间 JSON
  文本粘贴 → 直接作为 prompt 上下文
  图片 → 视觉模型直接输出结构化 JSON（不走 OCR 中间层）

统一处理：
  中间 JSON → AI（结构化输出）→ 目标格式预览表格
  预览表格：单元格只读，低置信度单元格浅黄底色标注
  AI 说明：映射逻辑解释（"原始'姓名'列 → 系统 name 字段"）

用户选择：
  a) 全部接受 → 直接入库
  b) 手动微调 → 单元格变为可编辑，改完后：
     - "AI 继续" → AI 基于修正后数据重新解析剩余部分
     - "直接入库" → 用户确认的数据直接入库
  c) 打回重析 → AI 重新解析原始文件
```

## 为什么

- 教务老师的现有数据格式千奇百怪（自己画的 Excel、微信聊天记录、纸质表拍照），传统模板导入太僵硬
- 视觉模型（Gemini、DeepSeek V4.1 等）原生支持图片理解，不需要独立 OCR 服务
- "人机接力"模式让用户在 AI 不准时保持控制权，又不至于完全手工

## Consequences

- 所有 AI 导入操作记录到 `ai_import_log` 表（谁、何时、上传什么、AI 解析结果、用户确认内容、最终入库数据）
- 低置信度标注基于 AI 返回的 confidence 字段，阈值可配置
- 图片输入时校验模型 `vision_capable` 标记，不支持视觉的模型给出明确错误提示
- 入库前做数据校验（必填字段、格式、重复检测），校验失败标红并阻止提交
