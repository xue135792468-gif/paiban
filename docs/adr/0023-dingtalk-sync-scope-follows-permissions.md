# 钉钉通讯录同步范围由钉钉权限决定，程序不配置部门白名单

钉钉同步从根部门开始递归遍历整棵部门树，凡是应用能读到的部门与用户都导入本地教师表。程序内不提供部门白名单、`sync-dept-id` 之类的范围过滤：学校在钉钉侧收紧应用的通讯录可见范围后，下一次同步自然只导入范围内的人，无需改配置或重启。

## 为什么

- **单一事实源在钉钉侧**：通讯录的组织边界由学校人事维护，本地再维护一份白名单必然与钉钉漂移。
- **避免「同步成功但少了人」**：此前客户端把 `dept_id` 写死为 `1`，只导入根部门直属的 2 人，而全校有 300 多位教职工；这类静默漏导无法通过日志发现。
- **收紧权限即可收紧导入**：应用可见范围是钉钉已有的治理手段，程序不需要再造一个开关。
- **一次点击完成**：教务管理员不应为了「把全校导进来」去逐个填写部门 id。

## 实现约束

- 从根部门（`1`）开始，`department/listsub` 深度优先遍历；每个部门用 `user/list` 按 `cursor` 翻页到底，跨部门按 `userid` 去重。
- 部门 id 为负数的直接跳过（`-7` 是家校通讯录，学生/家长不属于教职工）；`user/list` 对某个部门返回 `errcode=41` 时跳过该部门继续，不让单点无权限拖垮整次同步。
- 部门名含「离职」或钉钉返回 `active=false` 的用户落库为停用，不进入排课候选。
- 本轮同步不自动停用「这次没看到」的教师：权限临时收紧不能让整校教师被停用，停用只来自钉钉明确的离职信号。
- 匹配顺序固定为 `dingtalk_user_id` → 工号 → 手机。姓名相同只作为「疑似同名」提示，必须由管理员确认，绝不自动合并。
- 失败必须可见：文案透传 `errcode` / `sub_code`；IP 白名单拒绝（`88` / `60020`）明确提示检查服务器出口 IPv4。

## Consequences

- 学校若只想导入部分部门，应在钉钉应用的「通讯录权限 / 可见范围」里收紧，而不是在排课系统里配置。
- 家校通讯录、团委学生、校外人员等分支是否导入，取决于它们是否在应用可见范围内；若在，管理员可在同步预演确认页按部门排除。
- 同步数量必须与钉钉后台核对：成功日志输出扫描部门数、用户数与耗时。
