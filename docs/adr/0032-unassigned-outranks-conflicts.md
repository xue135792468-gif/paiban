# 未排课的代价必须高于一处硬冲突

## 背景

自动排课把 546 节课排进 14 个班、每班 40 个时段（每班 39 节，只剩 1 个空位）。求解器一度停在 `-5hard`：3 节没有时间、2 节有时间但没有教室，草稿因此不能发布。

根因有两层：

1. Timefold 的 `forEach` / `forEachUniquePair` 会跳过还有规划变量为 null 的实体。一个“有时间但没教室”的课节因此**不会**触发教师/班级/教室冲突，也不会触发固定教室约束；它在求解器眼里只剩「课节未排」这 1 分。
2. 「课节未排」原来也是 `ONE_HARD`，和任意一处硬冲突同分。求解器于是认为“空着一节课”和“多一处冲突”一样糟，跑到 60 秒（甚至 300 秒）就停在一个有空洞的局部最优。

## 决策

- 「课节未排」改为 **10 hard**，严格高于单处冲突（1 hard）。当完整课表与空洞冲突时，求解器必须先补全课表；补全后仍有冲突，则冲突会明确留在草稿里，由人处理，而不是被隐藏成“没排”。
- `classFixedRoom` 和 `courseRoomTypeMetadata` 改用 `forEachIncludingUnassigned`，让“有时间但没教室”的课节也能被固定教室/教室类型约束抓到。
- 不额外改变求解时长或终止条件：补全课表的优先级由分数保证，60 秒预算保持不变。

## 结果

- 自动排课不会再以“留空”作为省分的办法；草稿要么完整，要么把冲突显式留在课表上。
- 草稿得分里一个空洞会显示为 -10 hard，而不是 -1；这是有意的，提醒使用者“这不是一处普通冲突”。
- 如果数据本身让完整排课不可行，求解器仍会产出完整课表并留下冲突；这时校验会按真实冲突拦截发布，不会用“未排课”掩盖问题。
