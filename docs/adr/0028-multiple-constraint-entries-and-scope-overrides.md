# 约束按类型控制、多条对象条件与具体对象覆盖

日期：2026-10-25
状态：Accepted（票10原设计已实现；2026-10-27批准逐项控制及重叠处理的设计修订，修订尚未实现，见文末）

## 背景

每学期每类型仅一行配置会让第二个对象覆盖第一个。简单改成列表会产生重复惩罚、偏好“且/或”歧义和不同评估入口不一致。逐条独立软硬权重又会显著增加页面和求解复杂度。

## 决定

- 原票10决定同类条目共用启用、软硬和权重；各条只承载对象与条件。页面采用分组折叠卡片。**强制共用控制这一限制已由2026-10-27修订替代**：类型保留总开关与默认值，每条要求可独立启停，并可覆盖软硬与软约束重要程度。当前已实现代码仍使用旧契约，见文末修订。
- 禁排取并集；同一教师的多个偏好时段是可选集合。
- 同一课程互斥教室要求、重复对象阈值明确拒绝，不以最后一条覆盖。
- 五类阈值支持全局默认＋自然适用对象例外，具体对象替代全局；不为不适用的对象类型开放万能作用域。
- 原有单条配置与模板保留含义；求解、草稿、发布、调代独立检查及 CLI 使用一致条目集合与匹配。
- 用户已确认上述控制层级、覆盖与组合语义，并认可六张端到端票据的划分。

## 后果

后续需迁移唯一限制、保存身份和读取契约，覆盖完整 24 类目录及模板。原型获确认是实施门槛；本 ADR 不表示代码已上线，也不包含自然语言生成。

## 补充决定（2026-10-26，票 10/05 模板兼容）

- 模板保存的是**整学期快照**：每个类型一条 config（启用/软硬/权重）＋ 全部条目。旧格式（只有 `params`）照旧读取，按「一条 legacy 条目」套用，含义不变。
- 跨学期的行政班引用**不自动按同名映射**：默认拒绝整个套用，并在错误体里列出失效引用（类型、第几条、字段、对象名/id、原因）；调用方可以为每个失效班级显式指定目标学期的班级后重新套用。教师/课程是全局资产，仍然存在即原样保留，不存在的同样列明而不是静默丢弃。
- 模板文本容量由 `VARCHAR(8000)` 扩容到 `VARCHAR(65535)`（V29；H2 与 PostgreSQL 都接受 `ALTER COLUMN ... SET DATA TYPE`），超限仍然显式 400，不静默截断。
- 套用仍是整学期替换：失败零写入，重复套用不累加。

## 修订决定（2026-10-27，票14设计，尚未实现）

自然语言需要准确区分“王老师周三下午必须不排”和“李老师周五下午尽量不排”。强制同类共用软硬会让其中一项要求改变时连带改变另一项，不能忠实表达用户意图。用户已确认改为：**每条要求可独立选择必须/尽量，未单独设置时沿用同类默认值**。同一要求展开的多个课节作为一组，共用该要求的设置；手动配置与自然语言共用这项能力。

原有配置在没有逐项设置时仍表达原来的软硬，不能在升级时改义；新增或修改某条要求的软硬不自动更改其他已有要求。求解、草稿/发布校验、调代检查、模板及页面均须使用一致的实际设置。保留类型默认是为减少逐条重复操作；允许逐项设置是为准确表达不同对象的要求。

同日第四轮 Q13–Q16 用户确认以下配套决定：

- 每条要求有独立启停，暂停保留内容。类型总开关关闭时整类不生效，重开后仍保留各条原来的启停状态。
- 每条软要求可以单独调整重要程度，默认沿用同类值，需要时展开设置；必须满足的要求不显示无意义权重。AI不任意编造重要程度。
- **同一限制、同一违反事实**被多条有效要求覆盖时不重复扣分：含硬要求按硬要求处理，均为软要求时取较高重要程度。不同限制或不同违反事实不因同一课节而被合并；教师偏好时段仍是命中任一即可，不能因拆条改变含义。
- 阈值先按作用域选择：具体对象例外替代全局，未覆盖对象仍用全局。例外自身的软硬和数值一并生效；例如全局必须最多4节、王老师尽量最多6节，王老师按尽量6节。保存此类放宽前必须明确提示并获确认，不能把“重叠取最强”误用到已经被对象例外替代的全局项上。

以上均为已确认设计，尚未实施。
