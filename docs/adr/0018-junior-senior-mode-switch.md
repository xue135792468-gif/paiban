# 初中/高中模式通过系统设置切换，仅影响 UI 显示层

系统设置新增"学校类型"枚举（`junior` 初中 / `senior` 高中），默认 `junior`。切换后仅影响 UI 层的显示与隐藏，不改变底层数据模型与功能可用性。

## 为什么

- 一期按"通用中学"设计，实际夹杂高中思维（复杂约束、权重滑块、多草稿对比等），初中教务老师反馈"复杂麻烦"
- 初中与高中共享 80% 功能（基础数据、课表引擎、调代、导出），分代码分支意味着改 bug 改两遍
- UI 层裁剪是最低成本的分版方式：初中老师看不到复杂功能就不觉得乱

## 初中模式默认隐藏的功能

- 约束权重滑块（简化为"必须/尽量"两档）
- 多草稿对比视图（只保留当前草稿）
- 约束模板保存/加载（使用内置默认模板）
- 全校大平铺视图（初中班级少，按班级列表即可）
- 教室类型细分（初中教室类型简单）
- 钉钉同步策略选择（默认"钉钉为准"）
- 高中特有的约束规则（选科组合、教研组互斥等）

## Consequences

- 前端组件通过 `v-if="schoolType === 'senior'"` 控制显示
- 后端不感知学校类型，所有接口对两种模式一致
- 设置项存储在 `system_config` 表，key 为 `school.type`
- 未来支持"完全中学"时扩展枚举为 `combined`
