# 调代审批模式做成系统级配置项：审批模式 / 直接生效模式，可在设置中切换

调代申请的状态机支持两种流转路径，由系统设置项 `substitution.approval_mode` 控制：

- **审批模式**（`approval`）：教师提交 → 待审批 → 教务批准/驳回 → 批准则生效并通知相关人员
- **直接生效模式**（`direct`）：教师提交 → 立即生效 → 通知教务与相关教师（事后备案）

## 为什么

- 国内中学真实流程两种都有：管理严格的学校走审批，管理宽松的学校走备案；让学校自选比替他们做决定更合适。
- 实现成本极低：一个枚举配置 + 状态机分支，但避免了二期"学校要求加审批流"的返工。

## Consequences

- `substitution_request` 状态机必须从一开始就支持两条路径，不能写死单一流程
- 切换配置只影响**之后**新提交的申请；已在流程中的申请按提交时的模式走完（避免状态混乱）
- 两种模式下都保留完整状态历史，便于审计
- 默认值为**审批模式**（更保守，符合多数学校的预期）
