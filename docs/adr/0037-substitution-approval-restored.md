# 老师自助代课恢复审批，管理员决定后生效

取代 [ADR-0009](0009-substitution-approval-mode-configurable.md) 的「审批模式 / 直接生效模式可切换」，
也推翻票 15 Q5「删除审批链」的产品结论。ADR-0009 记录的历史事实不改写。

## 背景

票 15 删掉了老师自助调代的审批链：老师提交代课后当场生效，教务只能事后发现问题。
多用户版本上线后，全校老师都能直接改已发布课表，这与学校「先审批、再生效」的要求冲突：
代课人可能在提交时还有空、到上课前已经被别的安排占住，也可能根本不是教务认可的人。
同时，原来的审批模式是系统级开关（ADR-0009），学校只有一套流程，
没有必要保留两套状态机让配置和已存在申请互相打架。

## 决定

流程固定为一条，不再保留模式切换：

1. 老师自助提交只保存为 `SUBMITTED`（待审批），不写生效行、不改课表、不发网络通知。
2. 超级管理员或教务管理员可以**批准**（可同时换成另一位代课人）、**驳回**（理由必填）。
   先处理者为准；后到的处理返回 409，不产生部分生效。
3. 申请人本人在批准前可以**撤回**。
4. 到开课时刻仍停在 `SUBMITTED` 的申请**作废**（`EXPIRED`），不会在课后突然生效。
5. 管理员调代工作台「亲自确认」保持直接生效：它本来就要求管理员即时判断并留审计，
   不属于老师自助申请，因此不套审批队列。

配套约束：

- 状态集合：`SUBMITTED` / `EFFECTIVE` / `REJECTED` / `WITHDRAWN` / `EXPIRED`。
  `CANCELLED` 保留既有语义：生效安排被系统撤销时按既有流程转 `CANCELLED`
  （例如撤回已发布基线后，新近已生效的安排仍会转 `CANCELLED`），
  展示为「系统撤销」，不等同申请人撤回，也不能改写成 `EXPIRED` 或删除原回归断言。
- 锁定顺序固定为「学期 → 申请」。提交时的同实例待审批唯一检查放在学期行锁之后；
  批准/驳回/撤回拿锁后刷新再读状态，不信任锁前载入的实例。
- 批准必须按**当前**事实重验：申请对应的基线条目仍在、实例的原教师与节次未变、
  最终代课教师存在且未停用未删除、不撞课、仍未到开课时刻。任一项不满足就拒绝，
  旧生效行不退出、新行不生成。
- 改人批准时，`expected_substitute_teacher_id` 永远保留提交时的期望人，
  `final_teacher_id` 记录实际批准的人；DTO 同时给出两者。
- 作废要真落库：在可写事务里保存 `EXPIRED`、状态历史和审计，事务提交后才向调用方返回 409。
  不对全部 `ApiException` 配置 `noRollbackFor`，避免把本该回滚的失败半写留下来。
- 申请表新增 `approver_user_id` / `approved_at` / `approval_comment`（V63）；
  V55 只作为历史，不再改写。不恢复 `approval_mode`。
- 审计：提交 / 批准 / 驳回 / 撤回 / 作废各写一条同事务成功审计；
  失败路径沿用既有失败审计，但不再触发告警通知。
- 通知不在本票恢复：提交不再发「已接课」，批准/驳回的钉钉通知由后续票统一接入与去重。

## 后果

- 老师提交后必须等管理员处理；「我的调代」需要展示五种状态与驳回理由，
  「待审批」成为管理员入口（前端见对应票）。
- 任何依赖「自助提交即生效」的既有测试、脚本与调用方都要改成「提交 + 批准」两步；
  工作台直接确认路径的调用方不受影响。
- 申请与生效行分离得更彻底：`substitution_request` 是流程状态，`substitution` 是
  已生效的课表覆盖；批准才产生后者。
- 审批人记的是真实操作账号，而不是账号绑定的教师身份；
  申请归属先认真实操作账号，旧行才回退到非空的申请人教师关系。
