# 钉钉首次免登身份绑定与密码恢复入口

2026-11-11，钉钉多用户票 03。补充 ADR-0006、ADR-0035；历史正文不改写。

## 背景

老师首次进入需要自动开通账号。唯一同名可以配对普通教师，但教务可编辑教师姓名，不能让姓名匹配赋予已有管理员账号的身份。产品所有者明确确认：钉钉 ID 仅超级管理员可改，关联管理员账号的首次绑定须超级管理员确认。

## 决定

- 身份仅取服务器向钉钉交换得到的 UID 与姓名。先查未软删档案的 UID；无 UID 命中时，只在未绑定的同名档案中计数。已绑定其他 UID 的档案不参与姓名候选；排课资格 `active` 不影响账号可用性。歧义时拒绝，不凭查询顺序选择。
- 管理员保护按账号实际管理权限识别，包含停用账号与遗留自定义角色。唯一候选关联管理员账号时拒绝自动首次绑定。超级管理员在教师管理中显式填入 UID 是当前可信确认入口；同步、导入、事件不得绕过，事件不得覆盖非空 UID。
- 复用已有启用账号，多个历史账号时固定选最小 ID；只有停用账号则拒绝，不另建、不重新启用。无账号时只创建老师角色的 `DINGTALK` 账号，密码哈希为 null；手工建号与旧账号仍是 `PASSWORD`。提升角色不改变登录方式。
- 第三方网络调用完成后才进入本地事务。账号写入共享超级管理员角色锚点，随后按 ID 顺序锁定并刷新教师，再重新判断候选与账号。自动配对、开号、各自审计在同一事务中提交。失败不得留下半绑定或孤立账号。
- 免登失败使用稳定原因码，前端显示对应说明和管理员密码入口。供应商错误正文、凭证、authCode、token、密码及哈希不进入业务响应或审计。
- 任意启用超级管理员的保护继续保留；另须保留至少一个启用的 `PASSWORD` 超级管理员，防止钉钉异常时失去密码恢复入口。降级、编辑停用、专用停用、同步停用均在同一锚点锁内使用数据库标量计数，不依赖旧实体快照。

## 后果与验证边界

V62 保留历史密码账号，新增类型与哈希组合约束。不对存量教师 UID 盲加唯一索引；脏重复数据以明确失败处理。未增加审批队列或通用身份框架。

自动化采用独立 H2、Fake 钉钉、本地 HTTP 协议桩与浏览器验证；这些不证明真实企业权限、网络、PostgreSQL 或手机钉钉客户端已验收。原始测试与复查记录见 `.scratch/dingtalk-multiuser/`。
