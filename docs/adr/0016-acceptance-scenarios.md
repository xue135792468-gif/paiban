# 一期验收：三个端到端场景全部跑通

## 场景 1：新学期排课闭环

教务老师从零开始 → 向导录入学校数据 → 配置作息表与约束 → 录入授课任务 → 提交自动排课 → 在草稿上手工微调 3 处冲突 → 发布课表 → 教师收到钉钉通知。

## 场景 2：调代闭环

张老师周三下午请假 → 提交调代申请 → 教务审批通过 → 李老师收到代课通知 → 高一 1 班班主任收到班级课表变更通知 → 周三当天课表显示李老师（代）→ 期末能查到这次调代记录。

## 场景 3：无钉钉环境完整可用

学校未开通钉钉 → 教务用本地账号登录 → 完成场景 1 全流程 → 调代时通过系统内消息（而非钉钉）通知 → 所有功能正常。

## 为什么

- 场景 1 覆盖核心排课价值链（数据 → 排课 → 微调 → 发布 → 通知）
- 场景 2 覆盖调代价值链（申请 → 审批 → 通知 → 叠加展示 → 追溯）
- 场景 3 验证 ADR-0005（外部集成可插拔）——钉钉不是依赖，是增强

三个场景任何一个跑不通，一期不算完成。

## Consequences

- 每个场景必须写成自动化 E2E 测试（Playwright / REST Assured），CI 上每次提交都跑
- 场景 3 的"无钉钉"测试环境必须独立可用，不能依赖 mock 钉钉
