# 发布后调课采用同班置换环，由确定性搜索生成、独立校验器把关

课表发布后的临时变更拆成两类，共用一套引擎：

- **调课**：把一个课节从原时间移到目标时间，并在**同一行政班**的课表内用置换环把原节次补满。环长 2–6（可配置），班级当天的课节数量与课程集合不变，只有节次顺序变。
- **代课**：原教师不能上课，另一位教师接替该课节，单向补位，不回填原节次。

调课候选方案由纯确定性搜索生成：以「日期 + 节次」为节点建图，硬约束做建图剪枝，按「同日优先 → 跨天窗口（默认 7 天）→ 影响天数 → 是否同周 → 影响教师数 → 软约束扣分」分层 BFS，提供 `min-impact` / `min-teachers` / `stable-timetable` 三个排序预设。AI 不参与可行性判断与排序。批准前由与求解器**彼此独立**的校验器对「基线 + 全部生效调代」做完整硬约束校验，任何违规整单拒绝。

本文推翻 ADR-0002「第一版调代课只支持单节课变更」的边界。

## 为什么

- **单节课模型表达不了真实流程**：教师 A 想把周三第 3 节换到第 2 节，第 2 节是教师 B 的课。只改 A 会造成班级撞车，只改 B 会造成 B 的原节次空缺。真实操作就是一个同班置换环，参与教师 2–6 位。只支持单节变更会把这类协调推回线下。
- **确定性优于启发式**：班级规模下（一个班 5 天 × 8 节、窗口 7 天）图很小，BFS + 分层预算能在毫秒级枚举全部最短环。确定性意味着同一输入永远得到同一方案，可测试、可复现、可离线 CLI 复算；也让「方案为什么不可行」能逐边解释。
- **独立校验器是安全边界**：求解器可以出错，错误方案绝对不能生效。校验器不共用求解器的剪枝 helper，独立暴力复核四条核心不变量（教师同刻唯一、班级同刻唯一、教室同刻唯一、班级每天节数不变），并独立重算软分与求解器报告值比对。
- **同班限定**：跨班联合置换需要多个行政班一起重排，协调成本与解释成本陡增，收益低；目标节次为空时的「只挪不补」保留为教务低层换时间能力，不进入调课申请。
- **软约束复用现有权重**：24 类 `ConstraintType` 的硬/软标志与权重是草稿期与发布后的唯一语义来源，避免两套规则漂移（`ConstraintChecker` 是唯一实现）。

## Consequences

- `substitution_request` 增加 `type`（`SWAP`/`COVER`，存量回填 `COVER`）与 `target_period_id`；新增 `substitution_plan` 与 `substitution_plan_move`；`substitution` 增加 `type` 与 `plan_id`。
- 调课方案的每一行 `substitution` 表示「一节课被挪动」，`original_teacher_id = substitute_teacher_id`；代课沿用「换教师、不换节次」。
- 方案携带生成时的课表快照哈希与 30 分钟有效期；批准时哈希变化或校验失败返回 409 并整单零写入。
- 搜索窗口（默认 7，1–30）、教师数上限（默认 6，2–10）、排序预设是设置项，即时生效。
- 只读 CLI `plan` / `verify` 复用同一套纯求解器与校验器，不连数据库、不写业务数据；JSON 带 `schemaVersion`。
- 统计口径分离：被代课次数与代课次数只统计 `COVER`，`SWAP` 只计入「参与调课次数」。
- 迁移从 V22 开始（V20/V21 已被八期占用）；ADR 编号 0025（0023/0024 已被十期占用）。
