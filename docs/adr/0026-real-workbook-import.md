# 真实教务工作簿导入：模型用只读工具理解文件，写入仍由确定性代码完成

后续范围澄清（2026-10-25）：[ADR-0027](0027-explicit-draft-room-and-period-completion.md) 允许在草稿/预览中由用户显式确认补教室或缺课节；导入管道仍不隐式创建这些数据。该决定已确认，代码尚未实现。

导入管道从「模型一次看完整张表并吐 JSON」改为「模型先用只读工具浏览工作簿，确认结构后再分批取值」。上传时不再手选导入目标，一次确认可同时写入教师、课程、行政班与课表。

## 为什么

- 教务老师拿到的是查询型工作簿：五张表、560 行、无表头、`八（1）|星期一|1` 这种复合列，还有 14 个空课位。原来的管道假定「单表、≤500 行、前两行是表头、用户先选目标」，每一条都不成立，结果只能让人手工拆表。
- 同样的模型在用户自己的 agent 里能读懂这些表，差别不在模型能力，而在脚手架：agent 有工具、可以翻页、可以交叉核对；导入管道只有一次调用。
- 但写入不能交给模型：目标是带外键的关系库，一次判断错误就是脏数据，而且要求可复现、可审计、可重试。所以放开的是**阅读理解**，收紧的是**写入契约**。

## 决定

- 工具循环用纯 JSON 请求实现，不改四个供应商适配器（现有策略会显式拒绝 `tool_calls`）。模型每轮返回一个动作对象，后端执行后追加结果，最多 6 轮。
- 只读工具只有四个：列出工作表、按页读工作表、查询已有实体、宣告结构。模型不能写库，也不能触发任意外部调用。
- 6 轮未收敛时仍产出预览，并标记「结构未确认」；不整次作废。
- 多工作表全部参与识别；纯说明类表按保守规则确定性跳过，跳过原因可见。
- 槽位键为「行政班 + 星期 + 节次」；同一槽位完整行优先，残缺行丢弃并计数；空课位跳过并计入警告。
- 自动入库类别限定为教师、课程、行政班、课表；学期与作息仍由人工建立（作息提供一键生成默认作息的显式入口）。
- 同名实体只补空字段、不覆盖已有值，与钉钉同步的既有语义一致。
- 写库按类别分事务，成功类别保留，失败类别单独报告可重试；写库前必须在预览页确认。
- 不指定目标的 Excel/CSV 上传走整本工作簿；显式指定目标仍走旧的单目标解析（文本与图片必须指定目标）。这样旧流程与它的批次/停止/重试语义在兼容期内保留。

## Consequences

- 每次导入多出最多 6 轮工具调用；换来的是结构判断在批次之间一致，且判断结果对人可见。
- 会话记录需要保存工具轨迹（新增一个可空列），线上问题可回放。
- 行上限由 500 提到 5000，分批由 1 行提到 40 行；560 行的文件约 14 次模型调用。
- 没有 AI 时，模板导入仍然完整可用，符合「AI 特性可选」的既有约束。
- 原生 function calling、多供应商工具协议、模型直接写库仍然不做；如要做，另立决策。
