# 通知触达范围可配置，默认只发当事人

调代单生效后的通知接收人由系统设置项控制，教务可勾选：

- **当事人**（默认开启）：原教师 + 代课教师 + 班主任
- **年级组长**（默认关闭）
- **教务管理员**（默认关闭，教务自己在系统里已经能看到）

## 为什么

- 通知轰炸是学校对 IM 集成最常见的抱怨
- 不同学校管理风格差异大，让教务自己决定比替他们做决定更合适
- 技术实现上只是 NotificationChannel 接口多传一个"接收人列表"，由设置项计算

## Consequences

- 通知模板需要支持变量（课程名、时间、原/新教师、教室、原因），由后端渲染
- 所有通知发送记录落库（谁、何时、什么内容、是否成功），便于排查"为什么没收到"
- 钉钉工作通知失败时要有降级策略（重试 3 次 → 标记失败 → 教务界面可见）
- 年级组长没有独立模型；九期后续改为管理员维护的「调代通知收件人」名单（设置项 `substitution.notify.recipients`，按具体账号多选），`with-grade-leader` 作为旧值保留但只等同当事人。

## 2026-11-13 追加：通知收敛与交付边界

多用户钉钉特性部分推翻上面按「当事人 + 班主任 + 管理员/名单」扩散的通知范围：

- 只保留审批结果、最终接课教师的代课生效通知，以及工作台调课时每位被移动教师自己的调课明细。原任课教师抄送、班主任抄送、管理员与收件人名单抄送、课表发布和方案校验失败通知停发。
- 旧模板和历史设置值继续保留，用于历史数据与回退；公共通知入口不移除，但退休模板不再产生新的投递。
- 业务事务只生成最小不可变快照并登记提交后投递。审批/驳回只有在业务提交成功后才进入专用有界内存 executor；网络发送经 `NOT_SUPPORTED` 代理离开业务事务。队列拒绝或外发失败写独立安全失败记录，不改变已提交审批的 HTTP 结果。
- 投递时重新读取账号启用状态和教师映射。审批结果按真实操作账号投递；接课通知按最终 Teacher 投递。同一钉钉 UID 去重；只有停用账号时不发；可信 Teacher 尚无本地账号时仍可按教师 UID 发钉钉，但不会为通知自动建号。
- 保留三次总发送尝试、失败标记、渠道首成功降级和管理员可见发送记录。持久 outbox、进程崩溃重放、手机实际送达与已读不在本决定范围内。
