# 通知触达范围可配置，默认只发当事人

调代单生效后的通知接收人由系统设置项控制，教务可勾选：

- **当事人**（默认开启）：原教师 + 代课教师 + 班主任
- **年级组长**（默认关闭）
- **教务管理员**（默认关闭，教务自己在系统里已经能看到）

## 为什么

- 通知轰炸是学校对 IM 集成最常见的抱怨
- 不同学校管理风格差异大，让教务自己决定比替他们做决定更合适
- 技术实现上只是 NotificationChannel 接口多传一个"接收人列表"，由设置项计算

## Consequences

- 通知模板需要支持变量（课程名、时间、原/新教师、教室、原因），由后端渲染
- 所有通知发送记录落库（谁、何时、什么内容、是否成功），便于排查"为什么没收到"
- 钉钉工作通知失败时要有降级策略（重试 3 次 → 标记失败 → 教务界面可见）
- 年级组长没有独立模型；九期后续改为管理员维护的「调代通知收件人」名单（设置项 `substitution.notify.recipients`，按具体账号多选），`with-grade-leader` 作为旧值保留但只等同当事人。
