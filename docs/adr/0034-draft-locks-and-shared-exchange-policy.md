# 草稿锁定是持久保护，换位共用调课策略但保留周期语义

Status: accepted（2026-11-02，15项访谈已回答，用户确认并要求拆票发布；尚未实施）

草稿直接换位与发布后按日期调课共用基础约束和方案策略配置，但分别处理周期课表与具体授课实例。用户明确要求共享“最多变动几节课”和三种方案排序，避免两处重复设置；真实日期搜索窗口、审批和通知仅属于发布后流程。保留旧设置值与接口兼容，名称从“教师上限”更正为实际实现的课节数上限，去重教师人数仍独立统计。

锁定是具体授课的持久保护，固定时间与任课教师，所有草稿写入口和继续优化都必须执行，不能只做前端禁拖。以指定草稿继续优化是显式来源模式，生成另一份保留锁定的新草稿，不能静默采用默认热启动来源，也不能依赖新旧数据库行ID碰巧一致来继承锁。此项扩展ADR-0033，普通新建排课的默认来源策略保留。

选择共享规则/策略、分离生命周期，而不是将周期草稿伪装为某个日期的调代申请，避免引入审批、历史叠加及日期窗口对星期范围的错误限制。搜索与最终验证保持独立；允许不新增硬冲突地修复旧草稿，但发布仍采用整表绝对合规与完整性门槛，不能用调代的差分结果代替。已发布基线只读与ADR-0030一致。
