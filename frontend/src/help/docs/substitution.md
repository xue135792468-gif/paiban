# 调代课

课表发布后，临时变更分为两类，共用「调代」入口：

- **调课**：把一个课节从原时间换到同一行政班的另一个节次，并用**置换环**把原节次补满。通常涉及 2–6 位教师，班级当天的课节数量与课程集合不变。
- **代课**：原教师不能上课，由另一位教师接替该课节。只涉及一位教师的变动，不要求回填原节次。

菜单：**调代 → 调代课**（`/substitutions`），页面分「我的调代」「待审批」「调代记录」三个标签页。

## 提交申请

<a id="apply"></a>

在「我的调代」顶部选择类型，再填写表单：

**代课**

1. 选择「请假日期」，系统只列出当天有课的课节。
2. 选择「我的课节」。
3. 「期望代课」可指定一位教师，也可留空由教务决定。
4. 填写原因，提交。

**调课**

1. 选择「调课日期」与「我的课节」。
2. 在「换到」中选择同班的目标节次。系统只列同一天、同班已有课的节次——目标为空堂时属于「只挪不补」，不在调课范围内。
3. 填写原因，提交。调课必须经教务审批，不能直接生效。

提交后申请出现在「我的申请」：类型标签区分调课 / 代课；调课会显示「原节次 → 目标节次」，点【方案】可以查看教务生成的全部候选方案。

> 账号需要先在 **系统 → 用户管理** 中关联教师，否则无法提交。

## 审批

<a id="approve"></a>

具备审批权限的账号在「待审批」标签页处理：

**代课**：点【批准】，确认代课教师后生效；点【驳回】结束申请。

**调课**：

1. 点【生成方案】。系统在后台做确定性搜索，返回最多 3 个候选方案。
2. 方案卡显示：环长、影响天数、影响教师数、软约束扣分、当前排序预设与有效期。
3. 点【整单批准】。系统在同一个事务里写入方案的全部课节移动、更新申请状态并发送通知；任何一步失败都整单回滚，绝不会出现「张老师换了、赵老师没换」的半截状态。

方案有效期 30 分钟。批准时如果课表已经变化（例如别人先占用了目标节次），系统会返回冲突并提示重新生成，旧方案不会生效。

### 方案卡各字段

| 字段 | 含义 |
|---|---|
| 环长 | 被挪动的课节数，也就是参与置换的课节数量 |
| 影响天数 | 方案涉及的日期数量；同日方案为 1，跨天方案按实际日期去重 |
| 影响教师数 | 被挪动课节的教师去重后的数量；同一教师出现两次只算一位 |
| 软约束扣分 | 采用现有 24 类约束的权重，方案造成的软约束增量；越小越稳 |
| 排序预设 | 当前采用的排序规则，见下方「排序预设」 |
| 有效期 | 方案可用于批准的最后时间，默认生成后 30 分钟 |

### 搜索窗口与排序预设

在 **设置中心 → 调代与通知**（`/admin/settings`）中配置，保存后立即生效：

- **调课搜索窗口**：默认 7 天，范围 1–30。先找同一天；当天无解时，向后在该窗口内找跨天方案。
- **方案教师上限**：默认 6 人，范围 2–10。环长超过上限的方案不会生成。
- **方案排序**：
  - **最小影响**（默认）：影响天数 → 是否同周 → 影响教师数 → 软约束扣分。
  - **最少教师**：影响教师数 → 影响天数 → 是否同周 → 软约束扣分。
  - **最稳课表**：软约束扣分 → 影响天数 → 是否同周 → 影响教师数。

### 常见无解原因

- `TARGET_EMPTY`：目标节次在本班是空堂。「只挪不补」请直接找教务做低层换时间。
- `TEACHER_BUSY`：某位老师的课在目标节次已有别的班，链条走不通。
- `ROOM_BUSY` / `ROOM_TYPE` / `ROOM_CAPACITY`：教室被占用或不满足场地类型、容量。
- `TARGET_OUT_OF_WINDOW`：目标时间落在搜索窗口之外，可扩大窗口或换目标。
- `NO_SOLUTION`：窗口内没有满足硬约束的置换环。

## 记录与统计

<a id="records"></a>

「调代记录」支持按行政班、教师、类型（调课 / 代课）和日期范围筛选。

- 类型标签区分调课与代课；调课行可以展开，查看该方案的全部课节移动。
- 选择教师后会显示统计：**被代课次数**、**代课次数**、**参与调课次数**。
- 一笔 3 人调课只会增加三位老师的「参与调课次数」，不会虚算成代课。
- 「被代课次数 / 代课次数」只统计代课；期末课时量按净变化计算。

## 课表标记

<a id="notify"></a>

审批生效后，课表「最新」视角会把相关课节标成：

- **调**：调课方案挪动了这一节，悬停可看原教师、原因与生效日期。
- **代**：这一节由另一位教师代课。

「原始」视角始终显示学期初发布的基线，不受调代影响。

## 通知

调代生效、驳回都会产生站内通知：

- 调课：每位被卷入教师收到**只关于自己那一节**的通知；班主任收到整单摘要；通知范围含教务时再发给教务。
- 代课：原教师、代课教师、班主任收到通知，范围同上。

通知范围在设置中心配置。启用钉钉 / 飞书时会同步推送，平台不可用时自动降级为站内通知。

## 只读命令行核查

<a id="cli"></a>

运维和教务可以用离线 CLI 做 what-if 与事后核查。它不连数据库、不写业务数据，和后端共用同一套纯 Java 求解器与校验器。

```bash
# 生成候选方案（0 有解 / 2 无解 / 1 错误）
scripts/substitution-cli.sh plan \
  --snapshot snapshot.json --request request.json \
  --window 7 --max-teachers 6 --preset min-impact --format json

# 对比改动前/后的课表（0 通过 / 1 违规）
scripts/substitution-cli.sh verify --before before.json --after after.json --format table

# 用快照 + 方案校验
scripts/substitution-cli.sh verify --snapshot snapshot.json --plan plan.json --kind SWAP
```

- JSON 输入输出都带 `schemaVersion: 1`；版本不兼容时返回可读错误、退出码 1。
- `plan` 输出 `candidates`（最多 3 个）与 `diagnoses`；`verify` 输出 `issues`（约束码 + 说明）。
- 快照包含节次、班级、课程、教师、教室、基线课节、已生效调代与约束配置。
