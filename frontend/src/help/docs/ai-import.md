# AI 数据导入

<a id="targets"></a>

菜单：**教务 → AI 数据导入**（`/admin/ai-import`）

AI 数据导入把「一份原始资料」变成系统里的数据。系统负责把文件读成原始表格网格，AI 负责判断这是什么表、每一列对应哪个字段；解析结果先预览，用户确认后才写入。

## 能处理什么

当前提供两个导入目标，页面上的目标卡片写明了每个目标的能力与限制：

| 目标 | 能处理 | 输出 |
|---|---|---|
| 教师 | 教师名单、通讯录、任课表；姓名、工号、电话、学科可以乱序，允许标题行和多余列 | 教师档案：姓名、工号、电话、邮箱、学科 |
| 课表 | 年级课表、班级课表；一行一节课，班级、星期、节次、课程、教师、教室可以分布在任意列 | 一份课表草稿，可在草稿编辑器里调整后发布 |

行政班、课程、教室、授课任务使用同一套流程，但目前标注「即将支持」，请先在对应页面录入。

<a id="limits"></a>

## 不能处理什么

- **图片导入需要视觉模型，且目前只支持教师目标**。当前模型不支持视觉时，图片入口会禁用并提示换用视觉模型；Excel/CSV 和粘贴文本不受影响。
- **含多个有数据工作表的 Excel**。系统不会替你猜用哪一张，请拆分文件或只保留一个工作表；只有一张表有数据时，空白的表会被跳过。
- **系统里没有对应实体的数据**。例如学生成绩、考勤，没有可写入的目标，AI 不会凭空创建。
- **不会静默创建缺失的年级、班级、课程、教师或教室**。名称对不上时进入映射步骤，由你选择系统记录；年级和班级可以在你确认后一起创建，解析阶段不会写库。
- **不会直接修改已发布课表**。课表导入只生成 `DRAFT` 草稿，发布仍走原有的草稿校验与发布流程。

<a id="flow"></a>

## 导入流程

1. **选择目标**：在目标卡片里选「教师」或「课表」。从排课页点【导入课表】会直接预选课表目标。
2. **上传资料**：支持 `.xlsx` / `.xls` / `.csv`，也可以粘贴文本。文件里的标题行、合并单元格、多行单元格都按原样交给 AI 判断。
3. **AI 解析**：提交后由 AI 解析，超时会提示「AI 解析超时，请重试或拆分文件」。**数据行超过 3 行的课表会拆成「一批一个班」放到服务器后台逐批解析**：上传后页面立刻显示「已完成 N/M 批」和正在解析的班级，全部完成后自动进入预览。见[后台解析与三种中间状态](#background)。
4. **预览**：教师目标用表格预览，低置信度单元格标黄；课表目标用只读网格预览，可以按班级或教师切换查看。顶部显示「共 N 节，M 节待映射」，网格始终显示全部行。
5. **映射与修正**：未匹配的班级、课程、教师、教室逐项列出；也可以直接修改单元格后点【打回重析】让 AI 基于修正继续补全。
6. **入库**：教师写入教师档案；课表生成草稿并自动跳转到草稿编辑器。课表导入使用当前学期；没有当前学期时预览会提示先设置，【确认入库】保持禁用。

<a id="background"></a>

## 后台解析与三种中间状态

一份年级课表动辄几百节课，一次问答装不下，浏览器也不该干等。系统因此把数据行超过 3 行的课表切成**一批一个班**，交给后台线程逐批解析：每批解析完立刻落盘，页面每 2 秒取一次进度。数据行 3 行以内的小表还是一次解析完，不产生批次。

三种中间状态决定了这时该做什么：

| 状态 | 页面显示 | 这时该做什么 |
|---|---|---|
| `PARSING` 解析中 | 「正在后台解析」卡片：进度条 + 「已完成 3/14 批」+ 正在解析的班级 | 等它跑完即可，最后一批完成会自动进入预览。可以离开页面，回来用「上次导入」接着看进度；也可以【停止解析】或【放弃导入】 |
| `PARTIAL` 部分结果 | 「部分结果：已解析 3/4 批」+ 已解析的课 + 失败批次列表（班级 + 失败原因） | 先【重试失败批次】；重试还是不行就【放弃导入】。这时的【确认入库】是禁用的，按钮上写着「先重试或放弃」 |
| `ABANDONED` 已放弃 | 会话关闭，页面回到上传入口，不再显示预览 | 不用做什么。记录留在 AI 操作历史里，但没有写入任何数据 |

<a id="controls"></a>

## 停止解析 / 重试失败批次 / 放弃导入

三个按钮解决的是三种不同的问题，别混着用：

**停止解析**（只在「解析中」出现）
点下去，服务器不再发新的批次请求：已完成的批次原样保留，正在解析的那一批和排队中的批次直接丢掉，会话立刻变成普通预览，可以照常映射、修正、入库；「AI 说明」会写明还剩几批没解析（例如「已停止解析，剩余 11 批未解析」）。
如果停下时一批都还没解析完，就没有可预览的结果，会话会标成「解析失败」并说明「已停止解析，没有任何已完成的批次」，这时只能重新上传文件。
适合「先看看已经出来的数据对不对」或者「文件太大，不想等剩下几十个班」。
注意它是**停止**不是暂停：停下之后想补齐剩下的班，得重新上传文件。如果停下前已经有批次失败，会话会停在「部分结果」，可以用【重试失败批次】。

**重试失败批次**（只在「部分结果」出现）
只重跑失败的那几个班，已解析成功的班不会再调用 AI、也不会重复入库。重试期间页面回到「解析中」并显示进度，跑完自动回到预览。
重试仍然失败会继续停在「部分结果」，可以再点一次；如果模型就是读不懂这份文件，继续重试没有意义，转【放弃导入】。

**放弃导入**（「解析中」和「部分结果」都有）
作废这次导入：不生成草稿、不写入任何班级/课程/教师数据，会话标记为已放弃。放弃后地址里的 `?session=` 和「上次导入」都不再提供这个会话，只能用新文件重新开始。
适合「上传错了文件」「表头混乱到重试也没救」这类情况——先放弃，比带着一堆错行去入库安全。

<a id="restore"></a>

## 切页或刷新后继续

解析成功后，页面地址会带上 `?session=…`。之后切到别的页面再回来，或者直接按 F5，预览都会按地址里的会话自动恢复：班级网格、映射进度和待处理项都还在，可以接着处理。

没有预览时，页面上会显示「上次导入」卡片（文件名 · 时间 · 状态），点【继续】即可回到上次的预览。恢复后的状态决定能做什么：`PARSING` 会接着显示进度并继续自动刷新，`PREVIEW` / `EDITED` 可以继续编辑和入库，`PARTIAL` 可以重试失败批次或放弃，`COMMITTED` 只能查看，`FAILED` 会显示失败原因。`ABANDONED`（已放弃）的会话不可恢复，卡片也不再展示它。

重新上传文件开始解析，或者点【重新导入】清除当前预览后，地址里的 `session` 会被移除，之后刷新就不会再回到这次导入。

<a id="timetable"></a>

## 课表导入生成草稿

课表预览会把每一行画进网格：

- **蓝框**：该行有未匹配的名称，先到下方映射步骤处理。
- **红框**：同一班级同一节次有多条记录。冲突不阻止生成草稿，但发布时会被草稿校验拦截。

预览顶部的统计告诉你这次导入会写多少节课、涉及多少个「班级 × 课程」组合，以及会**创建**多少条、**更新**多少条授课任务。确认无误后点【确认入库】，系统在一个事务里创建草稿和课节；任何一行校验失败，整批都不会落库。

<a id="mapping"></a>

## 名称对不上怎么办

映射步骤默认不自动创建，也不静默跳过。每个未匹配值有两种处理方式：

1. **选择系统中已有的记录**：下拉框会列出候选，选中后该值映射到对应实体，相关行一起更新。
2. **确认创建**：勾选「系统中没有，创建」，填写名称后点【确认创建】。创建班级需要年级：能从班级名称推断出来时按推断结果创建，推断不出时才需要手动选择。

星期、节次这类无法直接创建的值，会给出合法选项供你改行；全部未解决项清零后，【确认入库】才可用。

<a id="grade-inference"></a>

## 年级推断与按年级创建

班级名称里通常带着年级，系统会读取名称前缀推断年级：

| 文件里的班级名称 | 推断的年级 |
|---|---|
| 八（1） | 八年级 |
| 高一1班 | 高一 |
| 7年级(2) | 7年级 |
| 初一3班 | 初一 |

映射步骤的「年级」列会给出推断结果和状态：

- **已有**：当前学期已有这个年级，创建班级时直接归入。
- **新建**：当前学期还没有这个年级，它会在你确认创建班级时一起创建。

点【批量创建所选】时，每个班级各自带上推断出的年级，跨年级的批次不会被塞进同一个年级。班级名称保留文件里的原值（如「八（1）」），年级只决定归属。新建班级的人数默认 45，可以在批量栏或单个创建处修改。

<a id="assignments"></a>

## 部分导入会更新授课任务

课表入库按「班级 + 课程」查找或创建授课任务：

- 系统中已有该组合的任务时，导入会**更新**它的教师和周课时（周课时取本次导入的课节数），预览的统计里计为「将更新」。
- 没有该组合时**创建**新任务，计为「将创建」。
- 同一组合出现多位教师时，任务使用第一行的教师，每节课仍保留各自的教师，并在入库后给出提示（见 ADR-0022）。

因此，课表导入不只是生成一份草稿，也会影响后续自动排课使用的授课任务数量。导入前请确认预览里的创建/更新条数符合预期。
