# 排课

排课分为四步：配置约束 → 确认授课任务 → 提交自动排课 → 在草稿上微调并发布。本页按这个顺序说明。

## 约束配置

<a id="constraints"></a>

菜单：**教务 → 约束配置**（`/admin/constraints`）

每条约束都有「启用」开关，启用后可以选择约束强度：

- **硬约束**：必须满足。求解结果里硬冲突必须为 0 才能发布。
- **软约束**：尽量满足。不满足不会阻止发布，只影响得分。

软约束可以调「权重」（0–100）：数值越高，求解器越优先满足这条规则。例如把「教师连堂偏好」调到 80，系统会尽量避免同一教师连续上多节课。

约束按类别折叠展示，顶部显示「已启用 N 条 / 共 M 条」。部分约束带有参数（如指定星期、节次、教室类型），在约束卡片下方填写。

配置完成后点击【保存配置】。高中模式还可以【存为模板】并在其他学期【应用模板】，初中模式会隐藏模板与权重。

## 每周固定不上课

在约束设置中选择【每周不上课时段】，指定行政班、星期和节次，启用并保存。可以暂停或删除要求；启用时这些位置必须留空，不能改为“尽量”。例如晚上是第8、第9节时，可直接选择第8或第9节，不会另起一套课表或重复计算课时。

自动排课会把原有周课时安排到其他位置。草稿的空格标注“不上课”，不能拖入课程；若导入的课程已经占用该位置，会保留课程并提示冲突，需要移走后才能发布。“不上课”不等于有课没排上的“未排课”，也不会被减少空堂规则扣分。

这项要求按每周重复，不表示某个具体日期临时停课，也不会自动删除或改写已发布课程。当前通过表单设置，AI生成此类要求尚未开放。

## 授课任务

<a id="assignments"></a>

菜单：**教务 → 授课任务**（`/admin/assignments`）

授课任务的定义是：**行政班 + 课程 + 每周节数 + 任课教师**。

1. 点击【新增授课任务】。
2. 选择行政班与课程。
3. 填写「每周节数」——这是该班每周要上几节这门课，直接决定排课总量。
4. 选择任课教师。

同一行政班所有课程的每周节数之和，不应超过作息表提供的总课节数，否则排课一定失败。录入完成后可在此页核对总数。

## 提交排课

<a id="run"></a>

菜单：**教务 → 自动排课**（`/admin/scheduling`）

1. 在顶部选择学期。
2. 在「发起排课任务」中填写「草稿名称」（例如：方案 A）与「最大求解时长(秒)」。
3. 点击【开始排课】。

求解器同一时刻只运行一个任务，如果已有任务在跑，需要等待或先【取消任务】。运行中会显示进度、当前得分与硬冲突数。任务完成后点击【打开草稿】进入草稿编辑器。

若页面顶部提示「排课前请先录入授课任务、配置作息表和教室」，说明输入还不完整，先补齐对应数据。

## 草稿微调

<a id="draft"></a>

页面：课表草稿（`/admin/drafts/:id`）

- 拖拽课节到其他时段即可调整。拖动时绿色表示可放置，红色表示有冲突；点击红格可以查看冲突原因。
- 顶部统计显示「硬冲突」数量，硬冲突不为 0 时无法发布。
- 高中模式可以【比较草稿】，按得分对比多套方案。
- 可以【重命名】草稿，不需要的方案直接【删除】。

## 发布

<a id="publish"></a>

确认草稿无误后点击【发布课表】。发布后：

- 该草稿成为本学期的正式课表基线。
- 基线只读，后续的单节课变更必须走调代流程，而不是继续改草稿。
- 课表查看页选择「原始」视角看到的就是这份基线。

发布失败时页面会提示原因（通常是仍有硬冲突）。解决冲突后再次发布即可。
